# Сценарии использования

## User Journey (принципы)

- **Time to value:** пришёл → рассказал тему → получил результат (черновик, структура)
- Минимум времени на изучение продукта
- Аудитория — эксперты, не нужен handholding
- Детальный journey — после MVP и реальных пользователей

## Сценарии

### UC-1: Структурирование доклада

**Контекст:** спикер имеет тему и набор мыслей/заметок, но нет структуры. Нужно превратить сырой контекст в логичный аутлайн или черновик.

**Действия:**
1. Описывает тему, целевую аудиторию, ключевые тезисы
2. Агент подгружает skill "structure", анализирует контекст
3. Предлагает структуру материала
4. Итеративная доработка через диалог

**Результат:** готовый аутлайн или черновик материала в Markdown.

---

### UC-2: Research по теме

**Контекст:** тема доклада за пределами обучающей выборки LLM — актуальные инструменты, свежие практики, нишевые технологии. Нужны достоверные и актуальные источники.

**Действия:**
1. Формулирует запрос на исследование (что искать, какой уровень глубины)
2. Агент подгружает skill "research", ищет информацию
3. Верифицирует источники, фильтрует нерелевантное
4. Возвращает структурированный результат со ссылками

**Результат:** подборка материалов с прозрачными ссылками на источники. Агент явно отделяет факты от интерпретаций.

---

### UC-3: Работа в контексте проекта (Knowledge Sphere)

**Контекст:** спикер возвращается к проекту (лекция, курс, серия докладов) через дни или недели. Не хочет заново объяснять, что уже обсуждалось, какие решения приняты, какие материалы собраны.

**Действия:**
1. Открывает существующий проект
2. Агент загружает Knowledge Sphere — связанную картину проекта
3. Продолжает работу с учётом всего накопленного контекста
4. Новые факты и решения автоматически интегрируются в шар знаний

**Результат:** бесшовное продолжение работы без повторного объяснения контекста.

---

### UC-4: Генерация слайдов (v1.5)

**Контекст:** 75% докладов = презентация. В текущих LLM-инструментах слайды приходится собирать вручную — самая большая боль в workflow спикера.

**Действия:**
1. На основе готовой структуры или черновика (из UC-1) запрашивает генерацию слайдов
2. Агент формирует презентацию с учётом контекста проекта
3. Итеративная доработка отдельных слайдов

**Результат:** готовая презентация, сгенерированная из материалов проекта.
