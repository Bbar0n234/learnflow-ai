# Выбор моделей: методика и карта ролей

Как проект выбирает LLM, пока нет собственного eval-контура (Langfuse datasets + LLM-as-judge — в backlog). До его появления опираемся на внешние бенчмарки и операционные сигналы; финальная валидация — догфудинг через runtime model switching. Документ ведёт архитектор; агент готовит срезы данных по этой методике.

## Классы моделей и роли

Модели проекта делятся на три класса с разными требованиями:

| Класс | Роли | Что важно | Что вторично |
|-------|------|-----------|--------------|
| Основной | main-агент + whitelist для переключения пользователем | Качество текста (учебный контент, русский), tool calling, reasoning | Скорость — важна, но уступает качеству |
| Лёгкий | summarization, субагенты, генерация title | Цена (ступень ниже основного), скорость, instruction following | Креативность, глубина рассуждений |
| Guard | LLM-классификатор безопасности | Скорость, structured output, устойчивость вердиктов, цена | Генеративное качество |

Image-модель — отдельный контур (секция `image` в `agent.yaml`), методикой не покрывается: там свои критерии и свой discovery (`GET /api/v1/images/models`).

## Ценовые рамки

Цены — $/M токенов, источник правды — OpenRouter API (`/api/v1/models`), не маркетинговые страницы вендоров.

| Класс | Ориентир | Мягкая граница | Хард-блок |
|-------|----------|----------------|-----------|
| Основной (дефолт) | ~уровень текущего дефолта | ~$1.5 in / $5–6 out (≈2× дефолта) | — |
| Whitelist (не-дефолт) | — | — | **$10 in / $25 out** |
| Лёгкий | ступень ниже дефолта | ~$0.3 in / $1.5 out | $1 in / $3 out |
| Guard | как лёгкий | как лёгкий | как лёгкий |

Мягкую границу допустимо превышать при кратном (не процентном) превосходстве в качестве. Хард-блок whitelist не превышается никогда: сверхдорогие фронтир-модели не попадают в выбор пользователя независимо от качества.

## Критерии отбора

### Качество (внешние бенчмарки)

- **Artificial Analysis Intelligence Index против цены** — главный фильтр cost-optimal: ищем ~70%+ фронтир-качества при кратно меньшей цене. Смотрим сам индекс и положение модели на frontier-кривой intelligence-vs-price.
- **LMArena Elo** (text со style control, creative writing, multilingual) — человеческое предпочтение; наш домен — генерация учебного текста, поэтому creative/writing-срезы весят наравне с overall. Русский срез — обязателен к проверке, если доступен (LMArena multilingual, русскоязычные арены).
- **Tool calling** (BFCL, tau-bench-класс) — для main и субагентных ролей: агент активно зовёт tools; модель со слабым function calling непригодна как main независимо от Elo.
- **OpenRouter rankings (реальный usage)** — прокси «модель живёт в проде у людей»: устойчиво высокий token share означает, что модель прошла чужой прод-отбор.

### Операционные

- **Скорость**: output tokens/s и TTFT (Artificial Analysis, страницы провайдеров OpenRouter). Обязательный параметр, не tie-breaker: медленная модель портит UX чата независимо от качества.
- **Контекст** ≥ 100k (наш `context.max_tokens`).
- **Reasoning**: модель должна поддерживать reasoning-режим; суммаризованные рассуждения проприетарных провайдеров приемлемы. На каждую роль в карте альтернатив держим opensource-вариант с полными рассуждениями.
- **Провайдеры на OpenRouter** (для open-weights): число хостящих провайдеров и разброс throughput/uptime между ними. Единственный слабый провайдер — риск деградации класса «пустые ответы с ретраями» (наблюдалось на guard-модели).
- **Гео-доступность**: каталожные метаданные OpenRouter не гарантируют доступность модели с прод-инфраструктуры — провайдер может блокировать регион (наблюдалось на модели с единственным провайдером, US-only ограничение). Проверка реальной доступности с прод-инфраструктуры обязательна перед включением модели в состав, каталога недостаточно.

### Портфельный принцип whitelist

Whitelist — не топ-N одного рейтинга, а репрезентативный портфель: сильная универсальная (дефолт), креативно-пишущая, инженерно-reasoning, ультрадешёвая cost-efficient для массовых прогонов, опционально — фронтир-класс дороже дефолта (в пределах хард-блока). Пользователь выбирает характер модели, а не оттенки одного и того же.

### Что сознательно не смотрим

- Кодинг-бенчмарки (SWE-bench и родня) — не наш домен.
- Vendor self-reported результаты без независимого подтверждения.
- Синтетические long-context заявления (needle-in-a-haystack маркетинг).
- Single-user / non-scalable планы доступа (проверено: Fireworks Firepass — single-user, не подходит).

## Процесс пересмотра

Триггеры: деградация провайдера текущей модели, выход нового поколения используемого семейства, накопленные сигналы догфудинга о качестве, плановый пересмотр при подготовке фазы.

Шаги: свежий срез из OpenRouter API (цены/контекст/провайдеры) → срез качества по источникам выше → сводная таблица кандидатов по классам с рекомендациями (артефакт итерации, датированный) → отбор архитектором → правки `agent.yaml` / `security.yaml` / `pricing.yaml` (seed идемпотентен, включая утверждённые альтернативы) → смоук: переключение, reasoning, cost-матчинг в Langfuse.

Цены в `pricing.yaml` дрейфуют относительно OpenRouter — при каждом пересмотре сверяются все записи, не только новые.

## Карта ролей и альтернатив

Для каждой роли — активная модель + одобренные альтернативы, чтобы замена при деградации провайдера была правкой одной строки конфига (`agent.yaml`/`security.yaml` + запись в `pricing.yaml`) без нового ресёрча. Источник правды по конкретным slug и ценам — сами конфиги; здесь фиксируется обоснование и одобренный путь отката.

### Основной класс (main-дефолт + whitelist)

| Модель | Роль в портфеле | Характер | Opensource, полные рассуждения |
|---|---|---|---|
| `z-ai/glm-5.2` | Main-дефолт + whitelist | Универсальная: лучший баланс качество/скорость/цена в классе, топ tool calling, максимальная провайдерная избыточность | Да (open-weights) |
| `google/gemini-3.6-flash` | Whitelist | Премиум human-preference: топ русского среза и creative writing, дороже дефолта — «качественный» выбор портфеля | Нет (проприетарная, рассуждения суммаризуются) |
| `deepseek/deepseek-v4-pro` | Whitelist | Ультрадешёвая для массовых прогонов | Да (open-weights) |
| `x-ai/grok-4.5` | Whitelist | Фронтир-класс в пределах хард-блока; заменил `meta/muse-spark-1.1` после гео-блока (US-only, единственный провайдер) | Нет (рассуждения суммаризуются) |
| `qwen/qwen3.7-max` | Whitelist | Инженерный instruction-following профиль; единственный провайдер (Alibaba) — риск single point of failure | Нет данных по детализации рассуждений |

Портфель уже покрывает диапазон характеров и opensource-опцию с полными рассуждениями (`z-ai/glm-5.2`, `deepseek/deepseek-v4-pro`) внутри своего состава — отдельного списка альтернатив вне whitelist для основного класса архитектор не утверждал. Замена элемента портфеля — самостоятельный ресёрч-цикл (см. «Процесс пересмотра»), не point-swap лёгкого класса или guard.

### Лёгкий класс (summarization + субагенты)

Активная модель: `deepseek/deepseek-v4-flash` — open-weights, полные рассуждения подтверждены боевым смоуком; сама выступает opensource-фолбэком класса.

Одобренные альтернативы для свапа при деградации: `minimax/minimax-m2.5`, `tencent/hy3`, `z-ai/glm-4.7-flash` (предыдущий дефолт лёгкого класса; сохранён как резерв несмотря на однажды наблюдавшуюся деградацию у провайдера — риск известен и не исключает временного фолбэка).

### Guard

Активная модель: `google/gemini-3.5-flash-lite` (`effort: minimal`) — без изменений; подтверждена боевым смоуком: отдаёт рассуждения, латентность вердикта < 600 мс.

Одобренные альтернативы: `stepfun/step-3.5-flash` (быстрее и дешевле, без prompt caching), `deepseek/deepseek-v4-flash` (умнее; open-weights с полными рассуждениями — opensource-фолбэк роли).
