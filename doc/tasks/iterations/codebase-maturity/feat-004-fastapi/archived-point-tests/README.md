# Архив точечных автотестов feat-004

Эти автотесты написаны по ходу slice feat-004 (Backend/FastAPI) и **перенесены
сюда из `backend/tests/`** по решению архитектора: живую тестовую инфраструктуру
проектирует с нуля отдельная итерация фазы (feat-009 Testing), поэтому до неё
тесты не держатся в реальной инфраструктуре, а сохраняются как артефакт-бэкап.

Они уже отработали своё — в частности, поймали латентный circular import
`app.services ↔ app.agent` (фикс остался в коде: TYPE_CHECKING-импорт в
`backend/app/services/agent_runner.py`).

## Состав

Файлы переименованы без префикса `test_` (`*_tests.py`), чтобы pytest не подбирал
их из `doc/` в коллекцию — это архив, не запускаемый набор.

- `security_primitives_tests.py` — argon2 hash/verify roundtrip, refresh-токены, `hash_raw_token`.
- `rate_limit_tests.py` — `RateLimiter`: лимит/окно/`retry_after`, независимость ключей и экземпляров (state ушёл из module-level в `app.state`).
- `config_tests.py` — CSV-парсинг `CORS_ORIGINS`, в т.ч. env-путь (регрессия на `NoDecode`: без него `Settings()` падает на старте на CSV-строке).
- `security_types_tests.py` — StrEnum-регрессия: `.value` всех security-энумов неизменны, сериализация `GuardResult` по value.

## Для feat-009

Это не готовая рамка, а сырьё. При проектировании тестовой инфраструктуры
решить, что влить и в какой структуре (фикстуры, нейминг, расположение). Покрытые
здесь критичные пути (auth-примитивы, rate limiter, config-парсинг, StrEnum) —
кандидаты в обязательное покрытие. Импорты завязаны на `app.*` — при переносе в
реальную инфраструктуру вернуть префикс `test_` и актуализировать.
