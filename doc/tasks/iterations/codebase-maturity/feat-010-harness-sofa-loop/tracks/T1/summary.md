# Summary — feat-010, трек T1 (единственный)

Итерация мета: правились промпты ролей, скиллы и процессные документы — кода продукта нет. Партиция вырожденная (один трек), документы итерации ведутся в новой per-track раскладке, которую сама итерация и вводит.

Исполнение — по модели из design-brief: на каждый слой пара субагентов (implementer + reviewer, оба Opus), порядок 0 → 1 → 2 → 3, последовательно (слои пересекаются по файлам — `SKILL.md`, `workflow.md`, `sofa-contributor` — параллелить их значило бы нарушить собственный принцип партиции по непересечению). Каждый слой: реализация → «сухой прогон» ревьюером (полнота по брифу + замыкание writer↔reader) → закрытие находок → коммит.

## Решения и обоснования

- **Слои исполнены последовательно, а не «Слой 2 параллельно»** (бриф допускал параллель): Слой 2 делит файлы (`prompts/sofa-contributor.md`, скилл `sofa-contributor`, `workflow.md`) со Слоями 1 и 3 — партиция по файлам не проходит, значит fan-out неприменим. Решение консистентно с самим дизайном.
- **Cross-cutting кейсы живут в `test-cases.md` трека-источника** (без префикса трека, помечены Layer 2/3); на INTEGRATION_TEST tester собирает их по всем `tracks/*/test-cases.md` и флипает статусы in-place. Отдельного итерационного тестового файла не заводили — иерархия брифа фиксирует ровно три per-track документа. Закрывает разрыв «`{track_id}=final` резолвится в несуществующий путь», найденный ревьюером Слоя 0.
- **`sofa-proposals.md` пишется в корень итерации** (родитель `tracks/`), не в директорию трека — финализация идёт после барьера, файл single. Промпт роли мигрирован с singular-переменных на glob `tracks/*/...` (находка ревью Слоя 0).
- **Docs-updater пишет свои решения в `## Решения и обоснования` наиболее релевантного трека** — итерационного summary в новой модели нет; downstream-читатели уже читают summary всех треков через glob.
- **Переменные путей сохранили имена** (`{plan_path}`, `{summary_path}`, `{test_cases_path}`), но резолвятся под `tracks/<track_id>/`; `{test_cases_path}` при `final` не резолвится (tester читает glob). Минимум churn в промптах.
- **Question-классификатор живёт только в скилле `sofa-contributor`** (+ тонкая ссылка из промпта роли); в `conventions.md` — указатель без дубля механики. Довод implementer'а «SKILL — единственный дом SOFA-ноу-хау» поддержан ревьюером; буква интеграционной таблицы брифа (классификатор в conventions) исполнена указателем.
- **Выход blueprint-свипа закреплён детерминированно**: `doc/content/sofa/sweep-proposals-<YYYY-MM-DD>.md`. Запись в папку итерации-донора запрещена — там лежит её собственный `sofa-proposals.md` (клоббер), а архитектор должен искать кандидатов свипа в одном предсказуемом месте.
- **«Один сабагент за раз» переписан как вырожденный случай fan-out**, read-only исключение ревьюеров A/B — частный случай («read-only fan-out»). Один барьер на границе fan-out; после него — single-последовательность (INTEGRATION_TEST → CODE_REVIEW → DOC_UPDATE → SOFA → HARVEST → gate).
- **Per-track коммиты при fan-out — только scoped staging** (`git add <файлы скоупа>`, не `-a`): в общей ветке naive-коммит трека снял бы снапшот незавершённых соседей. Строка добавлена по рекомендации ревьюера Слоя 3.
- **Финальное независимое ревью всей итерации** (сквозной прогон по слоям) нашло и закрыло швы между слоями: семантика `{phase_id}`/`{track_id}` у implementer'а (фаза плана трека `T1.1`, а не трек как целое), разрешение оркестратору писать секцию `## Партиция треков` в design-brief, синхронизация шаблона `test-cases-template.md` и скилла `aidd-methodology` с новой per-track раскладкой.
- **Backlog:** пункты 107 (fan-out), 108 (context persistence), 109 (SOFA consumer) удалены — перенесены целиком, провенанс в tasklist «Из backlog». Пункт 61 разделён по правилу атомарности: механизм (blueprint-формат + реверс Question) уехал в итерацию, контентная работа (список blueprint-кандидатов к публикации) осталась самостоятельным P3-пунктом.

Финальный пакет решений архитектора (внесён после сквозного ревью):

- **Anytime-harvest при fan-out — per-track носитель.** Сабагент по ходу итерации фиксирует anytime-кандидата в `## Follow-ups` **своего** трека; напрямую в `harvest-proposals.md` (файл яруса итерации) по ходу пишет **только оркестратор** — иначе при fan-out два параллельных трека клоббят один файл яруса. Harvester сводит `## Follow-ups` всех треков и anytime-записи оркестратора.
- **Перекройка партиции — только при остановленных треках.** Оркестратор правит `## Партиция треков` design-brief лишь когда затронутые треки остановлены/не запущены: design-brief — файл яруса итерации, его нельзя менять под живыми читателями.
- **Ревью партиции — one-shot.** Один прогон general-purpose ревьюера без повторного круга и деградации — решение архитектора: этого достаточно (correctness-critical, но дёшево и однократно).
- **Дубли cross-cutting кейсов между треками приемлемы** — не чиним (дедуп не вводим); цена дубля ниже цены механизма синхронизации между независимыми треками.
- **`{attempt}` для fixer.** Fixer — свежий агент, сам не знает, что он «второй»; оркестратор передаёт `{attempt}` при каждом вызове, TIL-зонд обязателен при `{attempt} = 2` (перед повторной правкой, не перед эскалацией).
- **Question → обратная ссылка в backlog.** При публикации Question backlog-пункт-источник дополняется relational-ссылкой на пост («опубликовано как Question: <url>») — это провенанс, не перенос: пункт остаётся в backlog. Мониторинг ответов — вручную через режим `stats-polling`.
- **Закрыты три pre-existing разрыва:** (1) `{fix_list}` у implementer'а больше не приходит от tester'а — прод-баги, вскрытые тестами, чинит fixer (A6), implementer'у остаются фиксы по code review; (2) в входы `docs-updater` добавлен `review-b.md` (секция «Незамеченный дрейф документации» адресована именно ему); (3) убраны фантомные артефакты `decisions.md` и «отчёты stand-validation» из входов SOFA/HARVEST и промптов ролей (конвейер их не производит) — ADR оставлены как реальные.
