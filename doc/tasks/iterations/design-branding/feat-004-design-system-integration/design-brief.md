# Design Brief: feat-004 — Design-system integration

| Поле | Значение |
|------|----------|
| Итерация | feat-004 (трек design-branding) |
| Статус | 🚧 In Progress |

## 1. Зачем эта итерация

Продукт сейчас выглядит generic: дефолтная нейтральная палитра shadcn (серая шкала `oklch(L 0 0)`, без бренда), шрифт Geist, тёмная тема описана в CSS, но недостижима (нет переключателя), логотип — просто текст «LearnFlowAI», иллюстраций нет вообще. Цель Фазы 4 — «не стыдно показать»: продукт получает фирменный визуальный язык и перестаёт быть безликим.

В feat-001 (PoC) визуальная идентичность **уже спроектирована до уровня high-fidelity хэндоффа** — это не проектирование с нуля, а **перенос готовой дизайн-системы «Чернила / Электрик» в код**. Поэтому ключевая ценность брифа — зафиксировать границы (что переносим, что делаем на заглушках, чего не делаем) и процесс, а сама спецификация вида живёт в хэндоффе и не дублируется здесь.

## 2. Видение бренда (кратко)

Система **«Чернила / Электрик»**: тёплая бумажная основа (кремовый фон) + один плоский фиолетовый акцент (`#7434F4`), serif-акценты в заголовках, **сфера знаний как визуальное ядро бренда**. Характер: спокойный · умный · тёплый · собранный. Анти-цели: детскость, корпоративный холод, generic-AI-эстетика. **Жёсткое правило:** фиолетовые градиенты в UI запрещены — фиолетовый всегда плоский, градиент живёт только внутри сферы-орба.

## 3. Источник спецификации

Пиксельный first-source — пакет хэндоффа feat-001:

```
doc/tasks/iterations/design-branding/feat-001-poc/design-handoff/design_handoff_brand_electric/
├── README.md                  ← токены, типографика, wordmark K5, 11 экранов, интеракции, state
├── *.dc.html (5 файлов)       ← HTML-прототипы целевого вида (референс, НЕ переносить код)
└── support.js                 ← рантайм для просмотра dc.html (в кодовую базу не переносить)
```

Хэндофф high-fidelity: цвета, типографика, отступы, радиусы и копирайт финальные, воспроизводить пиксельно, но **средствами существующей дизайн-системы** (CVA-варианты, tailwind-токены, shadcn base-nova) — не копировать HTML напрямую. Числа в макетах — дизайн-масштаб 1352px (десктоп ~1440).

## 4. Scope

Хэндофф описывает продукт **шире текущей кодовой базы**. Делим на две группы; **обе в scope**, но по-разному.

### Группа A — чистый редизайн + релейаут существующего (реальная функциональность)

Экраны и элементы, которые в коде есть; переносим визуал и компоновку полностью:

- **Фундамент:** токены «Электрик» light+dark, типографика (3 шрифта), радиусы/тени, переключатель темы.
- **Бренд-примитивы кодом:** wordmark K5 (полная/короткая форма), знак, Сфера-орб, SVG-фавиконы.
- **Каркас:** sidebar 252px, центр-колонка max 680px (520px при открытой студии), правая панель 318/470px, высота шапок 52–58px.
- **Главный экран — чат:** bubbles, tool-чипы на лаванде, инлайн artifact-card, фидбэк, стриминг-индикатор, инпут-бар, send-круг.
- **Welcome:** hero-иллюстрация, serif-приветствие, CTA, карточки проектов.
- **Сфера:** viewer (markdown) + базовый редактор — рестайл.
- **Артефакты:** список + markdown-вьюер — рестайл.
- **Проект:** вкладки «Чаты» и «Настройки»; **Настройки пользователя**; **Sidebar**.
- **Иллюстрации** на welcome / empty-states / sidebar-vignette / error через централизованную карту ссылок.
- **★ Error UX (новое, frontend-only):** тосты и error-bars — сейчас красивого отображения ошибок нет (ErrorBoundary на инлайн-стилях, ошибки молчат). Добавляем.

### Группа B — новые фичи НА ЗАГЛУШКАХ (бэкенда нет)

Экраны/интеракции из хэндоффа, под которые в продукте нет бэкенда. Реализуем **фронтовую часть на mock/stub-данных**, без реальных API-вызовов; реальную интеграцию фиксируем в бэклог (§ 9):

- **Семвер сферы:** версии major.minor.patch, дропдаун «Сохранить версию ▾», история версий, бейджи.
- **Peek S3:** «агент записал в сферу» → разворачиваемая карточка в ленте с диффом и откатом.
- **Студия-панель S1.2** и **оверлей-линза S2** — новые интеракции/состояние доступа к сфере из чата.
- **Вьюеры артефактов по типу:** презентация (slides), изображение (зум), аудио (плеер + транскрипт).
- **Rich-редактор сферы** с тулбаром (B/I/H2/список/код/цитата/ссылка, автосейв).
- Панель «Жизнь сферы» (орб, счётчики, хроника, история версий).

**Принцип заглушек:** компонент рендерится с моковыми данными и не падает; интерактив, который требует записи в бэкенд, имитируется локальным состоянием (никаких новых сетевых контрактов). Где хэндофф советует «секцию просто скрыть» (отсутствующие ассеты) — скрываем.

## 5. Границы (что НЕ делаем в feat-004)

- **Реальный бэкенд для группы B** — никаких новых REST-endpoint, схем БД, SSE-событий. Всё, что их требует, → бэклог (§ 9). Появление нового публичного контракта = эскалация архитектору (правило проекта), в этой итерации не вводим.
- **Production-качество ассетов** — чистый cutout (feat-002) и SVG (feat-003) отложены к предпродакшн-гейту. Здесь — кандидаты с неаккуратными краями.
- **Standalone brand-kit** (README-баннеры, соцсети, splash, лендинг) — это feat-005, не трогаем.
- **Character sheets** человеческих персонажей, перегенерация сцен — feat-006.
- **Художественная доводка по живому просмотру** и пере-свап на production-ассеты — feat-006.

## 6. Ключевые решения

1. **Cutout сейчас — `soft-balanced`, не `final`.** Берём вырезанные кандидаты `refs/illustrations/candidates/transparent/soft-balanced/{light,dark}/` (6 сцен × 2 темы, RGBA). Известные дефекты края (кремовый halo на тёмном фоне, невырезанные внутренние области) на этой фазе приемлемы — качество не цель. Ассеты **копируются** в `frontend/src/shared/assets/illustrations/{light,dark}/` (билд не видит `doc/`).
2. **Централизованная карта ссылок на ассеты** — единый модуль (напр. `frontend/src/shared/assets/illustrations/index.ts`), отдающий путь по `(scene, theme)`. Это единственная точка свапа: feat-006 заменит soft-balanced → production-cutout/SVG правкой карты, без охоты по компонентам.
3. **Dark + переключатель.** Строим переключатель темы: zustand-стор, класс `.dark` на `<html>`, persist в localStorage, инициализация по `prefers-color-scheme`. Это активирует готовую dark-палитру и dark-пак иллюстраций.
4. **Типографика — замена Geist на 3 семейства** через `@fontsource`: Source Serif 4 (заголовки/имена сущностей), Instrument Sans (весь UI/body), IBM Plex Mono (версии/таймкоды/тех-метки). Точные пакеты подбираются на реализации.
5. **Бренд-примитивы — в `shared/ui`.** Wordmark K5, короткая форма, знак, Сфера-орб — переиспользуемые компоненты, строятся кодом по спеке (бинарников в хэндоффе нет). Текстовый «LearnFlowAI» в Sidebar/Welcome заменяется на wordmark.
6. **Error UX — через тост-примитив shadcn (`sonner`).** Тосты + error-bars подключаются к существующему парсеру ошибок (`shared/lib/api-error.ts`) и поведению QueryClient (не ретраит 4xx). ErrorBoundary переводится с инлайн-стилей на токены.
7. **Рефактор захардкоженных цветов → семантические токены.** Security-бейджи (`blue/yellow/green-500` в `pages/security/ui/*`) и инлайн-hex в `ErrorBoundary.tsx` приводятся к токенам.
8. **Документация.** Дизайн-соглашения (токены, темизация, нейминг css/компонентов, ассет-пайплайн) фиксируются в новом `doc/tech/design-system.md` + ссылка из `conventions.md` и `doc/index.md`. Пишутся по ходу, на фазе DOC_UPDATE.
9. **shadcn-примитивы руками не правим** (перегенерация затрёт) — кастомизация бренда идёт через токены и наши композиции поверх примитивов (конвенция `shared/ui`).

## 7. Трек-декомпозиция

Предлагаемое разбиение для планнера (детальный план — на фазе PLAN). Зависимости важнее порядка номеров.

```
T1  Фундамент: токены + шрифты + тема + переключатель          [блокирует всё]
    └ index.css (Электрик light/dark), @fontsource (3 шрифта), радиусы/тени,
      theme-store + toggle (.dark на html, persist, prefers-color-scheme),
      рефактор захардкоженных цветов → токены

T2  Бренд-примитивы                                             [после T1]
    └ wordmark K5 (full/short), знак, Сфера-орб в shared/ui, SVG-фавиконы

T3  Ассет-пайплайн + иллюстрации                                [после T1]
    └ копирование soft-balanced в shared/assets, централизованная карта,
      врезки на welcome/empty/sidebar-vignette/error (light/dark по теме)

T4  Каркас + рестайл экранов группы A                           [после T1–T3]
    └ каркас (sidebar 252 / центр 680 / шапки), рестайл: чат, welcome, сфера
      (viewer+базовый редактор), артефакты (список+md), проект (Чаты/Настройки),
      настройки пользователя, sidebar

T5  Error UX                                                    [после T1; ~независим]
    └ sonner-тосты + error-bars, привязка к api-error/QueryClient, ErrorBoundary

T6  Новые фичи группы B на заглушках                            [после T1,T2,T4]
    └ студия-панель S1.2, линза S2, peek S3, семвер-UI сферы, вьюеры
      slides/image/audio, rich-редактор, «Жизнь сферы» — на mock-данных
```

**Параллелизм.** Оркестратор по умолчанию однопоточный, но для этой итерации архитектор разрешил параллелить непересекающиеся скоупы. T1 идёт первым (трогает глобальный `index.css` — конфликтная зона). После T1 кандидаты на параллель: **T2, T3, T5** (разные файлы/директории). T4 — центральный и объёмный, после T2/T3. T6 — последним. Режим (параллель/линейно) — на усмотрение прогона.

## 8. Процесс (AIDD, cloud)

Итерация идёт штатным конвейером оркестратора: **PLAN → по трекам (IMPLEMENT → TEST → локальный коммит) → INTEGRATION_TEST → CODE_REVIEW → DOC_UPDATE → pre-commit gate**. `plan.md` создаёт фаза PLAN (здесь его нет намеренно).

**Cloud merge-policy** (`conventions.md` § Cloud sessions): агент доводит фичу до feature-ветки `fe/feat-004-...`, делает commit + push + PR в develop. **Merge в develop — за архитектором локально.** Причина — визуальная валидация редизайна обязательна на живых экранах, а в облаке UI-проверка ограничена. Все 👤-кейсы (визуальная сверка с хэндоффом) tester помечает как требующие ручной проверки и эскалирует.

**Статусы:** 🚧 уже стоит. Перевод в ✅ Done — только после явного апрува архитектора о завершённости (после локальной визуальной приёмки и merge PR). Агент ✅ самовольно не ставит.

**Quality gate:** `make check-fe` (ESLint + Prettier) и `tsc -b && vite build` — обязательный automated-гейт каждого трека.

## 9. Бэклог для бэкенда (порождается группой B)

Фиксируется здесь; заводится в продуктовый трек отдельными итерациями с апрувом архитектора. Фронт группы B построен на заглушках под эти будущие контракты:

- **Версионирование сферы:** хранение версий major.minor.patch, история, автор (agent/user), summary; API чтения/сохранения версии; правила предложения уровня (патч/минор/мажор).
- **SSE-событие «агент пишет в сферу»** для peek S3 (индикатор + последующая карточка с диффом и откатом к версии).
- **Типы артефактов** slides / image / audio: модель, хранение, отдача; для аудио — транскрипт/саммари/ключевые моменты с таймкодами.
- **Состояние студии-панели** (open/tab/selectedArtifactId), если требуется персистентность на сервере (иначе остаётся клиентским).

## 10. Open Questions

На момент написания брифа блокирующих открытых вопросов нет — крупные развилки (scope A+B-на-заглушках, cutout soft-balanced, dark+toggle, wordmark/орб в продукте, error UX, процесс через cloud) согласованы с архитектором. Решения уровня реализации (точные `@fontsource`-пакеты, размещение по FSD внутри слоёв, форма mock-данных группы B) планнер закрывает по дизайн-системе и FSD-конвенции; при многозначности без доминирующего варианта — эскалация по базовому принципу автономности.
