# Design Brief: feat-004 — Design-system integration

| Поле | Значение |
|------|----------|
| Итерация | feat-004 (трек design-branding) |
| Статус | 🚧 In Progress |
| Cross | frontend |
| Зависит от | feat-001 (стиль, токены, пак иллюстраций, design-handoff) |

## 1. Зачем эта итерация

Продукт сейчас выглядит generic: дефолтная нейтральная палитра shadcn (серая шкала `oklch(L 0 0)`, без бренда), шрифт Geist, тёмная тема описана в CSS, но недостижима (нет переключателя), логотип — просто текст «LearnFlowAI», иллюстраций нет вообще. Цель Фазы 4 — «не стыдно показать»: продукт получает фирменный визуальный язык и перестаёт быть безликим.

В feat-001 (PoC) визуальная идентичность **уже спроектирована до уровня high-fidelity хэндоффа** — это не проектирование с нуля, а **перенос готовой дизайн-системы «Чернила / Электрик» в код**. Поэтому ключевая ценность брифа — зафиксировать границы (что переносим, что делаем на заглушках, чего не делаем), процесс и архитектуру верификации, а сама спецификация вида живёт в хэндоффе и не дублируется здесь.

## 2. Видение бренда (кратко)

Система **«Чернила / Электрик»**: тёплая бумажная основа (кремовый фон) + один плоский фиолетовый акцент (`#7434F4`), serif-акценты в заголовках, **сфера знаний как визуальное ядро бренда**. Характер: спокойный · умный · тёплый · собранный. Анти-цели: детскость, корпоративный холод, generic-AI-эстетика. **Жёсткое правило:** фиолетовые градиенты в UI запрещены — фиолетовый всегда плоский, градиент живёт только внутри сферы-орба.

## 3. Источник спецификации

Пиксельный first-source — пакет хэндоффа feat-001:

```
doc/tasks/iterations/design-branding/feat-001-poc/design-handoff/design_handoff_brand_electric/
├── README.md                  ← токены, типографика, wordmark K5, 11 экранов, интеракции, state
├── *.dc.html (5 файлов)       ← HTML-прототипы целевого вида (референс + эталон для визуального ревью)
└── support.js                 ← рантайм для просмотра dc.html (в кодовую базу не переносить)
```

Хэндофф high-fidelity: цвета, типографика, отступы, радиусы и копирайт финальные, воспроизводить пиксельно, но **средствами существующей дизайн-системы** (CVA-варианты, tailwind-токены, shadcn base-nova) — не копировать HTML напрямую. Числа в макетах — дизайн-масштаб 1352px (десктоп ~1440).

## 4. Scope

Хэндофф описывает продукт **шире текущей кодовой базы**. Делим на две группы; **обе в scope**, но по-разному.

### Группа A — чистый редизайн + релейаут существующего (реальная функциональность)

- **Фундамент:** токены «Электрик» light+dark, типографика (3 шрифта), радиусы/тени, переключатель темы.
- **Бренд-примитивы кодом:** wordmark K5 (полная/короткая форма), знак, Сфера-орб, SVG-фавиконы.
- **Каркас:** sidebar 252px, центр-колонка max 680px (520px при открытой студии), правая панель 318/470px, высота шапок 52–58px.
- **Главный экран — чат:** bubbles, tool-чипы на лаванде, инлайн artifact-card, фидбэк, стриминг-индикатор, инпут-бар, send-круг.
- **Welcome:** hero-иллюстрация, serif-приветствие, CTA, карточки проектов.
- **Сфера:** viewer (markdown) + базовый редактор — рестайл.
- **Артефакты:** список + markdown-вьюер — рестайл.
- **Проект:** вкладки «Чаты» и «Настройки»; **Настройки пользователя**; **Sidebar**.
- **Иллюстрации** на welcome / empty-states / sidebar-vignette / error через централизованную карту ссылок.
- **★ Error UX (новое, frontend-only):** тосты и error-bars — сейчас красивого отображения ошибок нет (ErrorBoundary на инлайн-стилях, ошибки молчат). Добавляем.

### Группа B — новые фичи НА ЗАГЛУШКАХ (бэкенда нет)

Фронтовая часть на mock/stub-данных, без реальных API; реальную интеграцию фиксируем в бэклог (§ 10):

- **Семвер сферы:** версии major.minor.patch, дропдаун «Сохранить версию ▾», история версий, бейджи.
- **Peek S3:** «агент записал в сферу» → разворачиваемая карточка в ленте с диффом и откатом.
- **Студия-панель S1.2** и **оверлей-линза S2** — новые интеракции доступа к сфере из чата.
- **Вьюеры артефактов по типу:** презентация (slides), изображение (зум), аудио (плеер + транскрипт).
- **Rich-редактор сферы** с тулбаром (B/I/H2/список/код/цитата/ссылка, автосейв).
- Панель «Жизнь сферы» (орб, счётчики, хроника, история версий).

**Принцип заглушек:** компонент рендерится с моковыми данными и не падает; интерактив, требующий записи в бэкенд, имитируется локальным состоянием (никаких новых сетевых контрактов). Где хэндофф советует «секцию просто скрыть» (отсутствующие ассеты) — скрываем.

## 5. Границы (что НЕ делаем в feat-004)

- **Реальный бэкенд для группы B** — никаких новых REST-endpoint, схем БД, SSE-событий. Всё, что их требует, → бэклог (§ 10). Новый публичный контракт = эскалация архитектору.
- **Production-качество ассетов** — чистый cutout (feat-002) и SVG (feat-003) отложены к предпродакшн-гейту. Здесь — кандидаты с неаккуратными краями.
- **Standalone brand-kit** (README-баннеры, соцсети, splash, лендинг) — это feat-005.
- **Character sheets**, перегенерация сцен, художественная доводка по живому просмотру и пере-свап на production-ассеты — feat-006.

## 6. Ключевые решения

1. **Cutout сейчас — `soft-balanced`, не `final`.** Берём вырезанные кандидаты `refs/illustrations/candidates/transparent/soft-balanced/{light,dark}/` (6 сцен × 2 темы, RGBA). Дефекты края на этой фазе приемлемы. Ассеты **копируются** в `frontend/src/shared/assets/illustrations/{light,dark}/`.
2. **Централизованная карта ссылок на ассеты** — единый модуль (`frontend/src/shared/assets/illustrations/index.ts`), отдаёт путь по `(scene, theme)`. Единственная точка свапа для feat-006.
3. **Dark + переключатель.** zustand-стор, класс `.dark` на `<html>`, persist в localStorage, инициализация по `prefers-color-scheme`.
4. **Типографика — замена Geist на 3 семейства** через `@fontsource`: Source Serif 4 (заголовки/имена сущностей), Instrument Sans (UI/body), IBM Plex Mono (версии/таймкоды). Точные пакеты — на реализации.
5. **Бренд-примитивы — в `shared/ui`.** Wordmark K5, короткая форма, знак, Сфера-орб — переиспользуемые компоненты кодом по спеке. Текстовый «LearnFlowAI» заменяется на wordmark.
6. **Error UX — через тост-примитив shadcn (`sonner`).** Привязка к парсеру `shared/lib/api-error.ts` и поведению QueryClient (4xx не ретраит). ErrorBoundary переводится на токены.
7. **Рефактор захардкоженных цветов → токены.** Security-бейджи (`pages/security/ui/*`) и инлайн-hex в `ErrorBoundary.tsx`.
8. **Документация** дизайн-соглашений — новый `doc/tech/design-system.md` + ссылка из `conventions.md` и `doc/index.md`, на фазе DOC_UPDATE.
9. **shadcn-примитивы руками не правим** — кастомизация бренда через токены и композиции поверх (конвенция `shared/ui`).

## 7. Трек-декомпозиция и параллелизм

```
T1  Фундамент: токены + шрифты + тема + переключатель          [блокирует всё]
T2  Бренд-примитивы (wordmark K5, знак, Сфера-орб, фавиконы)    [после T1]
T3  Ассет-пайплайн + иллюстрации (карта + врезки)               [после T1]
T4  Каркас + рестайл экранов группы A                           [после T1–T3]
T5  Error UX (sonner-тосты + error-bars + ErrorBoundary)        [после T1]
T6  Новые фичи группы B на заглушках                            [после T1,T2,T4]
```

**Параллелизм волнами** (локально, оркестратор разводит скоупы):

```
Волна 1:  T1                    (solo — глобальный index.css/тема, конфликтный хребет)
Волна 2:  T2 ∥ T3 ∥ T5         (в основном новые файлы, чёткие границы владения)
Волна 3:  T4                    (solo — каркас + все экраны, общий хребет)
Волна 4:  T6                    (solo/полу — заглушки группы B)
```

T1 трогает `index.css`, тему, роутер — параллелить нельзя. После T1 burst T2/T3/T5 идут параллельными implementer'ами (примитивы в `shared/ui`, ассеты в `shared/assets`, тост+ErrorBoundary — пересечения минимальны, после волны короткая интеграция). T4 — центральный и объёмный, solo. T6 — последним. Верификация (визуальный ревьюер) идёт рядом с волнами.

## 8. Архитектура верификации

**Принцип:** максимум проверки автоматизируем или отдаём агенту-ревьюеру; архитектору на финал приходит только то, что требует вкуса (бренд-ощущение, тонкая полировка), а не механика. Три яруса:

### 8.1. Automated gate (детерминированный, каждый трек)
`make check-fe` (ESLint + Prettier) + `tsc -b && vite build` + статические грепы (нет захардкоженных цветов, shadcn-примитивы не тронуты, нет сетевых вызовов к несуществующим endpoint'ам в заглушках). Блокирующий.

### 8.2. Агент-визуальный-ревьюер (Playwright MCP, без установки в проект)
Отдельный сабагент драйвит запущенное локальное приложение. По каждому экрану в **light и dark**:
- **навигация** на роут (на населённых данных — см. 8.4);
- **детерминированные числа** через `browser_evaluate` + `getComputedStyle`: вычисленные значения токенов (`--primary` и пр.), ширина sidebar (252px), высота шапок (52–58px), `font-family` заголовков (Source Serif 4) и body (Instrument Sans), радиусы, контраст текста (порог читаемости);
- **скриншот** экрана + открытый рядом `.dc.html`-макет как эталон гештальта;
- **сверка вида** с макетом и спекой README → находки с severity;
- **чтение консоли** (`browser_console_messages`) → ноль ошибок/ворнингов.

**Выход:** триажный отчёт (`visual-review-report.md`) + контактный лист скриншотов всех экранов × тем (артефакты итерации). Триаж:
- `blocker` / явный `mismatch` (не та геометрия/цвет/шрифт, пропал элемент, ошибка консоли) → цикл фиксов с implementer'ом **без архитектора**;
- `taste` / «не могу определить» (бренд-ощущение, тонкая полировка) → к архитектору.

**Размещение в конвейере:** лёгкий **smoke на каждом треке** (числа + консоль для экранов трека — ловит грубое сразу) и полная фаза **VISUAL_REVIEW** перед арх-гейтом (все экраны × light/dark vs макеты, триаж).

### 8.3. Финальный вкусовой проход архитектора
Архитектор получает триажный отчёт + контактный лист и сам проходит по живому UI, давая видение поверх. Его правки — высокоценный остаток, не первичный отлов дефектов.

### 8.4. Подготовка данных (data-prep)
Населённые экраны (чат с сообщениями, артефакты, сфера с контентом, security) тестируются на **реальных данных в реальной БД**, не на агентском кликинге. Отдельный **data-prep сабагент** готовит детерминированный seed-фикстур **через существующие SQLAlchemy-модели/репозитории, без изменения схемы**: один пользователь (+admin через `make grant-admin` для security-экранов), проект, несколько чатов с сообщениями (user + assistant, tool-вызовы, инлайн-артефакт), набор артефактов, документ сферы. Seed-скрипт идемпотентен и складывается в репозиторий как тест-инфраструктура (не продакшен-код). Welcome/empty-states данных не требуют; группа B — на моках.

## 9. Процесс (AIDD, локально)

Штатный конвейер оркестратора, расширенный визуальным ревью: **PLAN → по волнам (IMPLEMENT → smoke-TEST → локальный коммит) → INTEGRATION_TEST → VISUAL_REVIEW → CODE_REVIEW → DOC_UPDATE → pre-commit gate (архитектор)**. `plan.md` создаёт фаза PLAN.

- **Quality gate** каждого трека: `make check-fe` + `tsc -b && vite build` + smoke-ревью.
- **Loop bound:** на находку ≤2 фикс-цикла implementer ↔ ревьюер; не сдвинулось — эскалация.
- **Статусы:** 🚧 стоит. Перевод в ✅ Done — только после явного апрува архитектора (после его визуальной приёмки и merge PR). Агент ✅ не ставит.
- **Merge** PR в develop — за архитектором локально.

## 10. Бэклог для бэкенда (порождается группой B)

Заводится в продуктовый трек отдельными итерациями с апрувом. Фронт группы B построен на заглушках под эти будущие контракты:

- **Версионирование сферы:** хранение версий major.minor.patch, история, автор (agent/user), summary; API чтения/сохранения; правила предложения уровня.
- **SSE-событие «агент пишет в сферу»** для peek S3 (индикатор + карточка с диффом и откатом).
- **Типы артефактов** slides / image / audio: модель, хранение, отдача; для аудио — транскрипт/саммари/таймкоды.
- **Состояние студии-панели** на сервере (если потребуется персистентность; иначе остаётся клиентским).

## 11. Open Questions

Блокирующих открытых вопросов нет — все крупные развилки согласованы с архитектором (scope A+B-на-заглушках, cutout soft-balanced, dark+toggle, wordmark/орб в продукте, error UX, локальный прогон, агент-визуальный-ревьюер на Playwright MCP, населённые данные через data-prep seed). Решения уровня реализации (точные `@fontsource`-пакеты, размещение по FSD, форма mock-данных) планнер/implementer закрывают по дизайн-системе и FSD-конвенции; при многозначности без доминирующего варианта — эскалация.
