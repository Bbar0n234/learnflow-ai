# Test Cases: feat-004 — Design-system integration

## Природа итерации и стратегия проверки

Визуальный редизайн + релейаут. Цель стратегии — **максимум проверки автоматизировать или отдать агенту-ревьюеру**, чтобы архитектору на финал приходил только вкусовой остаток. Три механизма:

- **🤖 Automated gate** — `make check-fe` + `tsc -b && vite build` + статические грепы. Блокирующий, каждый трек.
- **🔍 Агент-визуальный-ревьюер (Playwright MCP)** — драйвит запущенное приложение: снимает детерминированные числа через `getComputedStyle`, скриншоты, сверяет с `.dc.html`-макетами, читает консоль. Закрывает бывшие «👤»-числовые кейсы как детерминированные и триажит визуальные находки (mismatch → implementer; вкус → архитектор).
- **👤 Архитектор** — финальный вкусовой проход поверх триажного отчёта (бренд-ощущение, тонкая полировка). Не первичный отлов.

**Данные:** населённые экраны проверяются на реальном seed-фикстуре (см. {DP}); welcome/empty-states — без данных; группа B — на моках.
