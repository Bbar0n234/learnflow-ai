# Test Cases: feat-001 — Видимость работы агента / трек T2

Трек T2 сделал экранную половину «видимости работы агента»: ленту активности, которая рисует
работу агента одними и теми же строками в live и в истории, реестр человекочитаемых подписей
инструментов, переработанный stream-store и диспетчер SSE v2 со сторожем тишины от heartbeat.
Это **новая фича с изменением контракта**, а не поведение-сохраняющий рефактор: `ThinkingIndicator`
и `ToolIndicator` исчезли, `streamingText`/`activeTool`/`pendingImages` в сторе заменены лентой,
сообщение ассистента рендерится по `parts`, а `VITE_SSE_FIRST_BYTE_TIMEOUT_MS` ушла вместе с
first-byte-таймаутом.

Кейсы страхуют то, что в этой картине ломается тихо. Почти всё покрытие трека — про вещи, чья
поломка не даёт ни исключения, ни красного экрана: лента после перезагрузки показывает не то, что
пользователь видел живым; строка вызова теряет подпись; обрезанные сервером аргументы уезжают на
экран сырым обломком JSON; сторож тишины гасит живой поток или, наоборот, не срабатывает вовсе;
заблокированный ход оставляет на экране свои рассуждения. Ни одна из этих поломок не роняет
приложение — она просто врёт пользователю о том, что делал агент, — поэтому каждая покрыта
отдельным кейсом.

## Конвенции прохождения (инлайн — это рамка тестировщика)

**Статус и run-log.** У каждого кейса — текущий статус плюс опциональный run-log, если кейс прогонялся не раз:

- `- [x]` + лаконичный результат: что проверялось, что получилось, значимые нюансы. По заполненному чек-листу должно быть видно, что всё работает, без перепрохождения.
- `- [ ] ⚠️` + причина, если кейс не пройден или требует отдельного внимания.
- Кейсы с 👤 — требуют ручного действия / решения архитектора (UI, браузер); тестировщик помечает и эскалирует.
- **Доменные маркеры**: `📊` — проверка наблюдаемости (структура БД, метрики, Redis state, Langfuse); `🔴` — проверка реальных инъекций / атак / security-событий; `[auto]` — кейс закрыт автотестом (живёт рядом со слайсом, `frontend/src/**/*.test.tsx`); *(регресс)* — кейс страхует «поведение не сломалось».
- **run-log** (только у перепрогнанных кейсов) — строка-история флипов с причиной:
  `runs: r1 ✅ → r2 ❌ (после фикса review #3: регрессия инвалидации) → r3 ✅`.
  Один прогон — run-log не нужен. Перепрогон после правки кода обязателен (см. ре-верификацию).

**Ре-верификация.** Правка кода аннулирует прошлый зелёный статус затронутого. После фиксов: детерминированный гейт (`make check-fe` / `make test-fe`) — перепрогон всегда; ручные/UI-кейсы — перепрогон только затронутой области. Каждый перепрогон → запись в run-log.

**Диагностика — через наблюдаемость, не догадки.** Один кейс — одна попытка диагностики: не сошлось — повтори (мог быть транзиент); не сошлось второй раз — fail + эскалация, без долгой отладки. Инструменты: DevTools → Network → EventStream (кадры SSE), DevTools → Console (логи через `@/shared/lib/logger`, там же предупреждение о неизвестном типе события), React DevTools для состояния стора, structlog бэкенда. Код читать только там, где поведение иначе не наблюдаемо (явно отмечать). Код тестировщик не правит: прод-баги, вскрытые кейсом, чинит **fixer** (A6: fixer ≠ автор теста).

**Скоуп по трекам.** Кейсы с префиксом трека (`{T2.1}`) гоняются на своём треке + Layer 0; cross-cutting (Layer 2/3 без префикса) — в INTEGRATION_TEST. Не пропускать кейсы молча — неприменимый помечать причиной.

## Дизайн автотестов

Покрытие разложено по трём уровням, ровно как советует `testing.md` § Frontend. Чистая модель ленты
и реестр подписей закрыты solitary-юнитами — это трансляции без зависимостей, где дублей не нужно
вовсе. Экран (`MessageItem`, `MessageList`) закрыт integration-тестами через RTL: запросы идут по
роли и тексту, то есть проверяется то, что видит пользователь, а не разметка. Диспетчер стрима
закрыт integration-тестом поверх настоящего `fetch` с MSW-стримом: события подаются кадрами
`data: {json}`, как их шлёт сервер, а таймеры сторожа тишины двигаются фейковыми часами.

Смоук-наборы, оставленные реализаторами фаз T2.1–T2.6, разобраны поимённо: кейсы, проверяющие
контракт, сохранены на месте, остальное дополнено или переписано. Помечено в записях суит ниже.

**Проверено мутацией** (прод-код правился временно, рабочее дерево после каждой проверки чистое):
(1) перенос перезавода сторожа тишины **за** проверку известности типа события — краснеет кейс
«перезаводит сторож тишины и на событии неизвестного типа», и только он; (2) возврат к
консервативному флагу усечения в адаптере истории (`result_truncated || args_truncated` — та самая
эвристика, которую T2.2 выбросила) — краснеют три кейса сразу: независимость флагов в модели,
эквивалентность live/история на ходе с усечением и маркер зоны на экране. То есть оба механизма
сторожатся не по чтению, а по факту.

**Покрываем автотестом** — по одной записи на суиту:

### `agent-tools.test.ts` — реестр подписей инструментов

### `useAgentStream.test.ts` — диспетчер SSE v2

1. **Файл**: `frontend/src/pages/chat/model/useAgentStream.test.ts` — integration, MSW со стриминговым телом `text/event-stream`, фейковые таймеры под сторож тишины
2. **Тестирует**: `pages/chat/model/useAgentStream :: useAgentStream`
3. **Суть**: Суита закрывает единственное место, где словарь контракта превращается в содержимое экрана, и проверяет его с трёх сторон. Первая — маршрутизация: полный ход v2 подаётся кадрами, и с каждой ветки диспетчера спрашивается её собственный наблюдаемый след, а не только форма ленты. Строка вызова обязана приехать с аргументами (без них теряется дополнение подписи, зона «Вызов» в развороте и задание субагента), рассуждение и текст — со своим содержимым, срез guard'ом — статусом `cancelled`, объявленный артефакт — карточкой в идущем ходе, пара review-событий — поднятым и снятым флагом проверки. Пропущенная ветка ничего не роняет, она просто стирает часть работы агента из виду, поэтому ассерт на форму ленты её не ловит. Вторая — сторож тишины: он обязан взводиться до запроса (иначе сервер, не вернувший даже заголовков, оставляет пользователя в бесконечном ожидании), перезаводиться любым пришедшим кадром — включая `heartbeat` и событие типа, которого фронт ещё не знает, — и сниматься на терминальном событии, чтобы сервер, придержавший соединение открытым после `done`, не превратил успешный ход в ошибку. Третья — терминальные события и кэши: списки чатов рефетчатся на `done`, `cancelled` и `error`, потому что автозаголовок пишется в БД независимо от исхода хода, и не рефетчатся на блокировке, где генерация заголовка не запускается вовсе.
4. **Кейсы**: `done` отдаёт message/trace id; блокировка заменяет ленту одной заглушкой; блокировка оптимистично помечает чат заблокированным; блокировка закрывает стрим; `error` доносит detail; не-ok ответ отдаёт problem-сообщение; битый кадр пропускается, поток продолжается; отмена не даёт ошибки; unmount рвёт поток и сбрасывает стор; хвостовая ошибка после отмены подавлена; полное молчание сервера даёт таймаут ровно за порогом; heartbeat держит молчаливый поток живым; неизвестный тип не рвёт поток; он же перезаводит сторож тишины; сторож снимается на терминальном событии; `cancelled` закрывает поток без ошибки и рефетчит detail и оба списка; повтор POST после 401; `artifact_created` даёт карточку артефакта в идущем ходе и инвалидирует их список; пара review-событий поднимает и снимает флаг проверки; обрыв без терминального события; сетевая ошибка; полный ход v2 доезжает до ленты с содержимым каждой ветки; списки рефетчатся на терминальной ошибке; списки чатов проекта не рефетчатся на блокировке, detail и recents — рефетчатся; feat-002: патч заголовка в три кэша, отсутствие рефетча на `title_updated`, отсутствие кэшей не роняет ход, fallback-инвалидация на `done` ровно по своему ключу

### `MessageItem.test.tsx` — сохранённый ход на экране

1. **Файл**: `frontend/src/pages/chat/ui/MessageItem.test.tsx` — integration (RTL), запросы по роли и тексту
2. **Тестирует**: `pages/chat/ui/MessageItem` в связке с `ActivityFeed` / `ActivityRow` / `ActivityDetails`
3. **Суть**: Суита проверяет, что сохранённый ход читается как работа агента, а не как дамп: строка действия несёт подпись из реестра вместо машинного имени, разворот показывает зоны «Вызов» и «Результат» с сырым именем инструмента, а статус вызова выражен словом, а не одним цветом — все три состояния истории, включая `pending` у хода, оборванного отменой. 4. **Кейсы**: подпись из реестра с аргументом; разворот показывает сырое имя, args и результат; маркер усечения и честная надпись кнопки; усечение аргументов не метит зону результата; три статуса вызова читаются словами; незавершённый вызов объясняет отсутствие результата; обрезанные аргументы сырой строкой не показываются; аргументы нештатной формы показываются сырыми без маркера обрезки; короткий результат без кнопки раскрытия; длинный неусечённый раскрывается и сворачивается; оба флага усечения независимы; инструмент вне реестра с пометкой источника; рассуждение свёрнуто и раскрывается своим текстом; ход из одного текста ленты не получает; пустые `parts` и отсутствие поля дают degraded-рендер по `content`; заблокированный ход показывает одну заглушку и ни одной строки; субагент в истории разворачивается в задание и ответ без вложенных шагов; несколько вызовов — одна лента

**П2. Инструмент, чьё имя совпадает с ключом `Object.prototype`, роняет рендер всего сообщения — major `[prod]`.**
`frontend/src/shared/config/agent-tools.ts:203-213`. `AGENT_TOOL_SIGNATURES[name]` ищет по обычному
