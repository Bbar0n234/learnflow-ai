### Что проверено и соответствует

Фиксирую явно, чтобы дальше по конвейеру это не переоткрывали:

- **Design-brief ↔ код.** Оба пути входа, отсутствие ввода имени чата где-либо в продукте, плейсхолдер «Новый чат» в БД, draft-режим (скрыты селектор модели и чип MCP, `useChat` не бьёт по сети), однократность авто-отправки (ref-guard + затирание router state), `title_updated` как не-терминальное событие с эмитом в relay-цикле, отсутствие эмита после терминала, `setQueryData` без `invalidateQueries` в трёх кэшах, `exact: true` на всех инвалидациях `projects.chats(id)`, fallback-инвалидация на `done` без дубля `chats.recent`, rename/delete доступны для `security_blocked` чатов, каскад удаления в заявленном порядке (проверены FK: `thread_mcp_servers`/`thread_settings` — `CASCADE`, `artifacts.thread_id` — `SET NULL`), best-effort `adelete_thread` после commit с `warning + exc_info`.
- **Scope boundaries брифа соблюдены**: нет чатов без проекта, нет soft-delete, нет чистки checkpoints проектов, нет регенерации title по запросу, нет индикатора «название генерируется» (`TypedTitle` — анимация прибытия, не индикатор процесса).
- **Конвенции доменов.** `agent.md` § Reasoning LLMs — `title` идёт через `_build_chat_model`, единая форма `extra_body.reasoning: {effort, exclude}`; § Prompt Naming — `title--{label}` через реестр `configs/prompts.yaml` (код сидера не тронут, `_seed_prompts` итерируется по реестру). `api.md` — `201/204/422`, идемпотентный DELETE, envelope списков не тронут, нейминг chat/thread по границе path. `db.md` — схема не менялась, миграции не требуются, ранний commit в `send_message` обоснован по правилу и предусловие проверено. `frontend.md` — `features/chat-actions` заведён по критерию «2+ хоста», `NewChatModal` остался в `app/components` (один хост), новых query-ключей нет, мутации пессимистичные, ошибки через `getApiErrorMessage` + `logger`, токены только через CSS-переменные (`var(--primary)` в `index.css`, hex в `.tsx` нет). `conventions.md` § Module-level state — состояние генератора в `app.state`, синглтонов нет; § Типизация — `TitleConfig` как `BaseModel` по образцу `ImageConfig`, форма секции YAML-конфига соблюдена.
- **Архитектурная уместность.** `ChatTitleGenerator` — сервисный слой, зависимости через конструктор, собственная сессия из `session_factory` (образец `image_generation`); `delete_thread` добавлен в контракт `AgentRunner` (Protocol), реализация получает checkpointer обычным DI, сервис в `app.state` не ходит; `services/constants.py` не создаёт нового паттерна — направление `api → services` легально, обратного импорта нет. Своих Result-типов, дублей сервисов, module-level синглтонов не заведено.
