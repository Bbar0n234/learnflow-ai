# Implementation Plan: feat-002-chat-ux / трек T2 — Frontend: вход через первое сообщение + `title_updated` + ChatActions

## Контекст

Трек переворачивает вход в чат на фронте: поле ввода становится полем **первого сообщения**, а не названия; название приезжает из стрима событием `title_updated` и заменяет плейсхолдер «Новый чат» анимацией посимвольной печати; у чатов появляются rename и delete. Работа целиком внутри `frontend/src/**` — бэкенд-контракты берём из § Контракты design-brief'а, в код трека T1 не заглядываем.

Источники:

- Запись итерации — [tasklist-dogfooding.md](../../../../tasklist-dogfooding.md) § feat-002 (C): Chat UX
- [design-brief.md](../../design-brief.md) — целевой UX, архитектура, § Контракты, § Frontend: раскладка нового кода, § Партиция треков (границы T2: `frontend/src/**`)
- Мокап-референс — [mockups/chat-ux.html](../../mockups/chat-ux.html) (утверждён архитектором): оба пути входа, тайминги печати title, тексты диалогов, поведение композера
- [conventions/frontend.md](../../../../../tech/conventions/frontend.md) — FSD-раскладка, ось состояния, мутации, дизайн-токены, stub-gating
- [frontend.md](../../../../../tech/frontend.md) — экраны, query-ключи, таблица «Mutations → инвалидация»; [streaming.md](../../../../../tech/streaming.md) — таблица SSE-событий

Что уже есть в коде и на что опираемся: `ProjectActions` (`app/components/ProjectActions.tsx`) — эталон dropdown + rename/delete-диалогов; `ProjectCard` — эталон вёрстки строки с hover-действиями (`group/card relative` + абсолютный слот); `useAgentStream` (`pages/chat/model/`) — единственная точка разбора SSE; кастомные keyframes с `prefers-reduced-motion` живут в `index.css` (`gen-progress-indeterminate`, `thinking-dot-pulse`) — новая анимация каретки идёт туда же по этому образцу.

Автотесты трека пишет позже независимый `test-author`; фазы ниже код тестов не создают. Глобальные MSW-handler'ы (`frontend/src/test/msw/handlers.ts`) намеренно пустые — каждый тест объявляет сеть через `server.use(...)`, так что инфраструктура тестов правки не требует.

Порядок фаз: сначала слой данных и стрима (T2.1–T2.2), затем UI поверх него (T2.3–T2.4), затем два пути входа (T2.5–T2.7). Такой порядок минимизирует переписывание одних и тех же строк списков: `ChatActions` перестраивает разметку строк чата, а печать title уже вставляется в готовую разметку.

## Фазы

### T2.1: API-слой чатов — create без тела, update, delete, доменные константы

**Цель:** привести `shared/api/chats.ts` к новым контрактам эндпоинтов чатов и завести data-хуки rename/delete с правильной инвалидацией.

**Изменения:**

- `frontend/src/shared/api/chats.ts`:
  - `createChat(projectId)` — запрос без тела; тип `CreateChatRequest` удаляется целиком (пользователь title больше не задаёт нигде, § Контракты); `useCreateChat` принимает только `projectId`.
  - `updateChat(projectId, chatId, { title })` → `PUT`, ответ `Chat`; `deleteChat(projectId, chatId)` → `DELETE`, `204`.
  - `useUpdateChat` / `useDeleteChat` — пессимистичные мутации (проектный дефолт): в `onSuccess` инвалидировать `queryKeys.projects.chats(projectId)` **с `exact: true`** и `queryKeys.chats.recent`; при rename detail открытого чата обновляется **`setQueryData`-патчем поля `title`** (симметрично T2.2), не инвалидацией — резолюция PLAN_REVIEW: точечная инвалидация detail при rename во время активного стрима воспроизводила бы ту же гонку задвоения из-за optimistic-копии в `localMessages`, ради которой бриф запретил рефетч detail для `title_updated`. `exact: true` обязателен: `projects.chats(id)` — префикс detail-ключа открытого чата, префиксная инвалидация зарефетчит его посреди активного стрима (§ Доставка title на фронт).
  - Доменные константы рядом с типами: `DEFAULT_CHAT_TITLE = "Новый чат"` (значение плейсхолдера из § Целевой UX) и предел длины названия для валидации rename (см. Open Questions — число задаёт T1).
- `frontend/src/pages/project-chats/ui/ChatList.tsx`, `frontend/src/app/components/Sidebar.tsx` — механическая правка вызовов `createChat.mutate` под новую сигнатуру, чтобы дерево компилировалось. Логику входа эти файлы получают в T2.5 и T2.7, здесь её не трогаем.

**Verification:**

- `make check-fe` проходит (ESLint + Prettier + tsc); `make test-fe` — зелёный (существующий набор не ломается).
- Новых ключей в `query-keys.ts` не появилось: rename/delete работают на существующих `projects.chats`, `projects.chat`, `chats.recent`.
- В `frontend/src` не осталось упоминаний `CreateChatRequest` и передачи `title` при создании чата (grep).

### T2.2: SSE-событие `title_updated` — патч кэша и fallback-инвалидация

**Цель:** принять новое не-терминальное событие стрима и обновить title в кэшах без рефетча открытого чата.

**Изменения:**

- `frontend/src/shared/api/sse.ts` — расширить union `SSEEvent` вариантом `{ type: "title_updated"; title: string }`.
- `frontend/src/pages/chat/model/useAgentStream.ts`:
  - новый `case "title_updated"` — **только `setQueryData`**, без `invalidateQueries`: патч поля `title` в `queryKeys.projects.chats(projectId)` (элемент списка по `thread_id`), `queryKeys.chats.recent` (элемент по `thread_id`) и `queryKeys.projects.chat(projectId, chatId)` (detail). Updater'ы возвращают `prev` как есть, если кэш-записи нет, — списки могут быть не смонтированы.
  - в `case "done"` — добавить fallback-инвалидацию `queryKeys.projects.chats(projectId)` с `exact: true` (случай «title не успел до конца рана»). `queryKeys.chats.recent` на `done` инвалидируется уже сейчас — дубль не добавлять.

**Verification:**

- `make check-fe`, `make test-fe` проходят.
- Событие обрабатывается без `invalidateQueries` по ключу открытого чата: мид-стрим оптимистичная копия user-сообщения в `localMessages` не задваивается (мотив ограничения — § Доставка title на фронт).
- Инвалидации по `projects.chats` — везде `exact: true`.
- Соответствие контракту брифа: событие не-терминальное, поток после него продолжается (обработка не выставляет `terminated`).

### T2.4: Анимация посимвольной печати auto-title

**Цель:** показать замену плейсхолдера сгенерированным названием печатью с кареткой — синхронно в шапке чата, списке чатов проекта и recents.

**Изменения:**

- Новый презентационный компонент в `frontend/src/shared/ui/` (например `TypedTitle.tsx`) — общая UI-композиция поверх примитивов, три хоста в разных слоях, поэтому место в `shared/ui` (граница shadcn / наше — § Граница shadcn в `shared/ui`). Контракт: `text` (актуальное значение из кэша) + `animateFrom` (значение, с которого печать запускается). Правило запуска ровно как в мокапе: анимируем **только** переход `animateFrom → новое значение`, то есть замену плейсхолдера; rename печать не запускает (в мокапе `applyTitle(..., flash=false)`). Принятый edge case (резолюция PLAN_REVIEW): rename чата, чей текущий title равен `DEFAULT_CHAT_TITLE`, формально тоже переход `animateFrom → новое` и печать запустит — безобидно и симметрично принятому в брифе edge case перегенерации title; событийную привязку триггера не строим. Компонент домен-нейтрален: плейсхолдер приходит пропом из хостов (`DEFAULT_CHAT_TITLE`), не импортируется внутрь.
- Тайминги и оформление — из мокапа: ~38 мс на символ, каретка 2px шириной с миганием `0.7s step-end`, цвет текста и каретки на время печати — `--primary`, возврат к обычному цвету через `transition: color .4s` спустя ~0.7 с после конца печати.
- `frontend/src/index.css` — keyframes каретки и её класс рядом с существующими кастомными анимациями, с блоком `@media (prefers-reduced-motion: reduce)` по образцу `gen-progress-indeterminate` / `thinking-dot-pulse`. Сам JS-таймер печати тоже уважает reduced-motion: при включённой настройке текст показывается сразу целиком.
- Подключение: `pages/chat/ui/ChatHeader.tsx` (название чата), `pages/project-chats/ui/ChatList.tsx` (заголовок строки), `app/components/Sidebar.tsx` (строка recents). Хардкод цветов запрещён — только токены/Tailwind-утилиты.

**Verification:**

- `make check-fe`, `make test-fe` проходят.
- Анимация — надстройка над кэшем: значение в кэше меняется атомарно в T2.2, компонент лишь отрисовывает переход; при размонтировании таймер очищается.
- Печать запускается при переходе «Новый чат» → сгенерированное название и не запускается при rename и при обычном рендере уже готового названия.
- В `dist/` нет хардкод-цветов и инлайн-hex у новых стилей (правило дизайн-токенов); при `prefers-reduced-motion: reduce` название появляется мгновенно.

## Cross-cutting
