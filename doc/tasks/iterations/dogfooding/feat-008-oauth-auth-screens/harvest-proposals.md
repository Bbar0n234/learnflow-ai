`## Follow-ups` треков T1/T2, `pre-existing`/`⏭ отложено`-находки `review-a.md`/`review-b.md` и
отложенные развилки `ADR-031`/`design-brief.md § Scope boundaries`. Каждый кандидат сверен с

архитектора на pre-commit gate.

## known-trivial

- **`.env.local` этого worktree не переопределяет `REDIS_URL` на localhost.** `make dev` доходит до `Application startup complete` с нефатальной Redis DNS-ошибкой (hostname docker-сети). Специфика конкретного worktree, не кода — учитывать при ручных прогонах, не чинить.
- **Порт 8000 занят docker-контейнером соседнего worktree** (`learnflow-ai-wt-feat-011-execution-runtime`, параллельная итерация). Verification треков шли на запасных портах (8010–8013), чужой контейнер не тронут — известная особенность параллельной разработки, не аномалия.

## Отсеяно как шум (с причиной)

- **Drift прод-топологии в design-brief feat-008** (диаграмма топологий рисует прод как «nginx → SPA-статика», фактически `app`-образ сам собирает и отдаёт SPA). Безвредно для итерации (маршрут `/login` переживает прямой заход без правок). Проверено на HEAD: `auth.md` эту неточность **не унаследовал** — топология там не переописывается, DOC_UPDATE (`2c7fec5`) сузил auth.md до флоу/cookie/эндпоинтов/кодов ошибок без диаграммы окружений. Сам бриф — read-only история итерации, не актуализируется. Закрыто, действие не требуется.
- **В dev-БД worktree остались артефакты стенда T2** (`user-a-t2`, проект «T2 stand»). Неактуально: `{T1.4}` снёс volume (`docker compose down -v`) и переналил БД с нуля перед финальным стендом — артефактов больше нет (подтверждено `test-cases.md {T1.4}`).
- **`GET /api/auth/providers` вне list-envelope** (review-b nit) — не хвост: DOC_UPDATE уже внёс норму-исключение в `doc/tech/conventions/api.md:42` («Исключение — capability-дескриптор... санкционировано design-brief итерации feat-008»). Landed, не кандидат.
- **Противоречие скоупа `doc/security/architecture.md`** (документ явно исключает auth/rate-limiting/RBAC из своего предмета, а бриф предписывал новую OAuth-поверхность) — решено фактически: DOC_UPDATE описал всю OAuth-поверхность в `auth.md`, `security/architecture.md` не тронут, вводный абзац документа («это обычная app-security») остался согласованным сам с собой. - **ADR-031 отсутствует** (находка review-b на момент ревью) — закрыто: ADR создан в рамках DOC_UPDATE (`2c7fec5`), файл `doc/tech/adr/ADR-031-oauth-identity-model.md` на HEAD.
