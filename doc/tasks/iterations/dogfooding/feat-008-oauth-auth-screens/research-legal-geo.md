# Политика доступности OAuth-провайдеров

Документ описывает выбор набора провайдеров по IP клиента и поведение при недоступной базе IP-метаданных. Контракт авторизации — в [design-brief.md](design-brief.md).

## Наборы провайдеров

Сервер определяет доступный набор по метаданным IP клиента:

- **Ограниченный набор:** Яндекс ID и пароль.
- **Полный набор:** Яндекс ID, Google, GitHub и пароль.

В ответ попадают только провайдеры с настроенными credentials. Если Яндекс ID не настроен, ограниченный набор содержит только парольный вход. VK ID не входит в реализованный состав.

## Серверная проверка

Политика применяется в трёх точках: выдача списка провайдеров, начало OAuth-флоу и callback. Скрытия кнопки в интерфейсе недостаточно: прямой запрос к недоступному провайдеру также отклоняется. Повторная проверка на callback учитывает смену IP между шагами.

IP берётся через `get_client_ip`, с учётом доверенной конфигурации reverse proxy. VPN меняет наблюдаемый адрес: политика применяется к адресу запроса, без предположений о пользователе.

## База IP-метаданных

Используется локальная MMDB-база IPinfo Lite и reader `maxminddb`. Reader открывается в lifespan и хранится в `app.state`. Поддерживаются плоское поле `country_code` и вложенное `country.iso_code` для совместимого формата GeoLite2.

Базу необходимо обновлять; атрибуция IPinfo указана в README проекта. Отдельный сетевой lookup при входе не требуется.

## Деградация и проверка

Если база не настроена, недоступна или повреждена, IP не разбирается либо lookup не находит запись, используется `GEOIP_FALLBACK_COUNTRY`. Его системное значение выбирает ограниченный набор: вход по паролю остаётся доступен, список OAuth-провайдеров не расширяется.

Конкретные ISO-коды остаются техническими значениями конфигурации и тестовых данных. Для проверки обоих наборов в dev используется `GEOIP_FALLBACK_COUNTRY`; настройки reverse proxy и `CLIENT_IP_SOURCE` должны соответствовать топологии стенда.

Проверяются оба набора, отсутствие credentials, недоступная и повреждённая база, lookup-промах, нормализация регистра fallback и смена IP между authorize и callback.
