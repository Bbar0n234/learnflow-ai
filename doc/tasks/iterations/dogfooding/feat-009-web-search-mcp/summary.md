# Summary: feat-009 — Web search MCP: замена Firecrawl на Jina AI

- `.env.example`: в секции «MCP External Tools» добавлен `JINA_API_KEY` первым, `FIRECRAWL_API_KEY` оставлен (fallback), `TAVILY_API_KEY` удалён.

- `backend/app/main.py:561`: комментарий про инструменты `web-research` актуализирован (`firecrawl_*` → `search_web/read_url`), код не менялся.

## Решения и обоснования

- **Механика `agent-tool-names.json`**: контракт — не файл ручного сопровождения, а артефакт `scripts/generate_tool_names_fixture.py`, тонкой обёртки над `app.agent.tools.registry.build_tool_name_fixture(agent_config)`; та же функция гоняется в `backend/tests/agent/test_tool_names_fixture.py` как drift-gate (`test_fixture_matches_generated_output`). Обновление — регенерация, не ручная правка. Регенерировал: `PYTHONPATH=backend uv run --package learnflow-backend python scripts/generate_tool_names_fixture.py`.
- **Находка**: `builtin_mcp_tool_names()` (registry.py) собирает `allowed_tools` со **всех** объявленных `mcp_servers`, независимо от `enabled` — по явному дизайну (докстринг: «any `enabled`... since it can be turned on elsewhere»). Поскольку бриф требует оставить `firecrawl` в конфиге как выключенный fallback (без изменения его `allowed_tools`), контракт после регенерации содержит **и** `firecrawl_search/scrape/extract`, **и** `search_web`/`read_url` — 5 записей `builtin_mcp` (было 5: 3 firecrawl + 2 tavily; теперь 3 firecrawl + 2 jina), а не «заменить три записи на две», как буквально сформулировано в брифе (§ п.2 сценария). Это не рассинхрон и не баг — прямое следствие того, что `firecrawl`-блок физически остаётся в `mcp_servers`. Обновил контракт каноническим способом (regen), результат отражает реальный `agent.yaml`; расхождение с формулировкой брифа фиксирую здесь, правку не делал, т.к. решение (оставить firecrawl предзаявленным, а не удалить блок) — уже архитектурное и стоит выше этой фазы.
- **Тесты со стенд-именами firecrawl**: часть упоминаний (`test_stream_events.py` и стриминг-контракты) — это произвольные имена tool-вызовов в фикстурах, никак не резолвящиеся через `configs/agent.yaml` (сам маппер токенов/контракт SSE не знает о реестре инструментов). Переименование туда — не обязательное с точки зрения корректности тестов, но убирает шум «мёртвого» имени инструмента из тестовой базы, как просил бриф (п.7).
- **`_fake_firecrawl_pool` → `_fake_search_pool`**: единственное место, где имена firecrawl были содержательны — пул реально резолвил инструменты `SubagentSpec` из `configs/agent.yaml` (docstring прямо говорил «all specs use the firecrawl trio»). Переименование обязательно, иначе тест резолвил бы несуществующие инструменты.

## Отклонения

- Контракт `agent-tool-names.json` после регенерации содержит 5 `builtin_mcp`-записей (`firecrawl_extract`, `firecrawl_scrape`, `firecrawl_search`, `read_url`, `search_web`), а не 2, как буквально написано в задаче фазы («заменить три firecrawl-записи на две»). Причина и обоснование — см. «Решения» выше; итог соответствует каноническому генератору и фактическому `configs/agent.yaml` (firecrawl остаётся объявленным, но `enabled: false`).
- Свежий `uv sync` (без `--all-packages`) в этом worktree один раз временно снёс backend/services-зависимости из общего `.venv` (root-проект не тянет их как свои deps) — исправлено повторным `uv sync --all-packages`. К изменениям кода/конфига не относится, упомянуто для прозрачности прогона проверок.
- `make test` — единственный красный тест, `backend/tests/agent/test_pricing_external.py::test_active_model_prices_within_drift_tolerance` (`@pytest.mark.external`), падает и на немодифицированной ветке (проверено через `git stash`) из-за дрейфа реальных цен провайдера моделей относительно `pricing.yaml` — не связано с этой итерацией, не чинил (вне scope, требует решения архитектора по `pricing.yaml`).
