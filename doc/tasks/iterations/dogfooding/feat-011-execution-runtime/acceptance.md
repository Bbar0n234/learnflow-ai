# Приёмка feat-011: сквозные сценарии архитектора

Верхнеуровневая приёмка в конце итерации: что агент **умеет** после реализации и что границы **держатся**. Каждый пункт проверяет контракт из design-brief/ADR-031/ADR-032. Прогон: блок A — руками в UI и/или Playwright-агентом; блок B — разовые команды (кандидаты в скрипт-чеклист и интеграционные автотесты); блок C — частично покрывается обычными автотестами. `test-author` при реализации разворачивает это в детальные `test-cases.md` и помечает, что ушло в автотесты.

Статус прогона: ☐ / ✅ / ❌ (+ дата, заметка).

**Прогон: 2026-08-12.** Блок **B** прогнан целиком заново на топологии с настоящим gVisor —
`EXECUTOR_RUNTIME=runsc`, контейнер executor'а под `runsc` (ядро джобы `4.19.0-gvisor`), песочница
включена (`GET /health` → `{"status":"ok","sandbox":"enabled"}`), джобы дёрганы через `POST /jobs`
изнутри сети `exec` с shared-secret'ом плюс живыми ходами агента (B6, B8, B9). Блоки **A** и **C** —
функциональные сценарии, для них рантайм джобы значения не имеет; их результаты перенесены из
второго захода INTEGRATION_TEST (`tracks/{T1,T2,T3}/test-cases.md`, Layer 2/3 и ручные хвосты),
прогнанного на топологии `runc`, — это помечено в каждой строке. Единственное исключение в блоке A —
хвост `A9` («скрипт скилла исполнен»), доснятый живым ходом уже на `runsc` после того, как в
`skills/gost-lab-report` появился первый скилл со скриптами.

Дополнительно к таблицам подтверждён shared-secret executor'а: `POST /jobs` без заголовка,
с неверным токеном и с токеном без схемы `Bearer` → **401** `invalid or missing executor auth token`
(все три ответа одинаковы, разницы «нет заголовка / не тот токен» вызывающий не видит), с верным —
обслуживается; `GET /health` открыт и отвечает 200 без авторизации.
