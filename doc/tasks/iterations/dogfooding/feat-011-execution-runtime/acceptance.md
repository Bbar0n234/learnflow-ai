# Приёмка feat-011: сквозные сценарии архитектора

Верхнеуровневая приёмка в конце итерации: что агент **умеет** после реализации и что границы **держатся**. Каждый пункт проверяет контракт из design-brief/ADR-031/ADR-032. Прогон: блок A — руками в UI и/или Playwright-агентом; блок B — разовые команды (кандидаты в скрипт-чеклист и интеграционные автотесты); блок C — частично покрывается обычными автотестами. `test-author` при реализации разворачивает это в детальные `test-cases.md` и помечает, что ушло в автотесты.

Статус прогона: ☐ / ✅ / ❌ (+ дата, заметка).

## A. Новые способности агента (как пользователь, через UI)

| # | Сценарий | Проверяемый контракт | Статус |
|---|----------|----------------------|--------|
| A1 | «Посчитай статистику по этому CSV» → агент пишет Python, исполняет, отвечает числами | `execute_code`, лента показывает вызов и результат | ☐ |
| A2 | «Какая версия pandoc в окружении?» → ответ из stdout | `run_command` | ☐ |
| A3 | «Сохрани конспект» → карточка артефакта вживую, файл открывается из списка | `write_file` → `artifacts/`, эмиссия `artifact_created` | ☐ |
| A4 | «Построй график matplotlib в png» → картинка-артефакт открывается | джоба → diff-снапшот → `artifact_created`; маппинг `png`→image-вьюер | ☐ |
| A5 | Артефакт в поддиректории (`lecture-1/slides.md`) открывается, list показывает дерево | id=путь, адресация query-параметром, вложенность | ☐ |
| A6 | «Поправь этот артефакт» → UI показывает новую версию, не старую; карточка/лента помечают обновление (бейдж «обновлён · +N −M») | `artifact_updated` с дельтой строк, перезапись по пути, ETag-ревалидация media | ☐ |
| A6b | Артефакт перезаписан **джобой** (скрипт правит существующий файл) → тот же бейдж; для текстового — дельта, для бинарного — без счётчиков | before-копия зоны в джобе → `artifact_updated`; бинарный/сверх лимита → `diff: null` | ☐ |
| A6c | Джоба удалила/переименовала файл → после завершения хода список артефактов без призрака; клик по исторической карточке удалённого файла → внятное «файл больше не существует» | инвалидация списка по завершении хода; состояние отсутствия во вьюере | ☐ |
| A7 | Новый чат того же проекта: «продолжи вчерашнюю работу» → агент видит и читает файлы | персистентный workspace, `list_files`/`read_file` | ☐ |
| A8 | Перезагрузка страницы / старый (пост-миграционный) чат → карточки артефактов на местах, кликаются | `ArtifactPart` из чекпоинта, рендер на уровне part | ☐ |
| A9 | Ход со скиллом: агент вызывает `load_skill`, мои заметки скилла учтены, скрипт скилла исполнен | `load_skill` поверх файлового слоя + skill-context из Store; `/skills` в executor | ☐ |
| A10 | Джоба падает (ошибка в коде) → агент читает stderr, чинит, доводит до результата | ошибки джобы = результат tool'а, thread живой | ☐ |
| A11 | Прикрепил `.md`-заметку + вопрос → агент прочитал и ответил по содержимому | вложения: upload при отправке, пометка в сообщении, `read_file` | ☐ |
| A12 | Прикрепил PDF → агент сам извлёк текст (job) и работал с ним | бинарный формат через executor (pandoc), ingestion = runtime | ☐ |
| A13 | Чип вложения виден в композере до отправки; убрал чип — ничего не загрузилось; после отправки чип у сообщения в истории (и после перезагрузки) | клиентский чип до send; metadata → UI-чип | ☐ |
| A14 | Вложение сверх лимита размера → понятная ошибка, отправка не ломается | `Settings`-лимит upload, ошибка в композере | ☐ |

## B. Изоляция и границы (как архитектор, команды)

| # | Сценарий | Проверяемый контракт | Статус |
|---|----------|----------------------|--------|
| B1 | `docker exec` в executor: в env нет `DATABASE_URL`/`JWT_SECRET`/LLM-ключей; env job-процесса scrubbed | секреты не достижимы | ☐ |
| B2 | Из джобы: коннект к `db:5432`, `redis:6379` → fail (нет DNS/маршрута) | exec-сеть, executor вне стековой сети | ☐ |
| B3 | Из джобы: `curl https://…`, `pip install …`, коннект к `app:8000` → fail | `internal: true` + пустой netns джобы (обёртка `unshare -n` вокруг bwrap): сокеты не создаются | ☐ |
| B4 | Из джобы: `import numpy, pandas, matplotlib`, `pandoc --version` → работают | толстый образ, тулчейн запечён | ☐ |
| B5 | `docker inspect`: runtime `runsc`; процесс в контейнере non-root | gVisor, non-root | ☐ |
| B6 | «Прочитай /etc/passwd» через `read_file` → отказ + security-лог `agent.runtime.path_denied` | двухкорневой резолв, канонизация | ☐ |
| B6b | Из джобы (`execute_code`/`run_command`) обращение к чужому workspace абсолютным путём (чтение и `rm`) → fail «не существует» | bwrap: mount-ns джобы = только свой workspace + тулчейн ro | ☐ |
| B6c | Из джобы запись в свой workspace (относительным путём и абсолютным внутри mount-ns) → успех | единый uid: владелец каталога = job uid (gVisor-требование, следствие спайка №2) | ☐ |
| B7 | Запись в `/skills` из джобы → fail | ro-mount | ☐ |
| B8 | Бесконечный цикл → джоба убита по deadline вместе с потомками, диагностика у агента, чат живой | deadline, kill-цепочка bwrap (killpg обёртки → `--die-with-parent` → коллапс pid-ns), `pids_limit` | ☐ |
| B9 | «Стоп» во время долгой джобы → ход остановлен, следующее сообщение работает (файлы-сироты допустимы) | отмена v1: сироты приняты | ☐ |
