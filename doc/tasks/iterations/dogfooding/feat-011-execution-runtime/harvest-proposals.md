## В конвенции

- **Маркеры фазы итерации (`T1.3`, `T1.6`, …) в докстрингах прод-кода гниют так же, как в документации.** CLAUDE.md уже запрещает временные метапометки итераций в архитектурных документах; тот же принцип стоит явно распространить на докстринги/комментарии в коде приложения. Несколько новых модулей этой итерации (`routes/artifacts.py`, `routes/uploads.py`, `agent/tools/files.py`, `agent/tools/execution.py`, `infra/executor.py`, `services/artifact_workspace.py`) несут пометки вида «(ADR-032, T1.6)» — номер фазы не глобален (`agent/subagents/runner.py` уже несёт T1.3/T1.5/T1.6 **другой** итерации), читатель не может разрешить ссылку без похода в git-историю. Предлагаемое правило: ссылаться на стабильный ADR/design-brief, номер фазы не писать. Явно предложено ревьюером B как «Кандидат в harvest как конвенция» (`review-b.md`, замечание по `checkpoint_history.py`/другим файлам).
- **Паттерн парного `chown` точки монтирования named volume в оба (все) образа, которые могут первыми её коснуться.** Обнаружено и закрыто дважды за итерацию (блокер T1.10→T1.11, решение архитектора) и отдельно закреплено в ADR-031: свежий именованный volume наследует владение той директории, что уже существует в образе на момент первого использования — если ни один образ не создаёт путь заранее, Docker монтирует `root:root`, и первая же запись под non-root uid падает (`Permission denied`/gVisor `EINVAL`), независимо от порядка старта контейнеров. Рабочий паттерн: `RUN mkdir -p <path> && chown <uid>:<gid> <path>` запечён в **каждый** образ, разделяющий volume, до `USER <uid>` — не полагаться на порядок старта compose или отдельный init-контейнер (последний явно отклонён архитектором как лишний элемент топологии). Кандидат-конвенция для любого будущего сервиса на общем named volume с фиксированным uid.
- **`uv sync --package <member>` сужает общий dev-venv монорепо — не забыть восстановить.** Запуск `uv sync --package X` в общем venv воркспейса (не в одноразовом build-слое Dockerfile) выгружает зависимости остальных членов workspace, ломая `make check`/импорты для них до следующего `uv sync --all-packages` (или простого `uv sync`). `conventions.md:124` уже документирует `--package` для сборки Docker-образов, но не предупреждает про этот локальный dev-капкан. Обнаружено в T3.1, когда `uv sync --package executor` временно уронил `mypy backend/` посреди трека.
- **Императивный вызов write-only API без хука кэша — формализовать исключение.** `conventions/frontend.md` требует «компоненты вызывают хуки, не API-функции напрямую», но `uploads.ts`'s `uploadFile` дёргается из трёх компонентов напрямую (кэшировать нечего, эндпоинт только POST) — тот же паттерн уже был у `downloadArtifact`. Ревьюер B зафиксировал разрыв между буквой конвенции и уже принятым паттерном; предложение — либо тонкий `useUploadFile`-wrapper для единообразия, либо явное документированное исключение «императивный некэшируемый write-вызов».
