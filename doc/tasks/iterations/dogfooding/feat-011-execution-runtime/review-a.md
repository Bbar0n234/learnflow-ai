Общее впечатление: код высокого качества — граница путей построена как один барьер с двухслойной защитой и security-логом на каждый отказ, kill-контракт исполнителя (`start_new_session` + `--die-with-parent` + pid-namespace) документирован и проверен реальными процессами, `_PipeReader` честно решает задачу «не буферизовать, но и не блокировать писателя», sanitize-and-continue для unicode-хита сделан с повторной проверкой (payload не покупает себе проход через BOM). ### Что проверено и претензий не вызвало

- Kill-контракт и `_PipeReader`/`_drain` (`services/executor/executor/runner.py`): деградация капчи и таймаут видимы в самом выводе, `output_incomplete`/`stdout_truncated` попадают в лог, ERROR зарезервирован строго под «не смогли запустить».
- `build_job_argv` (`sandbox.py:104-176`): порядок `--tmpfs /tmp` → `extra_ro_binds` объяснён и корректен; отсутствующие пути `/etc` пропускаются, а не роняют префикс.
- Sanitize-and-continue для unicode (`tool_guards.py:184-200`): повторная проверка после очистки закрывает обход классификатора через BOM; редакция сохраняется для всех прочих детекторов.
- `resolve_path`/`resolve_artifact_path`: «оба корня проверяются против одного и того же канонизированного кандидата» — симлинк наружу не переезжает молча на skills-корень; выход из зоны `artifacts/` отказывается так же, как выход из workspace.
- Тесты треков (`services/executor/tests/**`, `backend/tests/workspace/**`, `backend/tests/projects/test_artifacts_api.py`, `test_uploads_api.py`): ассерты содержательные, границы (ровно лимит / за лимитом, 304 после перезаписи, non-ASCII в `Content-Disposition`) покрыты, фейк executor'а воспроизводит побочные эффекты джобы, а не только возврат.
