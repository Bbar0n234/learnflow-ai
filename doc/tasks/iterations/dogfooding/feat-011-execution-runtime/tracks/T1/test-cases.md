# Test Cases: feat-011 — Execution runtime / трек T1 (backend)

Трек перевёл backend на файловую модель: у проекта появился workspace на диске, артефакт стал файлом
с путём вместо строки в PostgreSQL, агент получил пять новых инструментов (три файловых и два
исполняющих код в соседнем сервисе), а пользователь — вложения. Почти всё это новое поведение, и
почти всё оно проходит через один модуль — файловый слой, который решает, какой путь чего может
касаться. Поэтому центр тяжести набора там: больше половины кейсов — про отказ, а не про успех.

Регрессировать здесь есть чему в двух местах. Первое — история чата: связь «артефакт ↝ сообщение»
переехала с PG-колонки на typed part чекпоинта, и если она поедет, старые чаты потеряют карточки
молча, без единой ошибки. Второе — граница «ошибка джобы против отказа инфраструктуры»: и то и
другое возвращается агенту текстом, но читаться должно по-разному, иначе агент будет чинить код в
ответ на упавший executor. Оба закрыты автотестами. Живая связка с executor'ом, изоляция bwrap и
всё, что видно только в браузере, в этот трек не входят — они в T2/T3 и в INTEGRATION_TEST.

## Конвенции прохождения (инлайн — это рамка тестировщика)

**Статус и run-log.** У каждого кейса — текущий статус плюс опциональный run-log, если кейс прогонялся не раз:

- `- [x]` + лаконичный результат: что проверялось, что получилось, значимые нюансы. По заполненному чек-листу должно быть видно, что всё работает, без перепрохождения.
- `- [ ] ⚠️` + причина, если кейс не пройден или требует отдельного внимания.
- Кейсы с 👤 — требуют ручного действия / решения архитектора (UI, браузер, прод-VM); тестировщик помечает и эскалирует.
- **Доменные маркеры**: `📊` — проверка наблюдаемости (структура БД, JSON-логи, SIEM-поток, Langfuse); `🔴` — проверка границы изоляции / отказа по безопасности; `[auto]` — кейс закрыт автотестом; `*(регресс)*` — кейс страхует «поведение не сломалось».
- **run-log** (только у перепрогнанных кейсов) — строка-история флипов с причиной:
  `runs: r1 ✅ → r2 ❌ (после фикса review #3) → r3 ✅`. Один прогон — run-log не нужен.

**Ре-верификация.** Правка кода аннулирует прошлый зелёный статус затронутого. После фиксов: детерминированный гейт (`make check`, `make test`) — перепрогон всегда; ручные кейсы — перепрогон затронутой области. Каждый перепрогон → запись в run-log.

**Диагностика — через наблюдаемость, не догадки.** Один кейс — одна попытка диагностики: не сошлось — повтори (мог быть транзиент); не сошлось второй раз — fail + эскалация, без долгой отладки. Инструменты: structlog (JSON stdout backend'а), поток security-событий siem-service, состояние БД (`psql`), содержимое тома `workspaces` (`docker compose exec app ls /workspaces/...`), Langfuse traces, DevTools → Network для SSE-кадров. Код тестировщик не правит: прод-баги, вскрытые кейсом, чинит **fixer**, не сам тестировщик.

**Скоуп по трекам.** Кейсы с префиксом `{T1.x}` гоняются на треке T1 (нужны БД и собранный образ backend'а, executor не нужен) + Layer 0; cross-cutting без префикса — в INTEGRATION_TEST на живой топологии. Не пропускать кейсы молча — неприменимый помечать причиной.

### Процесс (тестировщик поднимает стенд сам)

1. Трековые кейсы: `make docker-up-db` (Postgres + Redis), `make migrate`, backend `make dev`. Executor для `{T1.x}` не нужен — все кейсы трека либо не трогают исполнение кода, либо проверяют именно поведение при недоступном executor'е.
2. Актор — обычный пользователь через `/api/auth/register` (или UI): **user-a** с одним проектом и парой чатов.
3. Прогон сверху вниз; каждый failed-кейс — повторная попытка, затем фиксация в run-log + `## Решения и обоснования` summary трека.
4. После прогона — сводка (pass / failed / **deferred**). Deferred — кейсы 👤/заблокированные (нет runsc, нет прод-VM): отдельным счётчиком + причина по каждому.

## Дизайн автотестов

**Покрываем автотестом** — 183 новых кейса: 165 в восьми новых суитах и 18 достройками к семи
существующим. Все они гоняются `make test` и не требуют ни executor'а, ни сети. Общий харнесс новых
файловых суит — `backend/tests/workspace/conftest.py`: два корня под `tmp_path` (workspace-корень и
`skills`) и фабрика `Workspace` с настраиваемыми лимитами (чтобы дотянуться до веток усечения и
oversized-дельты, не записывая мегабайты). Сами билдеры, из которых собраны эти фикстуры
(`build_workspace`, duck-typed `ToolRuntime` с `project_id` — тот самый параметр, которого у
инструментов нет и который агент не может назвать сам, `write_file`, идентификаторы проектов), лежат
в `learnflow_testing.workspace`: один и тот же файловый слой гоняют три скоупа (workspace, вход
субагента, генерация картинок), а общие тест-утилиты живут в `packages/testing`, а не в conftest'е
одного из скоупов. Оттуда же берутся фабрики (`ProjectFactory`/`UserFactory`) и SSE-хелперы там, где
суита поднимает ASGI-клиент; собственных фейков БД и модели трек не заводит.

Файловая система в этих суитах **настоящая** (`tmp_path`), а не подменённая: предмет теста —
решение о том, что этому пути можно, и фейк ФС фальсифицировал бы ровно его. Дублируется одна
граница — executor: его HTTP-клиент тестируется через `httpx.MockTransport`, а инструменты — через
подмену `run_job` фейком, который *ещё и пишет файлы*, как это делает реальная джоба, — иначе
ассерты про diff-снапшот проверяли бы возвращаемое значение мока, а не наблюдение за ФС.

### `test_workspace.py` — файловый слой (границы путей, запись, снапшот)

1. **Файл**: `backend/tests/workspace/test_workspace.py` — solitary-unit на реальной ФС (`tmp_path`), без дублей
2. **Тестирует**: `app.storage.workspace :: Workspace`, `WorkspacePathError` и модульные хелперы (`to_artifact_path`, `artifact_type`, `sanitize_filename`, `unique_path`, `extension_from_mime`, `resolve_under_root`)
3. **Суть**: Суита проверяет барьер, на котором держится вся безопасность файловой части итерации: путь канонизируется до касания диска и обязан остаться внутри одного из двух разрешённых корней, причём в `/skills` можно только читать. Она страхует четыре класса обхода — относительный traversal, абсолютный путь мимо корней, путь в чужой проект и символическую ссылку, уводящую наружу, — и отдельно фиксирует, что каждый отказ оставляет security-лог `agent.runtime.path_denied`: кроме этой записи, попытка выхода не оставляет вообще никаких следов. Вторая половина суиты — обычные файловые контракты, на которых стоят инструменты и REST: чтение с потолком и пометкой усечения, отказ отдавать бинарь текстом, атомарная запись, которая не оставляет мусора и сама различает создание и перезапись со счётчиками строк, листинг, скрывающий служебные файлы слоя, и снапшот зоны `artifacts/`, из которого рождаются события артефактов. Лимиты дельты проверяются с обеих сторон — и per-file, и суммарный на джобу: без них перезапись большого файла молча съедала бы память процесса.
4. **Кейсы** (65): относительный путь резолвится в свой workspace; `..`, остающийся внутри, — нормальный путь, не отказ; traversal / абсолютный путь / чужой проект / глубокий traversal → отказ (parametrize); отказ пишет `agent.runtime.path_denied` с `security_event`, путём и причиной; чтение по символической ссылке наружу и в чужой проект не возвращает содержимое; запись по такой ссылке отказана, файл-цель не изменён; абсолютный путь в `skills` читается; запись в `skills` → отказ с причиной `write_to_readonly_root` + лог; `resolve_skill_path` за пределы корня → отказ; `resolve_under_root` внутрь / наружу; чтение в пределах лимита и с усечением; бинарь → `content=None`; отсутствующий файл → `FileNotFoundError`; запись создаёт родительские директории и сам workspace лениво; перезапись даёт `updated` + `{added, removed}`; перезапись бинаря → `updated` без счётчиков; после записи не остаётся tmp-файла; `write_bytes` кладёт точные байты; листинг плоский и рекурсивный с признаком директории; tmp-файлы скрыты; несуществующая директория → пустой список; файл вместо директории → `NotADirectoryError`; листинг за пределами корней → отказ; diff: новый файл → `created` без дельты, переписанный текст → счётчики, нетронутый файл в diff не попадает, бинарь → `null`, файл сверх per-file лимита → `null`, файл, перебравший суммарный лимит джобы, → `null`; tmp-файлы не попадают в снапшот; снапшот проекта без `artifacts/` пуст; `delete_project` сносит дерево и не падает на проекте без директории; хелперы — зона `artifacts/`, расширение, санитайз имени (traversal, windows-путь, кириллица, control-символы, фолбэк), числовой суффикс коллизии, mime→расширение (все parametrize).

### `test_file_tools.py` — файловые инструменты агента

1. **Файл**: `backend/tests/workspace/test_file_tools.py` — unit, реальный `Workspace` + duck-typed `ToolRuntime`
2. **Тестирует**: `app.agent.tools.files :: make_file_tools` (`read_file`/`write_file`/`list_files`)
3. **Суть**: Суита фиксирует, что инструменты переводят любую файловую реальность — отказ резолва, отсутствующий файл, директорию вместо файла, бинарь — в *строку, которую модель может прочитать и исправить*, а не в исключение: исключение доехало бы до generic-обработчика графа и выглядело бы для агента как поломка инструмента, а не как его собственная ошибка в пути. Отдельно она страхует главное решение `write_file`: артефакт рождается не потому, что вызвали особый инструмент, а потому, что путь попал в зону `artifacts/` — и вместе с ним едет признак created/updated и дельта строк, из которых фронт рисует бейдж. Вызов без `AgentContext` обязан падать: `project_id` брать неоткуда, и «тихий дефолт» здесь означал бы запись в чужой или несуществующий проект.
4. **Кейсы** (23): чтение файла (в т.ч. кириллица); усечение с пометкой; чтение файла скилла; отказ на трёх классах запрещённых путей (parametrize) — строкой, не исключением; отсутствующий файл; директория; бинарь → «use media endpoint»; вызов без контекста → `RuntimeError`; запись в `artifacts/` → конверт `path`/`title`/`type`/`kind=created` и файл на диске; вложенный путь даёт идентичность относительно `artifacts/`; перезапись → `updated` + дельта; запись вне `artifacts/` → артефакта нет, файл записан; запись по запрещённому пути → ошибка-строка и пустой список артефактов; запись в библиотеку скиллов отказана, файл скилла не изменён; листинг с суффиксом `/` у директорий, рекурсивный листинг, скрытие скретч-файлов, пустая директория, отказ, файл вместо директории.

### `test_execution_tools.py` — `run_command` / `execute_code`

1. **Файл**: `backend/tests/workspace/test_execution_tools.py` — sociable-unit; executor заменён фейком на шве `run_job`, workspace настоящий
2. **Тестирует**: `app.agent.tools.execution :: make_execution_tools`
3. **Суть**: Суита разделяет три исхода, которые агент обязан читать по-разному. Джоба, которая отработала — хоть с ненулевым кодом возврата, — это обычный результат со stdout/stderr: агент читает ошибку и чинит свой код, поэтому исключения здесь быть не должно. Недоступный executor — наоборот, инфраструктурный отказ, и он получает собственную формулировку, чтобы агент не ушёл переписывать код, который ни разу не запускался. Третье — файлы: то, что джоба написала в `artifacts/`, backend узнаёт сам, сравнивая снапшоты зоны до и после, и превращает в тот же конверт, что даёт `write_file`; executor об этом ничего не сообщает и сообщать не должен. Фейк джобы поэтому реально пишет файлы — иначе кейсы про снапшот проверяли бы сами себя. Отдельная линия — скретч-файл `execute_code`: он живёт в workspace, адресуется относительным путём (абсолютного backend-пути внутри mount-namespace джобы не существует), не виден агенту ни в листинге, ни в артефактах, и удаляется даже когда джоба не запустилась.
4. **Кейсы** (18): результат несёт команду, `exit_code`, stdout и stderr; в джобу уходят команда и deadline из `Settings`; ненулевой exit — результат, не исключение; вывод сверх лимита усечён с пометкой; недоступный executor → in-band текст про инфраструктуру и пустой список артефактов; вызов без контекста → `RuntimeError`; файл, созданный джобой в `artifacts/`, → `created`; переписанный — `updated` + дельта; N файлов одного вызова → N элементов конверта; файл вне `artifacts/` артефактом не становится; директория workspace создаётся backend'ом до старта джобы (требование единого uid); `execute_code` запускает скретч относительным путём `python <tmp>.py`; исходник действительно читается джобой; скретч удаляется после успеха и после отказа executor'а; имя скретча не показывается агенту; скретч не попадает в артефакты; вызов без контекста → `RuntimeError`.

### `test_executor_client.py` — HTTP-клиент executor'а

1. **Файл**: `backend/tests/workspace/test_executor_client.py` — unit, шов `httpx.MockTransport`
2. **Тестирует**: `app.infra.executor :: run_job`, `ExecutorUnavailableError`
3. **Суть**: Суита закрепляет межтрековый контракт с T3 со стороны заказчика — адрес, тело `{project_id, cmd, timeout}` и разбор ответа — и, главное, границу «что считать недоступностью». Транспортный отказ (connect refused, таймаут клиента) обязан стать `ExecutorUnavailableError`, который обвязка переводит в понятный агенту текст; ответ 4xx/5xx — наоборот, признак того, что мы собрали неверный запрос, и он должен всплыть обычным исключением, а не спрятаться под «сервис недоступен», иначе баг в нашем коде выглядел бы как перебой инфраструктуры. Клиентский таймаут проверяется отдельно и с конкретным числом: он обязан быть больше deadline джобы на настроенный запас, потому что ответ на убитую по таймауту джобу приходит только после kill-grace executor'а — с меньшим запасом каждый честный таймаут джобы превращался бы в ложную «недоступность».
4. **Кейсы** (7): POST на `{base_url}/jobs` с телом контракта, ответ разобран в `JobResult`; клиентский таймаут = deadline + запас; три класса транспортных отказов → `ExecutorUnavailableError` (parametrize); недоступность логируется WARNING с `project_id`; HTTP 500 → `httpx.HTTPStatusError` наружу.

### `test_artifacts_api.py` — REST артефактов на путях

1. **Файл**: `backend/tests/projects/test_artifacts_api.py` — integration, ASGI-клиент поверх реального приложения; ownership на реальном Postgres, файлы на временном корне через `app.state.workspace`
2. **Тестирует**: `app.api.routes.artifacts` (list/detail/media/download), `app.services.artifact_workspace :: ArtifactWorkspaceService`
3. **Суть**: Суита проверяет переезд адресации: артефакт опознаётся путём в query-параметре, один и тот же роут отвечает и списком (параметра нет), и деталью (параметр есть), а вложенность держится штатно — сегмент URL слэши не пережил бы. Три ответа на путь разведены явно: файл есть (200), путь валиден, но файла нет (404), путь уводит за пределы workspace (422 problem+json) — последнее отличает злонамеренный запрос от обычного промаха и не даёт им слиться в один невнятный код. Отдельная линия — кэш `media`: идентичность теперь перезаписываемая, поэтому ответ обязан ревалидироваться (ETag + `no-cache`), а не кэшироваться навсегда, как это делал immutable-ответ на UUID-блоб; кейс с перезаписью файла показывает, что тот же запрос после изменения отдаёт новую версию, а не 304.
4. **Кейсы** (25): пустой список у проекта без файлов; список с вложенными путями, отсортированный по `updated_at` вниз; пагинация и envelope `{items,total,limit,offset}`; чужой проект → 404 на list и на всех трёх читающих роутах — detail/media/download (parametrize), причём файл в чужом workspace реально существует, иначе 404 доказывал бы только пустоту; detail текстового файла с содержимым и метаданными; detail бинарного — без ключа `content`; кириллический путь переживает круговой рейс через `?path=` и возвращается байт в байт в `path`/`title`; отсутствующий путь → 404; traversal → 422 + `urn:learnflow:invalid-path` (parametrize); абсолютный путь ничего не читает с хоста; detail/media/download не отдают файлы за пределами зоны `artifacts/` (parametrize; закрывают прод-баг №1); media отдаёт байты с ETag/Last-Modified/`no-cache`/`nosniff`; повторный запрос с тем же ETag → 304 без тела; после перезаписи файла тот же ETag → 200 с новым содержимым; media отсутствующего файла → 404; download отдаёт вложение с корректным именем и `text/markdown`; кириллическое имя уезжает в `Content-Disposition` как `filename*=UTF-8''`; download отсутствующего → 404; `format=pdf` больше не существует как ветка (параметр игнорируется, PDF не отдаётся).

### `test_uploads_api.py` — загрузка вложений

1. **Файл**: `backend/tests/projects/test_uploads_api.py` — integration, ASGI-клиент, реальный Postgres для ownership, реальный workspace
2. **Тестирует**: `app.api.routes.uploads :: upload_file`, `app.services.upload_workspace :: UploadWorkspaceService`
3. **Суть**: Единственный write-эндпоинт файловой модели принимает две вещи, которыми управляет клиент, — имя и размер, — и суита проверяет обе.   остальные 17 кейсов суиты остаются зелёными. То есть фикс нельзя сдать, не сняв маркер, и он не
  ломает соседей. Симуляция откачена.
- Минорное наблюдение автора про symlink подтверждено чтением кода: `resolve_path` пересобирает
  кандидата от `skills_root` из **исходной** строки (`app/storage/workspace.py:205-215`), поэтому
  ссылка наружу даёт несуществующий путь под `/skills` и `FileNotFoundError` вместо `path_denied`.
  Тесты ассертят инвариант («содержимое не возвращается»), а не формулировку, — честный фикс их не
  покрасит.
- Инфра по слою: Postgres поднимается только под REST-интеграцией и repository-суитами; новые
  файловые суиты — `unit` на настоящей ФС в `tmp_path`, без БД и сети; фейкуется одна граница
  (executor) на двух швах (`run_job`, `httpx.MockTransport`).
- Флака не нашёл: ни `sleep`, ни сети, ни общего состояния между тестами; все diff-кейсы меняют
  размер файла, поэтому не опираются на гранулярность mtime; monkeypatch'и модульных атрибутов
  восстанавливаются.
- Граница unit/eval соблюдена: ни одного ассерта на содержательное качество ответа модели.
- Целостность (A6): все удаления в диффе задокументированы в `summary.md` (таблицы T1.2/T1.6/T1.7/
  T1.9), включая два найденных вне списка файлов плана; ни один сохранившийся ассерт не ослаблен —
  `test_stream_events.py` наоборот стал строже (`assert "kind" not in envelope["data"]`).
  Переименования `search_web`/`read_url` → `firecrawl_*` в чужих суитах — дрейф-фикс под уже
  закоммиченный `configs/agent.yaml`, покрытие не снижают.
- База воспроизведена локально: `backend/tests` → **1158 passed, 3 xfailed**, единственный красный —
  внешний `test_pricing_external.py`. Дерево после ревью чистое (мутаций не осталось).
