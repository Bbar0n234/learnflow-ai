# Implementation Plan: feat-011 / трек T2 — Frontend: файловая модель артефактов и вложения

## Контекст

Трек переучивает фронт на файловую модель: артефакт больше не строка в PostgreSQL с UUID, а файл в `artifacts/` проекта, чья идентичность — путь. Отсюда всё остальное: REST адресуется query-параметром `?path=`, карточка артефакта в чате рождается из новой части истории `ArtifactPart` (а не из `message.artifacts`), перезапись файла показывается бейджем «обновлён · +N −M», категорию вьюера определяет расширение, а список артефактов становится деревом. Вместе с этим приезжает вход файлов от пользователя — вложения в композере (поглощённая feat-004).

Источники: [design-brief.md](../../design-brief.md) (§ Артефакты: переезд из PostgreSQL в workspace, § Инструменты агента, § Вложения пользователя, § Партиция треков — границы T2 и межтрековые контракты 1 и 3), [ADR-032](../../../../../../tech/adr/ADR-032-project-workspace-file-model.md), [acceptance.md](../../acceptance.md) (блок A: A3–A8, A11–A14; C3), утверждённый мокап [mockups/attachments-artifacts.html](../../mockups/attachments-artifacts.html) — референс UI для всех визуальных фаз (чипы вложений, бейдж обновления, дерево артефактов), текущее состояние — [frontend.md](../../../../../../tech/frontend.md), [streaming.md](../../../../../../tech/streaming.md), конвенции — [conventions/frontend.md](../../../../../../tech/conventions/frontend.md).

**Границы трека:** только `frontend/**`. Бэкенд-контракты (SSE `artifact_updated`, `ArtifactPart`, path-query REST, `POST /uploads`) зафиксированы брифом — фронт реализуется против контракта, а не против живого бэкенда (тот пишет параллельный трек T1); расхождения ловит INTEGRATION_TEST. Фикстуру `backend/contracts/agent-tool-names.json` трек **не правит** — она чужого скоупа (T1).

Автотесты трека пишет `test-author` отдельно. Implementer в каждой фазе обязан лишь оставить существующие co-located тесты зелёными (привести к новым сигнатурам), не расширяя покрытие.

## Фазы

### T2.1: API-слой артефактов — путь вместо UUID

**Цель:** `shared/api/artifacts.ts` и фабрика ключей адресуют артефакт путём и ходят в path-query эндпоинты.

**Изменения:**

- `shared/api/artifacts.ts` — DTO по § Артефакты брифа: `Artifact {path, title, type, updated_at}`, `ArtifactDetail {path, title, type, updated_at, content?}` (`content` отсутствует у бинарного файла; `thread_id`/`message_id` уходят вместе с PG-маппингом). Все четыре вызова (list, detail, media, download) — `params: { path }` вместо сегмента URL; `path` не втыкается в строку URL руками, кодирование оставляем axios.
- `downloadArtifact` теряет параметр `format` — `download?format=pdf` не переносится (§ REST, C3); фолбэк имени файла при отсутствии `Content-Disposition` — basename пути, а не `artifact.md`.
- Предикат 404 обобщается с media на detail (`isArtifactNotFound`): вьюеру нужно отличать «файла больше нет» и «блоба нет» от сетевой/5xx-ошибки (используется в T2.2).
- `useArtifactMedia` теряет `staleTime: Infinity` и комментарий об иммутабельности: путь-идентичность перезаписываема (§ Кэш media). Свежесть держат инвалидация по SSE (T2.4) и ETag-ревалидация браузера; дедупликация «карточка ленты ↔ вьюер» на одном ключе сохраняется.
- `shared/api/query-keys.ts` — `artifact(projectId, path)` / `artifactMedia(projectId, path)`: путь как элемент ключа, иерархия «media — потомок artifact» сохраняется (префиксная инвалидация пути задевает и media).
- `shared/api/artifacts.test.ts` — привести к новым сигнатурам.

**Verification:**

- `make check-fe`, `make test-fe` проходят.
- Запросы уходят с `?path=…`; вложенный путь (`lecture-1/slides.md`) не коллидирует по ключу с корневым (`slides.md`).

### T2.2: Маршрут вьюера на `?path=`, категория по расширению, снятие PDF-кнопки

**Цель:** артефакт любой вложенности открывается по query-параметру, вид вьюера выбирает словарь расширений, а не семантический `type`.

**Изменения:**

- `app/router.tsx` — вложенный маршрут `artifacts/:aid` снимается: React-роут не матчит слэши в сегменте (§ Адресация REST). Вьюер живёт на `projects/:id/artifacts` и выбирается по `?path=`; пустое состояние «Выберите артефакт из списка» остаётся, когда параметра нет.
- `pages/artifacts/ui/ArtifactsPage.tsx` — вместо `Outlet` читает `useSearchParams` и рендерит вьюер/пустое состояние (сплит-раскладка 318px + вьюер не меняется).
- Новый словарь «расширение → категория вьюера» — **`shared/lib/artifact-category.ts`** (потребители — три слайса: вьюер, список, карточка чата; размещение в `pages/artifact` дало бы запрещённый FSD кросс-импорт pages→pages). Категории: `md` → markdown; `png|jpg|jpeg|webp|gif` → image; **нераспознанное расширение с `content` в detail → text** (моно-рендер содержимого: `.txt`/`.csv`/`.py`/`.json` — штатный выход `write_file`/джобы, A1); без `content` → binary (метаданные + скачивание). Ветка `type === "image"` уходит отсюда и из `ArtifactCard` (T2.5), и из иконок списка (T2.3) — словарь один на все три места.
- `pages/artifact/ui/ArtifactView.tsx` — диспетчер по категории; кнопка `.pdf` снимается (C3), `.md` качает по пути; метаданные в шапке — `type` + `updated_at` («изменён …», мокап блок 3); бинарный файл без `content` показывает метаданные и скачивание, а не «Содержимое недоступно» как ошибку.
- Состояние «файл больше не существует» (A6c): 404 detail (и media) → явное объяснение с путём — файл переименован/удалён агентом, ссылка истории устарела. Не голая красная ошибка загрузки; сетевая/5xx-ошибка остаётся отдельной веткой.
- `pages/artifact/ui/ImageViewer.tsx` — caption-полоса и `alt` из `content` (промпт) снимаются: у `generate_image` отдельной колонки промпта больше нет (§ generate_image), detail бинарного `content` не отдаёт; заголовок/дата/зум/скачивание остаются.

**Verification:**

- `make check-fe`, `make test-fe` проходят.
- A5: `lecture-1/slides.md` открывается по ссылке со слэшем, адрес читаемый, перезагрузка страницы вьюер сохраняет.
- A6c: путь, которого больше нет, даёт внятное состояние во вьюере.
- C3: `.pdf`-кнопки во вьюере нет; в коде не осталось вызовов `downloadArtifact(..., "pdf")`.

### T2.4: SSE — `artifact_created` по пути, новое `artifact_updated`, инвалидации

**Цель:** фронт понимает оба события файлового слоя и держит кэши свежими без live-рендера карточки.

**Изменения:**

- `shared/api/sse.ts` — `artifact_created {path, title, artifact_type}` (было `id`), новый тип `artifact_updated {path, title, artifact_type, diff}` (`diff` — счётчики строк, `null` для бинарного и для превышения лимитов); оба имени в `KNOWN_SSE_EVENT_TYPES`. Форма `diff` — см. Open Questions.
- `pages/chat/model/useAgentStream.ts` — оба события точечно инвалидируют ключ пути (`queryKeys.projects.artifact(projectId, path)` — префикс задевает media, § Кэш media) и список артефактов **с `exact: true`** (без него префиксная инвалидация списка сносила бы все detail/media, обнуляя смысл точечной; прецедент точности — инвалидация `chats`). Завершение хода дополнительно инвалидирует список на **всех терминальных ветках** (`done` / `cancelled` / `error`): событий удаления/переименования в контракте нет, а после «Стоп» отменённая джоба оставляет сирот (A6c, B9, § Идентификатор = путь).
- Модель ленты (`shared/lib/agent-feed.ts`) **не трогается**: событие артефакта ленты не касается, редьюсер возвращает то же состояние и подписчиков не будит (конвенция § Состояние стрима). Карточка в живом ходе не рисуется — она приезжает из истории по завершении хода (осознанное решение брифа, live-рендер — backlog).

**Verification:**

- `make check-fe`, `make test-fe` проходят.
- A6: после перезаписи артефакта вьюер/миниатюра показывают новую версию, не старую.
- A6c: после хода, где файл удалён или переименован, список открывается без призрака.
- Forward-compat не нарушен: неизвестный `type` по-прежнему логируется и пропускается.

**Цель:** артефакты чата рендерятся на уровне части хода, а не из `message.artifacts`; перезапись видна бейджем.

Имя поля типа файла внутри части — см. Open Questions (конфликт с дискриминатором `type` union'а).
- `shared/lib/agent-feed.ts` — `ArtifactFeedItem` + ветка в `fromMessageParts`; `groupFeedBlocks` получает третий вид блока: карточка идёт отдельным элементом в порядке parts (мокап блок 1 — карточка после блока текста), строкой ленты активности она не становится. `applyStreamEvent` артефактных веток не получает (см. T2.4).
- `pages/chat/ui/MessageItem.tsx` — карточки рендерятся из блоков; `message.artifacts.map` снимается.
- `pages/chat/ui/ArtifactCard.tsx` — пропсы по пути; ссылка на `?path=`; подпись под заголовком — путь относительно `artifacts/` (мокап); бейдж «обновлён · +N −M» при `kind === "updated"` (вариант A мокапа, утверждён брифом), при `diff: null` — бейдж без счётчиков; превью-миниатюра выбирается категорией из словаря T2.2.

### T2.8: Вложения — композер

**Цель:** прикрепление файла до отправки, загрузка ровно в момент отправки, внятная ошибка лимита.

**Изменения:**

- `pages/chat/ui/ChatInput.tsx` — скрепка + скрытый `<input type="file" multiple>`, drag&drop с оверлеем «Отпустите, чтобы прикрепить», ряд чипов над полем ввода (имя, размер, ✕), полоса прогресса на чипах во время загрузки. Чип до отправки **чисто клиентский**: файл живёт в состоянии композера, ✕ выбрасывает его — сервер не участвует (§ Тайминг). Отправка допустима при пустом тексте, если есть вложения.
- `pages/chat/ui/ChatThread.tsx` — `handleSend` загружает файлы (`uploadFile` на каждый), получает пути и только потом зовёт `send(text, paths)`; оптимистичная копия user-сообщения несёт `attachments`, чтобы чипы были видны сразу; на ошибке загрузки сообщение не уходит, чипы остаются, текст не теряется.
- Ошибка лимита размера — inline под композером (не тост, по образцу add-time блока форм): пользователь убирает файл и отправляет снова. Источник текста — ответ сервера через `shared/lib/api-error` (env-лимит на фронте не дублируем — см. Open Questions).
- Draft-композер (`/chats/new`) и поле первого сообщения на странице проекта **тоже получают скрепку** (решение архитектора, Open Question 6): upload идёт в проект (project_id известен), через router state в создающийся чат едут уже пути-строки; UX идентичен композеру существующего чата. Конкретные файлы: `pages/chat/ui/ChatDraft.tsx` (draft-композер) и `pages/project-chats/ui/ChatList.tsx` (поле первого сообщения — там сырой `Textarea` со своей кнопкой, не `ChatInput`); router state расширяется до `{initialMessage, attachments}`, авто-отправка `initialMessage` в `ChatThread` зовёт `send(content, attachments)`. Выносить ли композер в общий компонент — решение implementer'а (переиспользование предпочтительно, принудительный рефакторинг не обязателен; зафиксировать в summary).

**Verification:**

- `make check-fe`, `make test-fe` проходят.
- A13: чип виден до отправки; ✕ до отправки не порождает ни одного запроса; после отправки чип у сообщения в истории.
- A14: файл сверх лимита даёт понятную ошибку в композере, ввод и остальные вложения не ломаются.
- A11/A12: отправленный `.md`/PDF доезжает до агента как путь — проверяется живой связкой на INTEGRATION_TEST.

## Open Questions

Все вопросы закрыты на эскалации 2026-08-11 (оркестратор + архитектор), открытых нет.

1. **Форма дельты обновления.** **Закрыто (оркестратор):** вложенный объект `diff: {added, removed} | null` — одинаково в SSE `artifact_updated` и в `ArtifactPart` (дословно по брифу; T1 реализует ту же форму).
2. **Имя поля типа файла в `ArtifactPart`.** **Закрыто (оркестратор):** `artifact_type` — `type` занят дискриминатором union'а (`backend/app/api/schemas/chats.py:74`, симметрично на фронте); формулировка брифа поправится на DOC_UPDATE. На SSE-проводе уже `artifact_type`.
3. **Форма list-ответа.** **Закрыто (архитектор):** плоский `ListResponse<Artifact>` с полными путями; дерево строит фронт — T2.3 остаётся как в плане.
4. **Форма `attachments` в `POST /messages`.** **Закрыто (оркестратор):** список строк-путей в запросе (диаграмма брифа); metadata `MessageOut` — `{path, title}` без размера (по тексту брифа): чип истории показывает имя без размера, чип композера показывает размер клиентски из объекта File.
5. **Проверка лимита размера на клиенте.** **Закрыто (оркестратор):** предпроверки нет — ошибка из ответа сервера (A14 удовлетворён); «отдавать лимит фронту» — кандидат в Follow-ups (harvest).
6. **Вложения вне композера существующего чата.** **Закрыто (архитектор):** скрепку дать **и в draft-композере (`/chats/new`), и в поле первого сообщения на странице проекта** — догфудинг-сценарий «лекция №1» начинается с нового чата; upload идёт в проект, через router state едут пути-строки. Фаза T2.8 расширяется соответствующе.
7. **Stub-вьюеры slides/audio.** **Закрыто (оркестратор):** снять ветки вместе с моками как недостижимый мёртвый код при переезде на словарь категорий; зафиксировать в `summary.md`. Туда же — dev-only `StudioPanel.tsx` (мок-панель за статически выключенным `SHOW_GROUP_B_STUBS`): её `.pdf`-кнопка и ветка `type === "image"` подпадают под Cross-cutting-критерий чистоты.
8. **Подпись строки ленты при перезаписи.** **Закрыто (оркестратор):** одна подпись на `write_file` («Записал файл»); семантику «создано/обновлено» несёт бейдж карточки из артефактной части — по брифу «только записи реестра», новых данных в строку ленты не заводим.
