# Implementation Plan: feat-013 / трек T3 — Точечные компонентные правки

## Контекст

Трек закрывает два независимых пункта бэклога, оба — правки одного экрана-размера: селектор модели перестаёт показывать англоязычное значение в свёрнутом виде и снова показывает активную модель в project-scope; имя проекта в настройках перестаёт редактироваться парой «сырой input + кнопка Сохранить» и становится inline-edit'ом с явным подтверждением. Ни новых компонентов в `shared/`, ни новых слайсов, ни правок API-слоя: оба пункта — вёрстка и локальная модель состояния внутри двух файлов.

**Изменения:**

### T3.2: Inline-edit имени проекта — модель состояния, вёрстка, клавиатура

**Цель:** заменить пару «сырой input + кнопка Сохранить» на два режима одной строки — просмотр (текст + карандаш) и редактирование (`shared/ui/input` + галочка/крестик) — с сохранением по Enter/галочке, отменой по Esc/blur и без клоббера открытого редактирования внешними обновлениями проекта.

**Изменения:**

- `frontend/src/pages/project-settings/ui/ProjectSettingsPage.tsx`, секция «Имя проекта» (строки 57–79) и её состояние (строки 18–34):
  - **Модель состояния.** Источник истины в режиме просмотра — `project.name` из квери, он рендерится напрямую. Редактирование держит собственный черновик, который заводится в момент входа в режим (снапшот `project.name`) и живёт только до выхода. `useEffect [project]` (строки 21–26) и флаг `nameDirty` (строка 19) **удаляются**: «грязность» вычисляется сравнением черновика со снапшотом/актуальным значением, а синхронизировать локальную копию с квери больше нечего. Так доопределение брифа про конкурентное обновление выполняется конструкцией, а не сторожем: внешний rename (модалка сайдбара, вторая вкладка, focus-refetch) меняет только то, что рендерит режим просмотра, и не может дотянуться до открытого ввода; отмена возвращает в просмотр, где уже стоит актуальное серверное значение.
  - **Режим просмотра** (мокап 745–749, стили `.pn-row`/`.pn-text` 330–331): строка `flex items-center gap-2` с `min-h-8`, имя — `text-sm font-medium text-foreground`, рядом иконочная кнопка-карандаш (`Button variant="ghost" size="icon-sm"` + `Pencil` из `lucide-react` с `size-3.5`; мокап `.icon-btn` 28px, иконка 14px). Кнопка — единственный вход в редактирование (мокап-подсказка «Клик по карандашу — редактирование»); текст кликабельным не делаем. У кнопки осмысленное доступное имя («Переименовать проект» — `title` из мокапа плюс `aria-label`, иконка без текста).
  - **Режим редактирования** (мокап 750–754): `Input` из `shared/ui/input` с `className="flex-1"`, `maxLength={100}` (значение сохраняется как есть — бэкенд ограничивает `ProjectUpdate.name` тем же `MAX_TITLE_LENGTH`), рядом две иконочные кнопки — галочка (`Check`, доступное имя «Сохранить», hover `hover:text-success`) и крестик (`X`, «Отменить», hover `hover:text-destructive`), обе `variant="ghost" size="icon-sm"`, иконки 16px (дефолт кнопки). Подпись-хинт под строкой из мокапа (755) — на усмотрение реализации: она объясняет клавиши; если добавляется, то как `mt-1 text-xs text-muted-foreground` и без дублирования доступных имён кнопок.
  - **Вход в режим:** черновик = текущее `project.name`, фокус в поле с выделением всего текста (мокап: `focus()` + `select()`).
  - **Сохранение** (Enter в поле или клик по галочке): `trim()`; пустая строка — не сохраняем и не выходим (кнопка галочки при этом `disabled`, как сегодня дизейблится «Сохранить»); значение, равное текущему `project.name`, — мутацию не отправляем, просто выходим в просмотр (тот же приём, что в `ChatActions.handleRename`); иначе `updateProject.mutate({ id, data: { name } })` — хук и его пессимистичная инвалидация не меняются.
  - **Отмена** (Esc в поле, клик по крестику, blur): выход в просмотр без записи, черновик выбрасывается.
  - **Blur vs кнопки** (доопределение брифа): обе иконочные кнопки режима редактирования гасят `mousedown` (`preventDefault`), иначе blur успевает свернуть режим раньше, чем до кнопки дойдёт `click`, — и клик по галочке молча превращается в отмену, а клик по крестику вообще не доходит до своего обработчика. Допустимая альтернатива — считать отменой только blur наружу контейнера редактирования (проверка `relatedTarget`); выбрать одно из двух и не смешивать.
  - **Blur во время сохранения:** пока мутация в полёте, blur ничего не отменяет (запись уже началась, отменять её нечем); режим закрывается по результату мутации, а не по потере фокуса.
  - **Возврат фокуса:** после выхода из режима (и по сохранению, и по отмене) фокус возвращается на карандаш — иначе клавиатурный пользователь теряет позицию на `body`.
  - Остальные секции страницы (модель, MCP, удаление проекта) не трогаются; заголовок «Имя проекта» остаётся `label`-подписью той же типографики.

**Verification:**

- `make check-fe` и `make test-fe` проходят (тестов на страницу сегодня нет — прогон ловит регрессии соседей).
- Сверка с мокапом (секция 4, `make dev-fe`, обе темы): геометрия строки — `gap-2`, высота строки не прыгает при переключении режимов (мокапный `min-height: 32px` на обеих строках); поле — тот же `Input`, что на остальных экранах (высота 8/32px, радиус `rounded-lg`, focus-ring `--ring`), а не сырой input со своими классами.
- Клавиатура: Enter сохраняет и закрывает режим, Esc закрывает без записи, Tab по кнопкам работает, у всех трёх иконочных кнопок есть доступное имя (проверка через `getByRole("button", { name: … })` в devtools/скринридере).
- **Клик по галочке сохраняет, а не отменяет** — сценарий: войти в режим, изменить текст, кликнуть мышью по галочке (не по Enter); в Network уходит `PUT /api/projects/<id>`, имя в просмотре — новое. Симметрично: клик по крестику отменяет и не шлёт запрос.
- **Конкурентное обновление** — сценарий из брифа 5.2: открыть настройки проекта в двух вкладках, в первой войти в режим редактирования и набрать текст, во второй переименовать проект через модалку сайдбара, вернуться в первую (focus-refetch обновит `useProject`) — набранный текст на месте, не перетёрт; нажатие Esc возвращает в просмотр с **новым** серверным именем.
- Пустое имя не сохраняется (кнопка недоступна, Enter не отправляет запрос); имя длиннее 100 символов ввести нельзя.

### T3.3: Подтверждение сохранения на токене `--success`

**Цель:** после успешной записи имени пользователь видит краткое подтверждение — зелёную галочку с подписью «Сохранено», — и оно само исчезает; на время записи строка честно показывает, что запрос идёт.

**Изменения:**

- `frontend/src/pages/project-settings/ui/ProjectSettingsPage.tsx`, та же секция:
  - **Подтверждение** (мокап 748, стиль `.pn-saved` 332–333): в режиме просмотра, справа от карандаша, появляется `inline-flex items-center gap-1 text-xs text-success` с иконкой `Check` (14px, `size-3.5`) и текстом «Сохранено». Показывается **только после успешной мутации** (выход из режима без записи — по Esc, по крестику, по неизменённому значению — подтверждения не даёт: подтверждать нечего), держится ~1.6 с (мокапный таймер `setTimeout … 1600`) и гаснет. Цвет — исключительно утилитой `text-success` (токен T1); hex/rgba в `.tsx` запрещён конвенцией.
  - Таймер обязан сниматься при размонтировании и при повторном входе в режим редактирования — иначе висящий `setTimeout` дёрнет состояние размонтированного компонента (React-warning) или погасит свежее подтверждение чужим тиком.
  - Подтверждение — вспомогательный, а не единственный канал: обернуть его в `role="status"` (паттерн уже применён в `pages/chat/ui/StreamEndNotice.tsx:18`), чтобы скринридер сообщил об успехе; цвет остаётся усилением, как и для галочки ленты активности (бриф 1.1).

## Резолюции оркестратора

**Устаревшие ассерты `ModelSelector.test.tsx` правит `test-author`, а не implementer.** План отдаёт implementer'у актуализацию двух кейсов, кодирующих старое поведение (статичная подсказка project-scope и англоязычное значение свёрнутого селекта). Это ровно тот случай, против которого написан инвариант A6 (`testing.md` § Целостность тестов): имплементер не правит и не удаляет ассерты своего скоупа — иначе «зелёно» достигается переписыванием спецификации под реализацию, а не наоборот. Судить, каким должен стать ассерт, обязан независимый автор тестов, читающий контракт из брифа.

Порядок для трека:

1. **IMPLEMENT** реализует фазы и сдаёт прогон, в котором краснеют **ровно эти два кейса** — они перечислены поимённо и ожидаемы. Любой третий красный — сигнал регрессии, повод разбираться в коде, а не в тестах. Имплементер тест-файл не открывает на запись.
2. **TEST_AUTHORING** приводит устаревшие ассерты к новому контракту и дописывает покрытие на новое поведение (в том числе inline-edit: снапшот черновика, blur-guard, подтверждение сохранения).
3. Зелёный гейт трека фиксируется по итогам TEST_AUTHORING и GREEN, а не по итогам IMPLEMENT.

## Правки по plan-review (внесены оркестратором, обязательны к исполнению)

Ревью плана свежим агентом: blocker — 1 (снят ниже), nit — 2, question — 2. **При расхождении этой секции с телом фаз выше приоритет у неё.**

1. **`ModelSelector.test.tsx` — read-only для implementer'а; гейт фазы T3.1 переопределён.** Тело плана (границы трека, фаза T3.1, Open Question 4) осталось в редакции до резолюции: оно поручает имплементеру переписать два ассерта и трижды требует зелёный `make test-fe` — под резолюцией это недостижимо и толкает исполнителя либо нарушить A6, либо упереться в невыполнимый гейт. Итог: тест-файл из списка правок фазы **исключён**; гейт фазы T3.1 читается так — `make check-fe` зелёный, а `make test-fe` даёт **ровно два ожидаемых красных**: `labels the default choice 'Default' for user scope` и `labels the default choice 'Inherit' for project scope`. Любой третий красный — регрессия, повод разбираться в коде. Ассерты приводит к новому контракту `test-author` на фазе TEST_AUTHORING; зелёный гейт трека фиксируется после GREEN.

2. **Подпись-хинт под строкой имени — обязательна, не «на усмотрение реализации».** Мокап утверждён архитектором целиком и объявлен каноном визуальных значений; понижать его элемент до опции — значит допустить дифф, расходящийся с утверждённой картинкой, без решения архитектора. Текст берётся из мокапа буквально («Клик по карандашу — редактирование · Enter — сохранить · Esc — отменить»), оформление — `mt-1 text-xs text-muted-foreground`.

3. **Отмена во время полёта мутации не действует.** План отключает при `isPending` только поле и галочку, оставляя Esc, крестик и blur рабочими, — тогда режим закрывается, хотя запись уже ушла и завершится успехом, а следом мигнёт «Сохранено» поверх «отменённого» редактирования. Пока мутация в полёте, отмена (Esc / крестик / blur) игнорируется: режим закрывается только по результату — успехом или ошибкой. Крестик при `isPending` — `disabled`, наравне с галочкой.

4. **После успеха view держит только что сохранённое имя до прихода рефетча.** Между закрытием режима и ответом инвалидации `useProject` отдаёт **старое** `project.name` — иначе пользователь увидит кадр «старое имя рядом с зелёным „Сохранено“». Значение держится локально до совпадения с данными квери; `shared/api/**` при этом не открывается — граница трека сохраняется.

5. **Обоснование `preventDefault` на `mousedown` крестика уточняется** (требование к обеим кнопкам остаётся). Дело не в том, что «иначе отмена не сработает» — blur и так отменяет, исход тот же. Настоящий риск: строка перерисовывается между `mousedown` и `mouseup`, клик приземляется на элемент view-строки, плюс гонка с возвратом фокуса. Это и пиши в коде, если комментируешь.
