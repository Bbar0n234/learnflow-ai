# Summary: feat-013 / трек T3 — Точечные компонентные правки

## TL;DR

Трек T3 закрыт всеми тремя фазами. T3.1: `ModelSelector` показывает единый русский лейбл дефолтного выбора («По умолчанию» / «Наследовать») и в свёрнутом виде, и в раскрытом списке; строка «Активная модель: …» рендерится во всех трёх scope, включая `project`, статичная подсказка про переопределение и висящий пробел убраны. T3.3: после успешной записи в просмотре на ~1.6с мигает `role="status"` подтверждение «Сохранено» на `text-success` рядом с карандашом; кадр «старое имя рядом с зелёным „Сохранено“» снят локальной подменой отображаемого имени (`confirmedName`) до совпадения с данными квери; ошибка записи не закрывает режим и не трогает подтверждение — черновик остаётся, сообщение идёт единственным существующим каналом, глобальным тостом `MutationCache.onError`; повторный вход в редактирование гасит висящий таймер подтверждения, таймер снимается и при размонтировании. `make check-fe` зелёный на обоих файлах трека (`ModelSelector.tsx`, `ProjectSettingsPage.tsx`); `make test-fe` (точечно на файлах трека) даёт ровно два ожидаемых красных из T3.1 (см. «Гейты») — третьего в скоупе T3 нет.

  - Отмена: `cancelEdit` на Esc / клике по крестику / `blur` инпута.
  - Обе иконочные кнопки редактирования гасят `mousedown` (`preventDefault`) — комментарий в коде объясняет причину так, как уточнено в plan-review (не «иначе отмена не сработает», а защита от перерисовки строки между `mousedown`/`mouseup` и от гонки с возвратом фокуса).
  - Хинт под строкой — `mt-1 text-xs text-muted-foreground`, текст буквально из мокапа: «Клик по карандашу — редактирование · Enter — сохранить · Esc — отменить»; рендерится всегда (не только в режиме редактирования), как в мокапе.
  - Pending-guard (правка plan-review 3): пока `updateProject.isPending`, инпут и **обе** кнопки (галочка и крестик) — `disabled`; `cancelEdit` явно проверяет `isPending` и игнорирует Esc/крестик/blur, пока мутация в полёте — режим закрывается только по результату мутации (`onSuccess`), а не по потере фокуса. Это существенно, а не избыточно: React дизейблит инпут в момент старта мутации → браузер сам снимает с него фокус → срабатывает `onBlur` → без guard'а это закрыло бы режим редактирования раньше ответа сервера.
  - Подтверждение «Сохранено» (T3.3): состояние `showSaved: boolean` + `savedTimerRef`. `commitEdit`'s `onSuccess` вызывает `setConfirmedName(trimmed)`, `closeEdit()`, затем снимает возможный старый таймер (`clearSavedTimer()`) и заводит новый — `setShowSaved(true)`, `setTimeout(() => setShowSaved(false), 1600)`. Рендерится в просмотре после карандаша: `<span role="status" className="inline-flex items-center gap-1 text-xs text-success"><Check className="size-3.5" />Сохранено</span>`, монтируется только пока `showSaved` истинно (не постоянный элемент с `opacity`/классом-модификатором, как в HTML-мокапе, — условный рендер эквивалентен по итоговому DOM-поведению и проще в React, самой library кросс-фейд из мокапа воспроизводить не требовалось: план фиксирует только визуальный токен и длительность, не механизм анимации).
  - Удержание имени до рефетча (T3.3, правка plan-review 4): `confirmedName: string | null` — на успешный коммит получает сохранённое значение; `displayName = confirmedName !== null && confirmedName !== project?.name ? confirmedName : project?.name` — просмотр читает `displayName` вместо `project?.name` напрямую. Отдельный `useEffect([project?.name, confirmedName])` сбрасывает `confirmedName` в `null`, как только квери догоняет (`project?.name === confirmedName`) — с этого момента просмотр снова читает `project?.name` напрямую и внешние переименования опять видны немедленно.
  - Снятие таймера подтверждения (план, «таймер обязан сниматься при размонтировании и при повторном входе в режим редактирования»): `clearSavedTimer()` вызывается в двух местах — в cleanup `useEffect(() => clearSavedTimer, [])` (unmount) и в начале `startEdit()` вместе с `setShowSaved(false)` (повторный вход). `startEdit` также берёт снапшот черновика из `displayName ?? project.name`, а не из `project.name` напрямую — если пользователь реоткрывает редактирование до прихода рефетча, черновик заводится от свежего локально удержанного имени, а не от ещё не догнавшего кеша.
  - Ошибка записи (T3.3): отдельного кода не потребовалось — `commitEdit` передаёт мутации только `onSuccess`, `onError` не задаётся, поэтому при ошибке режим не закрывается (нет вызова `closeEdit()`), `confirmedName`/`showSaved` не трогаются (нет вызова), черновик остаётся как есть. Сообщение пользователю доставляет уже работающий глобальный канал `MutationCache.onError → toast.error` (`QueryProvider.tsx:42-48`), в `ProjectSettingsPage.tsx` для него не заведено ничего нового.

## Решения и обоснования

- Тест-файл `ModelSelector.test.tsx` не открывался на запись — это прямое требование резолюции оркестратора и секции «Правки по plan-review» плана (пункт 1): инвариант A6 запрещает implementer'у переписывать ассерты своего скоупа, чтобы не подгонять спецификацию под реализацию задним числом. Это порождает два ожидаемых красных теста (см. «Гейты» ниже) — по плану они переходят к `test-author` на фазе TEST_AUTHORING.
- `defaultChoiceLabel` вынесен в отдельную константу компонента, а не в helper-функцию модуля: логика однострочная, зависит только от пропа `scope`, второй вызывающей стороны кроме двух точек использования внутри компонента нет — выносить за пределы функции компонента избыточно.
- **Как снят клоббер конкурентного обновления (T3.2).** Раньше единственным источником истины было локальное `name`, а `useEffect [project]` перетирал его при каждом обновлении объекта проекта — в том числе когда обновление пришло извне во время открытого редактирования. Новая модель убирает промежуточное состояние из просмотра вообще: просмотр не хранит копию имени, а читает `project.name` из квери на каждый рендер, поэтому внешний rename виден в просмотре немедленно и без специального кода синхронизации. Черновик существует только пока `draft !== null` (режим редактирования), заводится один раз — снапшотом в момент клика по карандашу — и с этого момента живёт независимо от квери: обновления `project` из quiet refetch/фокуса/другой вкладки продолжают перерисовывать компонент, но не задевают `draft`, потому что для него больше нет эффекта, который бы его переустанавливал. Отмена не пытается «восстановить» старое значение — она просто выбрасывает черновик (`setDraft(null)`), и следующий рендер автоматически показывает то, что в этот момент реально лежит в квери, то есть уже актуальное серверное имя. Так доопределение брифа выполняется отсутствием синхронизирующего кода, а не сторожем поверх него.
- **Возврат фокуса на карандаш** реализован через `focusPencilOnCloseRef` (флаг «нужно сфокусировать после следующего рендера в режиме просмотра»), а не прямым вызовом `pencilRef.current?.focus()` в момент закрытия: кнопка-карандаш не существует в DOM во время редактирования (она размонтирована, рендерится только в просмотровом режиме), поэтому вызывать `.focus()` до коммита React-обновления бессмысленно — `pencilRef.current` в этот момент ещё `null`. Единый `useEffect` по `isEditing` обслуживает оба перехода (в редактирование — фокус+`select()` инпута; из редактирования — фокус карандаша, если флаг установлен).
- **`preventDefault` на `mousedown` — обеим кнопкам**, обоснование по правке plan-review 5: не «иначе отмена не сработает» (blur и так отменяет с тем же исходом), а защита от перерисовки строки между `mousedown` и `mouseup` (клик может приземлиться не туда) и от гонки с программным возвратом фокуса. Формулировка перенесена в код комментарием у `cancelEdit`.
- **Отмена во время полёта мутации не действует** (правка plan-review 3) — реализовано как ранний `return` в `cancelEdit()` по `updateProject.isPending`, а не отключением одних только Esc/крестика: `blur` тоже вызывает `cancelEdit`, и именно `blur` — самый частый практический триггер гонки, потому что дизейбл инпута на старте мутации сам провоцирует потерю фокуса браузером.
- Хинт-подсказка рендерится безусловно (вне ветвления просмотр/редактирование), а не только в режиме редактирования: в мокапе (`pn-varA`) это общий `<p class="hint">` под обеими строками, а не элемент одного из режимов — текст объясняет весь флоу («клик — редактирование», не только «Enter/Esc»), поэтому скрывать его в просмотре было бы расхождением с каноном.
- В T3.2 удержание только что сохранённого имени локально до прихода рефетча (правка plan-review 4) и подтверждение «Сохранено» были сознательно не реализованы, вне скоупа фазы по явному указанию оркестратора — оба закрыты в T3.3 (см. выше в «Реализовано»).
- Текстовая pending-индикация (вроде «Сохраняем…») из T3.3 сознательно не заведена, как и в исходном плане: кнопка иконочная, места под текст в макете нет, а `disabled`-состояние поля и обеих кнопок уже честно показывает, что запись идёт.
- **Доступные имена поля имени проекта и селектора модели (фикс R8, попытка 1).** Обе подписи были `<label>`, ни одна ни с чем не связана: ни `htmlFor`, ни вложенного контрола. Для скринридера это значит, что и текстовое поле, и селектор объявлялись безымянными — пользователь слышит «редактирование текста» и «combobox», но не знает, чего именно; попутно клик по подписи не переводил фокус в поле, а автотесты вынуждены были искать поле безымянным `getByRole("textbox")`. Паттерн старше итерации и в брифе поимённо не назван — чиним по решению оркестратора, потому что оба файла в закрытом списке трека, правка мелкая, а итерация ровно про предпоказную полировку интерфейса.
  - **Имя проекта** (`pages/project-settings/ui/ProjectSettingsPage.tsx`): `useId()` даёт `nameInputId`, `Input` получает `id`, подпись — `htmlFor`. Подпись при этом рендерится `<label>`'ом **только в режиме редактирования**: поля в просмотре не существует (там текст плюс карандаш со своим `aria-label`), и `<label htmlFor>` указывал бы в пустоту — `<label>`, который ничего не подписывает, это ровно тот же дефект, что и находка. В просмотре подпись — обычный `<p>` с теми же визуальными классами, DOM-вывод и вёрстка не меняются. Логика inline-edit не тронута: снапшот черновика, blur-отмена, pending-guard, возврат фокуса на карандаш работают как были. Побочный эффект `htmlFor` — клик по подписи во время редактирования: он приходит как клик вне инпута, срабатывает штатная blur-отмена и режим закрывается ровно так же, как от клика по любому другому месту страницы (поведение до фикса было тем же, менять его — вне скоупа находки).
  - **Модель** (`features/model-selector/ui/ModelSelector.tsx`): триггер Base UI — это `<button role="combobox">`, а не нативный контрол, поэтому связь идёт через `aria-labelledby` на `SelectTrigger` (подпись — `<span id>` от `useId()`). Это и штатный механизм Base UI (его собственный `Select.Label` внутри делает ровно то же — проставляет триггеру `aria-labelledby`), и канонический паттерн ARIA APG для select-only combobox: имя контрола — «Модель», текущее значение остаётся содержимым триггера. Приём уже есть в проекте на соседнем селекте — `features/mcp-servers/ui/MCPServerForm.tsx:80`. Контракт `ModelSelector` (пропсы, мутация, тексты) не менялся.
  - Почему не библиотечная часть `Select.Label`: обёртка `shared/ui/select.tsx` её не реэкспортирует (тамошний `SelectLabel` — это `GroupLabel` для групп внутри списка), и добавление экспорта означало бы правку сгенерированного примитива и его публичного контракта — вне закрытого списка файлов трека. Разница только в приятной мелочи: `Select.Label` дополнительно переводит фокус на триггер по клику по подписи. Вынесено архитектору решением, не сделано молча.
  - Проверено фактическим вычислением доступного имени (временная проба на харнессе трека, в репозиторий не коммитилась): `getByRole("combobox", { name: "Модель" })` и `getByLabelText("Имя проекта")` находят контролы. Скоуп трека — 27 passed, ни один ассерт не менялся.
