# Test Cases: feat-013 — UI polish / трек T3 «Точечные компонентные правки»

Трек T3 меняет поведение двух экранных мест, поэтому кейсы страхуют не «ничего не сломалось», а
именно новое поведение. Селектор модели перестал показывать англоязычное `Default`/`Inherit` в
свёрнутом виде и снова показывает строку «Активная модель: …» в project-scope — вместо неё там
раньше стояла статичная подсказка про переопределение. Имя проекта в настройках перестало быть
парой «сырой input + кнопка Сохранить» и стало inline-edit'ом: просмотр с карандашом, режим
редактирования с галочкой и крестиком, сохранение по Enter и по клику, отмена по Esc, крестику и
blur, краткое подтверждение «Сохранено» после успешной записи.

Ожидаемые изменения поведения (то, что раньше было «правильным», а теперь нет): свёрнутое значение
селекта локализовано; строки «Переопределяет модель пользователя для этого проекта.» больше нет
нигде; во время полёта мутации имени отмена не действует; после успеха просмотр показывает
только что сохранённое имя, не дожидаясь рефетча. Автотесты закрывают всё, что наблюдаемо в
jsdom; визуальная часть (цвет подтверждения, ритм строки, плавность появления, отсутствие
висящего пробела) ушла в ручные кейсы `{T3.x}` с пометкой 👤.

## Конвенции прохождения (инлайн — это рамка тестировщика)

**Статус и run-log.** У каждого кейса — текущий статус плюс опциональный run-log, если кейс прогонялся не раз:

- `- [x]` + лаконичный результат: что проверялось, что получилось, значимые нюансы. По заполненному чек-листу должно быть видно, что всё работает, без перепрохождения.
- `- [ ] ⚠️` + причина, если кейс не пройден или требует отдельного внимания.
- Кейсы с 👤 — требуют ручного действия / решения архитектора (UI, браузер); тестировщик помечает и эскалирует.
- **Доменные маркеры**: `[auto]` — кейс закрыт автотестом (живёт рядом со слайсом); `*(регресс)*` — кейс страхует «поведение не сломалось» (отделяет регресс от проверки нового поведения).
- **run-log** (только у перепрогнанных кейсов) — строка-история флипов с причиной:
  `runs: r1 ✅ → r2 ❌ (после фикса review #3: регрессия инвалидации) → r3 ✅`.
  Один прогон — run-log не нужен. Перепрогон после правки кода обязателен (см. ре-верификацию).

**Ре-верификация.** Правка кода аннулирует прошлый зелёный статус затронутого. После фиксов: детерминированный гейт (`make check-fe`/`make test-fe`) — перепрогон всегда; ручные/UI-кейсы — перепрогон только затронутой области. Каждый перепрогон → запись в run-log.

**Диагностика — через наблюдаемость, не догадки.** Один кейс — одна попытка диагностики: не сошлось — повтори (мог быть транзиент); не сошлось второй раз — fail + эскалация, без долгой отладки. Инструменты фронта: DevTools → Network (PUT `/api/projects/<id>`), DevTools → Console (логи через `@/shared/lib/logger`), React DevTools для состояния. Код тестировщик не правит: прод-баги, вскрытые кейсом, чинит **fixer** (A6: fixer ≠ автор теста).

**Скоуп по трекам.** Кейсы с префиксом `{T3.x}` гоняются на треке T3 + Layer 0; cross-cutting (Layer 2/3 без префикса) — в INTEGRATION_TEST. Не пропускать кейсы молча — неприменимый помечать причиной.

## Дизайн автотестов

**Покрываем автотестом** — по одной записи на суиту:

### `ModelSelector.test.tsx` — селектор модели во всех трёх scope

1. **Файл**: `frontend/src/features/model-selector/ui/ModelSelector.test.tsx` — frontend integration (компонент вместе со своими хуками `useModels`/`useSettings`/`useUpdateSettings`), шов: MSW + свежий `QueryClient` через `renderWithProviders`; попап Base UI открывается по-настоящему благодаря `@/test/pointer-event-polyfill`.
2. **Тестирует**: `features/model-selector/ui/ModelSelector.tsx :: ModelSelector`
3. **Суть**: Суита следит за тем, что селектор называет выбранное значение одинаково в свёрнутом триггере и в раскрытом списке и делает это по-русски во всех трёх scope, а под ним всегда стоит строка «Активная модель: …» — в том числе в project-scope, где её раньше вытесняла статичная подсказка про переопределение. Она же продолжает страховать запись выбора (`PUT` настроек с `model_name` и с `null`), деградацию на недоступном `/models` и блокировку триггера на время записи, поэтому правка рендера не может тихо утащить за собой мутацию. Триггер везде ищется **по доступному имени** — `getByRole("combobox", { name: "Модель" })`: подпись связана с ним только через `aria-labelledby` (триггер Base UI — кнопка, а не нативный контрол), и потеря этой связи обязана покраснеть, а не пройти незамеченной.
4. **Кейсы**:
   - свёрнутый триггер называет дефолтный выбор «По умолчанию» (user) и «Наследовать» (project, thread) — таблица через `it.each` по трём scope;
   - раскрытый список называет дефолтную опцию ровно так же, как триггер (project scope) — расхождение двух мест и было багом;
   - project-scope показывает «Активная модель: Claude Sonnet», а строки «Переопределяет модель пользователя…» нет в дереве;
   - явно выбранная модель показывается `display_name`'ом и в триггере, и в строке активной модели *(регресс)*;
   - список моделей не загрузился → строка активной модели показывает сырое имя модели *(регресс)*;
   - выбор явной модели шлёт `PUT {model_name: "claude-sonnet"}`, выбор дефолтного пункта — `PUT {model_name: null}` *(регресс)*;
   - триггер недоступен, пока запись в полёте, и снова доступен, когда она завершилась *(регресс)*; «в полёте» держит промис-затвор теста, а не задержка по реальным часам.

### `ProjectSettingsPage.test.tsx` — inline-edit имени проекта

1. **Файл**: `frontend/src/pages/project-settings/ui/ProjectSettingsPage.test.tsx` — frontend integration (страница целиком, вместе с соседними секциями), шов: MSW + свежий `QueryClient` + `MemoryRouter` через локальный хелпер `@/test/router`; долгий ответ сервера моделируется промисом, который освобождает сам тест, а не задержкой по часам.
2. **Тестирует**: `pages/project-settings/ui/ProjectSettingsPage.tsx :: ProjectSettingsPage` (секция «Имя проекта»)
3. **Суть**: Суита описывает жизненный цикл inline-edit'а от карандаша до подтверждения: как открывается редактирование, чем оно заканчивается по каждому из **пяти** выходов (Enter, галочка, Esc, крестик, потеря фокуса), что уходит в сеть и что не уходит. Отдельно она сторожит три вещи, ради которых бриф получил доопределения: клик по галочке сохраняет, хотя поле в этот момент теряет фокус; внешнее переименование проекта не стирает открытый черновик, а отмена после него возвращает актуальное серверное имя; пока запись в полёте, ни Esc, ни крестик, ни потеря фокуса не откатывают режим — он закрывается только результатом мутации. Наконец, она проверяет, что подтверждение «Сохранено» появляется только после реальной записи, гаснет само и никогда не соседствует со старым именем, а локальная подмена имени живёт ровно до того момента, как квери догонит запись. Поле везде ищется **по доступному имени** — `getByLabelText("Имя проекта")`, а не безымянным `getByRole("textbox")`: связь подписи с полем — часть контракта, и её потеря красит суиту.
4. **Кейсы**:
   - просмотр показывает имя текстом и кнопку-карандаш, поля ввода нет;
   - клик по карандашу открывает поле с текущим именем, поле в фокусе, значение выделено целиком;
   - подпись называет поле в режиме редактирования и не является `<label>` в просмотре (там подписывать нечего — `<label for>` вёл бы в пустоту);
   - Enter сохраняет обрезанное по краям имя, шлёт `PUT` и возвращает в просмотр;
   - клик по галочке сохраняет (blur поля при этом происходит раньше клика);
   - Esc отменяет: запроса нет, имя прежнее, подтверждения нет;
   - клик по крестику отменяет: запроса нет, подтверждения нет;
   - потеря фокуса вне полёта записи отменяет: запроса нет, имя прежнее, подтверждения нет;
   - пустое имя: галочка недоступна, Enter не шлёт запрос, режим не закрывается;
   - неизменённое имя: режим закрывается без запроса и без подтверждения;
   - ввод обрезается на 100 символах;
   - внешнее переименование во время открытого редактирования не трогает черновик; Esc после него возвращает просмотр с новым серверным именем;
   - во время полёта записи поле и крестик недоступны, blur не отменяет, режим закрывается только по ответу;
   - успешная запись показывает `role="status"` «Сохранено», которое гаснет само;
   - повторный вход в редактирование снимает подтверждение прошлой записи (оно не всплывает обратно при отмене) — на замороженном клоке, чтобы «подтверждения нет» нельзя было получить от собственного дедлайна 1.6 с;
   - просмотр показывает только что сохранённое имя рядом с подтверждением, даже если сервер ещё отвечает старым (кадра «старое имя + Сохранено» не возникает);
   - локальная подмена снимается, как только квери принесла сохранённое имя: следующее внешнее переименование снова видно в просмотре;
   - ошибка записи оставляет режим открытым с набранным текстом и без подтверждения — с ассертом на факт ушедшего `PUT`, иначе кейс истинен и в мире, где Enter ничего не отправляет;
   - фокус возвращается на карандаш после отмены и после успешного сохранения.

**Осознанно не покрываем автотестом:**

- Гонка «таймер прошлого подтверждения гасит свежее» (`clearSavedTimer()` в `onSuccess`) — механизмов, закрывающих её, **два, и они резервируют друг друга**: единственный вход в редактирование `startEdit` уже гасит висящий таймер, поэтому к моменту `onSuccess` `savedTimerRef` всегда `null`. Одиночная мутация любого из двух не наблюдаема ни в jsdom, ни в браузере (мутация `onSuccess`: 0 красных) — оракул появился бы только у мутации, снимающей оба сразу, а кейс на такую пару сторожил бы не поведение, а количество подстраховок в коде. Ручной `{T3.7}` по той же причине проваливается только при снятии обоих; сам по себе он даёт другое — отсутствие React-предупреждения о таймере, дотикавшем в размонтированный компонент. Кейса-декорации в наборе не оставлено.
- `preventDefault` на `mousedown` **крестика** — риск, ради которого он поставлен (перерисовка строки между `mousedown` и `mouseup`, гонка с программным возвратом фокуса), jsdom не воспроизводит, а исход без него в тестовой среде тот же: blur отменяет так же, как крестик. Свойство, которое среда не исполняет, сторожа не получает — фиксируем явно, а не кейсом-декорацией. У галочки `preventDefault` наблюдаем и сторожа имеет (без него клик по ней превращается в blur-отмену).
- Висящий пробел в конце строки «Активная модель: …» — RTL нормализует пробелы, `findByText` такой дефект не видит по определению → визуальная сверка `{T3.1}`.
- Цвет подтверждения (`--success`), геометрия строки (`min-h-8`, `gap-2`), совпадение поля с общим `Input`, плавность появления/исчезновения — jsdom не считает стили и не исполняет анимации → `{T3.3}`, `{T3.4}`.
- Тост об ошибке записи — глобальный канал `MutationCache.onError → toast.error` живёт в `app/providers/QueryProvider.tsx`, тестовый `QueryClient` его не подключает (и `app/**` — чужой трек) → `{T3.8}`.
- Настоящий двухвкладочный сценарий с focus-refetch — автотест воспроизводит его рефетчем той же квери, что честно моделирует источник данных, но не поведение браузера при возврате фокуса → `{T3.6}`.
- Соседние секции той же страницы (MCP-серверы, удаление проекта) — вне контракта T3; в суите они присутствуют только как сеть, которую страница обязана уметь загрузить. Удаление проекта по-прежнему без покрытия — кандидат в follow-up, не долг трека.
- Текст подсказки-хинта под строкой имени — статичная копия из мокапа; проверять её ассертом значит фиксировать копирайт, а не поведение → визуальная сверка `{T3.5}`.

**Замеченные прод-баги (для fixer'а, сам не чиню):** блокирующих нет. Наблюдение про подписи без связи с контролами (у поля имени и у селектора модели не было доступных имён) закрыто fixer'ом в рамках трека — `htmlFor`/`id` у поля в режиме редактирования, `aria-labelledby` у триггера селекта; оба набора после этого ходят по доступному имени, и откат любой из связей красит суиту (см. таблицу мутаций).

Две гипотезы о багах проверены и **не подтвердились**: локально удержанное имя (`confirmedName`) не залипает, если сразу после нашей записи проект переименовали снаружи — рефетч сначала приносит наше имя, подмена снимается, внешнее имя видно (проба доведена до кейса набора по R2, а не осталась пробой); повторный Enter без изменений сразу после сохранения лишнего `PUT` не шлёт (прогонялось отдельным пробным тестом, в набор он не вошёл).

## Ручные кейсы + статусы

### Layer 1: Трек T3 — точечные компонентные правки

> **Прогон INTEGRATION_TEST:** стенд — только фронт, backend не поднимался (решение оркестратора). Ключевое следствие для этого трека:
