# Test Cases: feat-013 — UI/UX polish / трек T4 «Состояния списков, страниц и роутинг»

Трек раскатал по спискам, панелям и роутеру четыре формы «не-контента», сданные T1: скелетон-группу, спиннер-блок, карточку ошибки с «Повторить» и полноэкранный `StateScreen`. Часть правок поведение сохраняет (перевод строк, замена вёрстки на общий примитив), часть — меняет его сознательно, и тесты обязаны отражать именно новое поведение, а не старое.

**Ожидаемые изменения поведения, под которые приведены тесты.** Любой нелегитимный URL теперь отдаёт брендовый 404 **внутри** `AppLayout` — включая `/security` в сборке с выключенным SIEM-флагом, где раньше не рендерилось вообще ничего (бриф блок 7). Каждое per-query error-состояние получило путь восстановления помимо F5: кнопка «Повторить» перезапрашивает свою квери (блок 4), а формулировка ошибки унифицирована под «Не удалось загрузить …». Плоские строки загрузки уступили скелетонам в списках и спиннер-блоку в панелях (блок 3), поэтому «видна строка „Загрузка …“» перестало быть наблюдаемым фактом. Пустая сфера получила действие при подсказке (блок 6.1), заглушка артефактов уехала из роутера в компонент слайса (блок 6.2). Доступные имена контролов и весь копирайт проектных модалок переведены на русский (блок 2 «Заодно») — accessible name английских кнопок больше не существует в DOM.

## Конвенции прохождения (инлайн — это рамка тестировщика)

**Статус и run-log.** У каждого кейса — текущий статус плюс опциональный run-log, если кейс прогонялся не раз:

- `- [x]` + лаконичный результат: что проверялось, что получилось, значимые нюансы. По заполненному чек-листу должно быть видно, что всё работает, без перепрохождения.
- `- [ ] ⚠️` + причина, если кейс не пройден или требует отдельного внимания.
- Кейсы с 👤 — требуют ручного действия / решения архитектора (UI, браузер); тестировщик помечает и эскалирует.
- **Доменные маркеры** (применять, если итерация их касается): `📊` — проверка наблюдаемости (структура БД, метрики, Redis state, Langfuse); `🔴` — проверка реальных инъекций / атак / security-событий; `[auto]` — кейс закрыт автотестом (живёт рядом со слайсом); `*(регресс)*` — кейс страхует «поведение не сломалось» (отделяет регресс от проверки нового поведения).
- **run-log** (только у перепрогнанных кейсов) — строка-история флипов с причиной:
  `runs: r1 ✅ → r2 ❌ (после фикса review #3: регрессия инвалидации) → r3 ✅`.
  Один прогон — run-log не нужен. Перепрогон после правки кода обязателен (см. ре-верификацию).

**Ре-верификация.** Правка кода аннулирует прошлый зелёный статус затронутого. После фиксов: детерминированный гейт (`make check-fe`, `make test-fe`) — перепрогон всегда; ручные/UI-кейсы — перепрогон только затронутой области. Каждый перепрогон → запись в run-log.

**Диагностика — через наблюдаемость, не догадки.** Один кейс — одна попытка диагностики: не сошлось — повтори (мог быть транзиент); не сошлось второй раз — fail + эскалация, без долгой отладки. Инструменты фронта: DevTools → Network (какие запросы ушли после «Повторить»), DevTools → Console (`@/shared/lib/logger`), переключатель темы в футере сайдбара. Код тестировщик не правит: прод-баги, вскрытые кейсом, чинит **fixer** (A6: fixer ≠ автор теста).

**Скоуп по трекам.** Кейсы с префиксом трека (`{T4.1}`) гоняются на своём треке + Layer 0; cross-cutting (Layer 2/3 без префикса) — в INTEGRATION_TEST.

### Процесс (тестировщик поднимает стенд сам)

1. Инфраструктура: `make docker-up-db`, `make migrate`, backend `make dev`, фронт `make dev-fe`. Для SIEM-кейсов — siem-service и `SIEM_ENABLED=true`; для кейса {T4.10} нужна и сборка с `SIEM_ENABLED=false`.
2. Акторы: **user-a** — обычный пользователь с проектом, в котором есть чаты и артефакты, и с проектом без содержимого сферы; **admin** — через `make grant-admin USER=<name>` (вкладки SIEM).
3. Прогон сверху вниз; каждый failed-кейс — повторная попытка, затем фиксация в run-log + `## Решения и обоснования` summary трека.
4. Ошибки сети воспроизводятся DevTools → Network → Offline либо остановкой backend: это единственный способ увидеть карточки ошибок и проверить «Повторить» вживую.

### `app/components/ErrorBoundary.test.tsx` — последний экран продукта

1. **Файл**: `frontend/src/app/components/ErrorBoundary.test.tsx` — unit, без сети; шов — `vi.spyOn(logger, "error")` (граница наблюдаемости) и глушилка `console.error`, которым React печатает пойманную ошибку.
