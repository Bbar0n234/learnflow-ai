# Бренд-бриф LearnFlowAI — вход для Claude Design

Опорный материал итерации feat-007 (брендинг / дизайн-система). Назначение: контекст-пакет для сессии в [Claude Design](https://claude.ai/design) — архитектор прикладывает этот документ к проекту, линкует репозиторий и генерирует концепт-направления.

## Как использовать (чек-лист сессии)

1. Создать проект в claude.ai/design.
2. Линкануть GitHub-репозиторий, **только поддиректорию `frontend/`** (весь монорепо — лагает). Claude Design вычитает дизайн-токены из `frontend/src/index.css` и компоненты из `frontend/src/shared/ui/`.
3. Приложить этот бриф + референсы ([refs/](refs/)). Текущий UI намеренно не прикладывается скриншотами: стиль и layout перерабатываются с нуля, а реальная информационная архитектура описана текстом ниже (раздел «Информационная архитектура») — придерживаться нужно её, а не текущего вида приложения.
4. Попросить 2–3 концепт-направления на ключевых экранах (список ниже), сравнить, итерировать.
5. Выбранное направление → экспорт handoff bundle для Claude Code → вход реализационной итерации.

## Продукт

**LearnFlowAI** — open-source AI-платформа, превращающая мысли и контекст эксперта в структурированные учебные и технические материалы: доклады, статьи, курсы, конспекты.

**JTBD:** «Когда у меня много мыслей и контекста по теме, я хочу быстро получить структуру и черновик материала, чтобы не тратить часы на рутину систематизации».

**Аудитория (первичная):** tech-спикеры и докладчики — разработчики, архитекторы, тимлиды. Взрослые технические эксперты, ценящие структуру и качество подачи. Расширение: самоучки, структурирующие знания для себя; позже — преподаватели вузов.

**Центральная метафора продукта — «шар контекста» (Knowledge Sphere).** Проект — это живое, растущее ядро знания: в нём накапливаются обсуждения, решения, артефакты, и агент опирается на эту память между сессиями. Это главное отличие от конкурентов (NotebookLM, Oboe): у них источники — статичная загрузка, у нас знание живёт и накапливается.

## Характер бренда

**Атрибуты:** спокойный · умный · тёплый · собранный. Взрослый стиль — но не старый и не скучный. Инструмент эксперта, которому доверяешь думать рядом с собой.

**Анти-примеры (чем мы НЕ будем):**

- Детскость, геймификация, конфетти.
- Корпоративный энтерпрайз-холод (стоковые иллюстрации, синие дашборды).
- Generic-AI-эстетика: фиолетовые градиенты, «магические» искорки ✨, дефолтный shadcn-вид.
- Перегруженный «вау-демо» визуал без пользы — против ценностей продукта.

**Иллюстрации.** Уместен сдержанный «мультипликативный» стиль **врезками** — сказочные мотивы в духе Zapier (волшебник на ковре-самолёте, кот учёный; см. [ref-09](refs/ref-09-zapier-fairytale-illustration.jpg)). «Кот учёный» — прямая культурная отсылка к учёбе. Применение точечное: welcome, empty states, onboarding, баннеры — не сплошной стиль интерфейса и не постоянный маскот в рабочих экранах.

## Ментальная модель и layout

Ориентир — creation journey NotebookLM: **inputs → conversation → outputs**, у пользователя всегда есть ощущение места. Наша адаптация — трёхпанельная структура, эволюционная к текущему UI:

```
┌──────────┬──────────────────────┬──────────────┐
│ Проекты  │  Рабочая зона:       │  Студия:     │
│ и чаты   │  чат с агентом       │  сфера знаний│
│ (история,│  (диалог, стриминг,  │  + артефакты │
│  входы)  │   инструменты)       │  (выходы)    │
└──────────┴──────────────────────┴──────────────┘
```

**Design challenge для концептов:** как UI показывает, что знание проекта *накапливается и живёт* — сфера знаний как видимое, осязаемое ядро проекта, а не просто вкладка. Это место, где допустима выразительность (визуализация роста, плотности, связности контекста).

Layout — предмет исследования в концептах наравне со стилем; решение о том, что входит в первую реализационную итерацию, принимается после просмотра концептов.

## Палитра — три направления для концептов

Базовое «лицо» продукта выбираем по живым концептам (обе темы light/dark остаются в любом случае):

1. **Тёплая светлая** — кремовые/бумажные тона (ориентир: Anthropic/Claude). Гуманистично, «учебно», заметный уход от generic.
2. **Нейтральная светлая** — спокойный белый/серый с одним выразительным акцентом (ориентир: NotebookLM). Тихо, профессионально.
3. **Тёмная техничная** — тёмная тема как основная (ориентир: Linear). Плотно, по-инженерному, близко к dev-инструментам аудитории.

**Рабочая гипотеза после референс-ресерча** (см. [reference-research-notes.md](reference-research-notes.md)): типовые AI-интерфейсы — «светлые, фиолетовые», от этого уходим. Тянет к **тёплому, дружелюбному**: оранжевый — главный кандидат в акцент, допустимы и другие яркие (но не «вырвиглазные») цвета с учебными ассоциациями, фиолетовый возможен как вторичный в иллюстрациях. Направление 1 (тёплая светлая основа) — приоритетный кандидат; референсы Cron/Zapier-dev показывают, что та же гамма работает и в тёмной теме (чёрный + оранжевый акцент).

**Типографика** — тоже вариативна в концептах: чистый sans (инструментально) vs sans + serif-акценты в заголовках (гуманистично). Сейчас используется Geist Variable.

## Wordmark

Имя — LearnFlowAI; написание открыто к вариантам: `LearnFlowAI`, `LearnFlow`, `learnflow` — пусть концепты покажут форму. Нужны: wordmark для sidebar, знак/иконка (favicon, аватар агента), вариант для тёмной/светлой темы. Метафора для знака — шар/сфера контекста.

## Текущее техническое состояние

- Стек: React + TypeScript, Tailwind CSS v4 (`@theme` в CSS, без config-файла), shadcn/ui (стиль base-nova), иконки lucide.
- Все токены централизованы: `frontend/src/index.css` — CSS-переменные в OKLch, light + dark (`.dark`).
- Стиль сейчас — дефолтный shadcn без кастомизации («95% generic»). Бренд-ассетов нет: ни логотипа, ни favicon.
- Базовые компоненты: `frontend/src/shared/ui/` (button, dialog, input, tabs и др., CVA-варианты).

## Информационная архитектура (что реально есть в продукте)

Источник правды — `doc/tech/frontend.md`. Концепты должны опираться на эти экраны и сущности, а не выдумывать свои.

**Навигационная модель:** chat-first SPA с постоянным sidebar. Путь пользователя: Sidebar → Проект → (Chats / Sphere / Artifacts / Settings) → Чат.

**Sidebar (постоянный):** New chat / New project, список проектов пользователя, Recents — недавние чаты со всех проектов.

**Экраны:**

- **Welcome (`/`)** — приветственный экран без input: чат создаётся только из контекста проекта. Кандидат на иллюстрацию-врезку.
- **Проект (`/projects/:id`)** — имя проекта, input нового чата, табы: **Chats** (список чатов: название, превью, дата) / **Sphere** / **Artifacts** / **Settings** (model override, MCP-серверы проекта).
- **Чат** — диалог с агентом: SSE-стриминг ответа, индикаторы работы инструментов (tool calls), карточки созданных артефактов прямо в ленте, кнопки фидбэка (like/dislike), индикатор review, ChatHeader (← к проекту, выбор модели, диалог tools).
- **Сфера знаний (Sphere)** — живая память проекта в Markdown: просмотр и редактирование. Агент сам читает и обновляет её между сессиями. Центральная сущность продукта (см. design challenge выше).
- **Артефакты** — выходные материалы проекта: список + просмотр (markdown) + скачивание (md/pdf).
- **Настройки пользователя (`/settings`)** — модель по умолчанию, custom instructions, память агента, MCP-серверы.
- **Security (`/security`)** — admin-only мониторинг безопасности: табы Events / Alerts / Rules. Не нуждается в отдельной проработке — только общие токены.

**Ключевые сущности:** пользователь → проекты → чаты / сфера знаний (одна на проект) / артефакты. Агент работает в чате, пользуется инструментами (web search и др. через MCP), пишет в сферу и создаёт артефакты.

## Экраны для покрытия концептами

По убыванию приоритета:

1. **Основной рабочий экран** — chat + sidebar (+ исследование трёхпанельного layout).
2. **Сфера знаний** (SphereView/SphereEditor) — носитель design challenge.
3. **Welcome / логин** — первое впечатление.
4. **Артефакты** (список + просмотр материала).
5. Projects, Settings — по остаточному принципу.
6. Security/SIEM (admin) — только токены, без отдельной проработки.

## Гайд по сбору референсов (Refero / живые продукты)

Цель — не «вдохновиться», а ответить на три вопроса брифа и собрать 5–10 скринов с пометками. Тайм-бокс: час-полтора.

**Стартовый промпт для Refero-чата** (вводит его в контекст продукта, дальше — уточняющие запросы):

> Я проектирую веб-приложение: AI-воркспейс, в котором tech-спикеры и преподаватели готовят учебные материалы — доклады, статьи, курсы. Layout — chat-first: слева sidebar с проектами и чатами, в центре зона диалога с AI-агентом, справа панель с живой базой знаний и сгенерированными артефактами. Ощущение — взрослое, спокойное, умное и тёплое: без игривости и геймификации, но и без корпоративного холода. Покажи реальные веб-продукты с похожими workspace-layout'ами.

**Запросы по вопросам брифа** (каждый закрывает конкретное решение):

| Решение | Запросы в Refero |
|---------|------------------|
| Трёхпанельный layout | «трёхпанельный workspace layout в веб-приложениях», «NotebookLM», «Notion», «Linear» |
| Температура палитры | «веб-приложения с тёплой светлой темой», «dev-инструменты с тёмной темой», «Claude», «Perplexity» |
| Типографика (sans vs serif-акценты) | смотреть в найденных скринах заголовки; добор: «editorial-типографика в веб-приложениях» |
| Сфера знаний (design challenge) | «UI базы знаний», «экраны библиотеки материалов», «продукты с graph-визуализацией» |
| Слабые места текущего UI | «empty states в productivity-приложениях», «onboarding в AI-инструментах», «страницы настроек в AI-продуктах» |

**Как фиксировать:** на каждый референс — скриншот + одна фраза, *что именно* отсюда брать («температура фона», «плотность сайдбара», «подача карточек материалов»). Анти-референсы с причиной так же ценны. Папка скринов потом прикладывается к проекту Claude Design вместе с этим брифом.

**Живые продукты** (бесплатно, смотреть поведение, не только статику): NotebookLM, Linear, Notion, Claude, Perplexity. Кейс эволюции бренда NotebookLM: jasonspielman.com/notebooklm.

**Промпт сессии 2 — цветовой ресерч (тёплая гамма):**

> Теперь я исследую только цветовую гамму, тип продукта не важен. Покажи веб-приложения и сайты с тёплыми палитрами: оранжевый как акцентный или фирменный цвет, кремовые/бумажные/песочные фоны, terracotta, amber, peach. Интересует, как тёплая гамма сочетается со спокойным взрослым интерфейсом — дружелюбно, но не по-детски и не кричаще. Покажи и светлые, и тёмные варианты с тёплыми акцентами.
