# Summary: chore-002 — Code Quality Tooling

## Результат

Трёхуровневая защита качества кода настроена для backend (ruff format → ruff check → mypy) и frontend (ESLint + Prettier). Pre-commit хуки установлены. ESLint MCP подключён.

## Отклонения от плана

### P1: mypy на пустом backend/ (fix)

**План предполагал:** `mypy backend/` отработает с `Success: no issues found` на пустой директории.

**Реальность:** mypy возвращает exit code 2 — `There are no .py[i] files in directory 'backend'`.

**Фикс:** добавлен `files: ^backend/` в pre-commit хук mypy. Теперь хук триггерится только при стейдженных Python-файлах из `backend/`. Если таких файлов нет — хук скипается. Протестировано:
- Python-файл вне backend/ → хук скипается (Skipped)
- Python-файл в backend/ → mypy Passed

Standalone-команда `uv run mypy backend/` вернёт ошибку до появления первого .py файла — это ожидаемо и не блокирует работу.

## Решения, принятые при реализации

1. **ESLint 10** (не 9) — v10 released 2026-02, flat config only, v9 в maintenance mode
2. **Local hook для mypy** — `mirrors-mypy` не видит зависимости проекта, `uv run mypy` использует проектный .venv
3. **eslint-config-prettier** (не eslint-plugin-prettier) — стандартная рекомендация Prettier
4. **pydantic в backend deps** — нужен для mypy pydantic plugin, входит в стек (FastAPI)
5. **ruff.toml отдельным файлом** — чище чем секция в pyproject.toml
6. **`files: ^backend/`** в mypy хуке — фикс для пустой директории (отклонение от плана)
