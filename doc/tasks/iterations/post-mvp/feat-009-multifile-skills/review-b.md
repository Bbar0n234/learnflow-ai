### Разбор по осям (конформно, для протокола)

- **Сигнал ошибки → § Агентные tools.** `load_skill` возвращает error-строки для доменных исходов (невалидное имя, файл не найден, невалидный путь, бинарный файл) — ровно «доменное отсутствие → graceful: tool возвращает error-строку, агент продолжает» (conventions.md:279). Исключения не глотаются: `except UnicodeDecodeError` — узкий локальный catch с контекстом для решения (conventions.md:232, 242); `OSError`/`PermissionError` не перехватываются и всплывают до `ToolNode(handle_tool_errors=_handle_tool_error)` (`backend/app/agent/graph.py:359`), который логирует `exc_info` — точное соблюдение conventions.md:278. Разделение «доменный исход — строкой без лога / инфра-отказ — исключением до барьера с логом» реализовано корректно.
- **Logging → § Logging Conventions.** Отсутствие логирования внутри tool'а — верно, а не пробел: доменные error-строки логировать не требуется (§ Агентные tools их не логирует), а инфра-исключения логируются на барьере (`_handle_tool_error`), не в теле tool'а. Дублировать лог в tool'е было бы против «catch late».
- **Типизация → § Типизация.** `file: str | None = None`, хелперы `-> bool` / `-> list[str]`, PEP 604-юнион — консистентно, mypy зелёный.
- **Доменные паттерны → conventions/agent.md.** Хелперы `_list_skill_files` / `_is_safe_relative_path` — module-level рядом с `_list_available`, симметрично существующему стилю (не замыкания в `make_load_skill_tool`, т.к. состояния не держат). Новый паттерн не заведён: обход через `rglob`+`sorted` повторяет `_list_available`/`scan_skills_index`; error-строки — та же форма, что «skill not found». Двухслойная валидация `file` симметрична существующей валидации `skill_name`.
