# Implementation Plan: feat-009 / трек T1 — Расширение `load_skill` (параметр `file`, автосписок)

## Контекст

Трек делает продуктовый рантайм способным подгружать вспомогательные модули многофайлового скилла, а не только `SKILL.md`. Инструмент `load_skill` получает необязательный параметр `file`: без него — содержимое `SKILL.md` плюс автосписок файлов скилла (progressive-disclosure футер); с ним — содержимое конкретного модуля внутри директории скилла, с двухслойной защитой от path traversal. Плюс актуализация описания механики в архитектурной доке.

Источники:
- Запись итерации — `doc/tasks/tasklist-post-mvp.md` § feat-009 (критерии приёмки).
- Design-brief — `doc/tasks/iterations/post-mvp/feat-009-multifile-skills/design-brief.md` (§ Решение → «Расширение `load_skill`», «Автосписок файлов»; § Тесты; § Партиция треков — границы T1).
- Архитектурная дока — `doc/tech/agent-runtime.md` § Skills System (в скоупе трека — актуализация под параметр `file` и автосписок).
- Код — `backend/app/agent/tools/skills.py` (`make_load_skill_tool`, `_list_available`).

Файловый скоуп трека (по § Партиция треков): `backend/app/agent/tools/skills.py` (+ хелперы рядом при необходимости), `doc/tech/agent-runtime.md`. Тестовый скоуп — `backend/tests/personalization/test_skills.py` (автотесты пишет независимый `test-author` по design-brief; здесь не планируются). `doc/tech/conventions/agent.md` — **эксклюзивно за T2**, трек T1 в него не пишет.

## Фазы

### T1.1: Автосписок файлов скилла в ответе `load_skill` без `file`

**Цель:** `load_skill(skill_name)` возвращает содержимое `SKILL.md`, а после него — футер со списком вспомогательных файлов скилла, когда они есть.

**Изменения:**
- `backend/app/agent/tools/skills.py` — добавить хелпер построения списка файлов скилла рядом с существующими (`_list_available`, `_parse_frontmatter`). Контракт списка по design-brief § «Автосписок файлов»: рекурсивный обход директории скилла, файлы любых расширений, исключаются сам `SKILL.md` и dotfiles; вывод — отсортированные пути относительно директории скилла. В теле `load_skill` (ветка без `file`) дописать футер по образцу из brief (`--- / Skill files (load with load_skill(skill_name, file)): / - <path>`). Скилл без модулей → футер не печатается, ответ однофайлового скилла не меняется.

**Verification:**
- `make check` проходит.
- Критерий приёмки итерации «Скилл виден в Skills Index и полностью проходим агентом в режиме B» в части автосписка: ответ без `file` содержит рекурсивный отсортированный список файлов скилла без `SKILL.md` и dotfiles (design-brief § Тесты — «автосписок присутствует … без SKILL.md и dotfiles»).
- Регрессия отсутствует: для скилла без вспомогательных файлов ответ прежний, футер не добавляется (design-brief § Тесты — «скилл без модулей — футер отсутствует, ответ прежний»).

### T1.2: Параметр `file` — загрузка модуля скилла с защитой от path traversal

**Цель:** `load_skill(skill_name, file)` возвращает содержимое указанного модуля внутри директории скилла, отклоняя выход за её пределы и внятно обрабатывая отсутствующий и бинарный файл.

**Изменения:**
- `backend/app/agent/tools/skills.py` — добавить необязательный параметр `file` в сигнатуру инструмента `load_skill` (докстринг обновить: семантика двух форм вызова). Реализовать по контракту design-brief § «Расширение `load_skill`» → «Контракт параметра `file`»:
  - относительный путь внутри директории скилла, поддиректории допустимы, расширение не ограничено `.md`;
  - двухслойная валидация: safe-паттерн по сегментам пути отклоняет абсолютные пути и `..`; вторая линия — `resolve()` + `is_relative_to(skills_dir/skill_name)`;
  - файл не найден → ошибка со списком доступных файлов скилла (переиспользовать хелпер из T1.1, паттерн существующей ошибки «not found → available»);
  - содержимое, не декодируемое как UTF-8 → внятная ошибка «binary file, cannot load as text» (в автосписке такие файлы остаются видимыми).

**Verification:**
- `make check` проходит.
- Критерий приёмки итерации: «`load_skill(skill_name, file=None)`: без `file` — SKILL.md + автосписок файлов, с `file` — модуль; path traversal невозможен».
- Поведение по design-brief § Тесты: happy path модуля; `../` и абсолютный путь отклонены; несуществующий файл → ошибка содержит список файлов; поддиректория; не-markdown расширение; бинарный файл → ошибка. Существующее поведение без `file` не регрессирует.

### T1.3: Актуализация `agent-runtime.md` под многофайловую загрузку

**Цель:** описание `load_skill` в архитектурной доке отражает параметр `file` и автосписок.

**Изменения:**
- `doc/tech/agent-runtime.md` — обновить строку таблицы Skills (§ Tools, «`load_skill` | Загрузить полный SKILL.md по имени») и § Skills System → «Lifecycle» / «Безопасность»: две формы вызова (`SKILL.md` + автосписок / модуль по `file`), рекурсивный автосписок как робастность progressive disclosure, двухслойная валидация пути `file` (safe-паттерн сегментов + `is_relative_to`). Механику многофайловой загрузки документируем здесь, не в `agent.md` (тот за T2).

**Verification:**
- Описание `load_skill` в `agent-runtime.md` соответствует фактической сигнатуре и поведению после T1.1–T1.2 (сверка с кодом `skills.py`); маркеров итераций/«будет в feat-XXX» в тексте нет (CLAUDE.md § Документация).
