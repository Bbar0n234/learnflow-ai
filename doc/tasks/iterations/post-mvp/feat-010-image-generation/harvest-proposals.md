Оба случая не пойманы `arch-checker` (индирекция через `deps.py`, не прямой импорт репозитория в файле роута) — то есть это не тот же класс долга, что уже отслеживаемый в backlog пункт «Findings из feat-008 Enforcement — R1: API→Repository, allowlist в `ignore_imports`» (те — AST-детектированные и занесены в allowlist; эти — вообще не детектируются). Нужно решение архитектора: либо признать «тонкий инжект read-only репозитория в route — легитимный паттерн» и обновить норму, либо завести оба места (media endpoint + mcp_servers) как отдельный рефакторинг-долг в backlog |

**→ Апрув архитектора: env-смягчение отклонено, принято обратное решение.** Вместо смягчения нормы «все четыре места» под фактический `env_file`-паттерн сервиса `app`, `docker-compose.yml` переведён на явную декларацию — каждая env-переменная сервиса `app` теперь перечислена в `environment:` (по одной), blanket `env_file:` убран. Норма зафиксирована как есть в `doc/tech/conventions.md` § Docker → «Что попадает в env, а что в код» (плюс уточнение технического правила), без ослабления.

**→ Апрув архитектора: API → Repository легитимизирован (с критериями), не отклонён.** `doc/tech/backend.md` § Правила вызовов теперь фиксирует исключение: тонкий read-only инжект допустим при (1) только чтение, (2) ноль бизнес-логики в handler'е, (3) авторизация уже выполнена предшествующими dependencies. Прецеденты — `get_artifact_media` (`BlobStorageDep`) и list-хендлеры `mcp_servers.py` (`MCPServerRepository`); write-хендлеры того же файла под исключение не подпадают и остаются R1-долгом.

**→ Новое решение архитектора (вне исходных кандидатов): нейминг Repository vs Storage/Store.** По факту переезда `BlobStorage`/`PgBlobStorage`/`TraceStore` из `repositories/` в новый `app/storage/` зафиксирована общая норма именования и границы слоя: `*Repository` — CRUD над ORM-сущностью в `app/repositories/`; `*Storage`/`*Store` — абстракция с заменяемым бэкендом или не-ORM семантикой в `app/storage/`, независимый сосед `repositories/`. Норма — `doc/tech/conventions.md` § Именование → «Repository vs Storage/Store»; слой отражён в `doc/tech/backend.md` (диаграммы, Module Structure, Правила вызовов).
