## В конвенции (conventions.md)

| Норма-кандидат | Раздел conventions | Почему фиксируем |
|---|---|---|
| Инъектируемый параметр `runtime: ToolRuntime` в агентском tool'е должен быть аннотирован **ровно** типом `ToolRuntime` (не `ToolRuntime \| None`), а default — `cast("ToolRuntime", None)`, вынесенный в модульную typed-константу (например `_NO_RUNTIME`), а не инлайн в сигнатуру (ruff B008 запрещает `cast(...)` в default). Обязательный параметр без default ломает прямой `tool.ainvoke({...})` без runtime (`ValidationError: Field required`); `Optional`/`Union`-аннотация ломает и распознавание инъекции framework'ом (детект — по точному типу аннотации), и генерацию JSON Schema (`PydanticInvalidForJsonSchema`). Уже применено дважды (`user_memory.py`, `skill_context.py` — T1.2 `load_skill`), верифицировано эмпирически (mypy + прямые async-прогоны) в обоих местах — устойчивый повторяемый паттерн, не разовая находка. | `doc/tech/conventions/agent.md` § Agent Runtime | Норма репозитория про интеграцию с конкретным механизмом LangChain/LangGraph (injected-параметр tool'а), не копия skill-контента (`langgraph-patterns` skill покрывает общие паттерны LangGraph, но не эту framework-специфичную деталь сигнатуры). Второй прецедент в кодовой базе делает её достаточно устоявшейся, чтобы зафиксировать явно — иначе следующий автор tool'а с runtime-инъекцией переоткрывает то же расследование (обе неудачные попытки уже задокументированы в `tracks/T1/summary.md`, но только там, не в норме, которую при написании нового tool'а естественно найти). |

## known-trivial (не в backлог, фиксируем как известное)

- `get_skill_context` (`backend/app/agent/tools/skill_context.py:134`) читает `item.value["content"]` прямым ключом, тогда как сервисный слой (`services/skill_context.py`) и `format_index` везде используют `.get("content", "")`/`.get("description", "")` — расхождение в defensive-стиле. Реального бага нет сегодня: оба пишущих пути (`save_skill_context`, REST `update_document`) гарантированно кладут оба ключа при каждой записи, документа без `content` в системе возникнуть не может. Осознанно не тронуто (review-a nit, оставлено на усмотрение) — если когда-либо схема значения изменится, именно этот tool упадёт `KeyError` вместо мягкой деградации.

## Отсеяно как шум (с причиной)

- **Неатомарная проверка cap-20** (`asearch` → `if len(...) >= 20` → `aput`, `backend/app/agent/tools/skill_context.py:174-184`, review-a) — окно гонки на 21-й документ при двух конкурентных `save_skill_context` с новыми ключами. Осознанное «не делаем»: тот же паттерн read-then-write уже в прецеденте (`knowledge_sphere`), Store не даёт транзакций, урон (21 вместо 20 в персональном per-user namespace) незначителен — сам ревьюер закрыл вопрос как «известное свойство, не дефект». `sofa-proposals.md` независимо пришёл к тому же выводу («штатное свойство KV-store без транзакций, не тянет на инсайт») — вопрос settled с двух сторон.
- **Вопрос о покрытии агентского write-пути checkpoint'ом** (review-a: «`save_skill_context` не прогоняет контент через `SKILL_CONTEXT_WRITE`, только REST — подтвердить у архитектора») — уже отвечен в той же итерации: review-b прямо верифицировал, что агентский путь покрыт runtime-checkpoint `tool_call_arg` (новые tools в `internal_tools` → `collect_fragment_corpus`/`collect_tool_registry`, `main.py:349–364`), симметрично design-brief § Инструменты агента. Вопрос закрыт внутри самой итерации, эскалация не нужна.
- **Лишний повторный `aget` после `aput` в `update_document`** (`services/skill_context.py:756-759`, review-b nit) — осознанный trade-off (свежепрочитанный `updated_at`/`created_at` как единственный источник истины вместо сборки ответа из входных полей), сам ревьюер пометил «оставить как есть — trade-off задокументирован и корректен». Не дефект.
- **Дрейф документации** (namespace/tools/REST/checkpoint не отражены в `doc/tech/`), отмеченный review-b как «незамеченный дрейф для docs-updater» — уже закрыт: DOC_UPDATE-фаза (commit `514c591`) актуализировала ADR-015, `user-memory.md`, `agent-runtime.md`, `backend.md`, `frontend.md`, `security/architecture.md`.
