# Tasklist: Design-branding

## Контекст

Сквозной трек визуальной идентичности продукта: брендовый язык, иллюстрации,
прозрачные ассеты, бренд-кит и оформление репозитория/платформ. Идёт параллельно
продуктовым фазам, не привязан к одной из них. Питается из backlog (P2 Design
system) и собственных research-итераций.

Трек подготавливает ассеты и pipeline; интеграция в код фронтенда — отдельная
итерация трека, помеченная cross: frontend (арты доводятся здесь, применение в
UI согласуется с frontend-треком).

**Документы:** [roadmap.md](../product/roadmap.md) (секция «Сквозные треки»), итерации в `iterations/design-branding/`.

## Зависимости

```
                  ┌─ feat-004 (design-system integration, СЕЙЧАС) ──────────┐
feat-001 (PoC ✅) ─┤                                                          ├─ feat-006 (доводка + пере-свап, предпрод-гейт)
                  ├─ feat-005 (бренд-кит / баннеры / репо, СЕЙЧАС) ──────────┘
                  │
                  └─ feat-002 (cutout ✅) ── [предпрод-гейт ⏸️] feat-003 (SVG?) ─┘
```

- **feat-004 и feat-005 — параллельны и стартуют сейчас.** Зависят только от стиля PoC (feat-001), друг от друга не зависят. feat-004 интегрирует визуальную идентичность в продукт на текущих ассетах; feat-005 — бренд-кит/баннеры/репо.
- **feat-002 — завершена.** Production-пак прозрачных PNG готов. **feat-003 — остаётся отложенной к предпродакшн-гейту**, вход — утверждённый прозрачный пак из feat-002 (готов).
- **feat-003 (SVG) — под вопросом для сцен.** Сложные иллюстрированные сцены векторизуются плохо; SVG релевантнее плоской геометрии бренд-кита (логотипы, иконки, инфографика — feat-005). Сценам, вероятно, достаточно высокого PNG. Решается на планировании feat-002/003.
- **feat-006 — финал в предпродакшн-гейте.** Доводка по живому просмотру + пере-свап текущих ассетов на production cutout/SVG. Зависит от feat-002/003 (качество) и feat-004 (куда свапать). Свап задуман тривиальным: в feat-004 ассеты заводятся через централизованные ссылки, чтобы поздняя замена была точечной (атрибут/расширение), а не охотой по коду.

### feat-003: Векторизация в SVG

**Цель:** превратить утверждённый прозрачный пак в SVG для резкости на любых разрешениях. Open problem — подход и инструменты определяются на этапе планирования (research уже начат в feat-001).

**Статус:** ⏸️ Paused — отложено к предпродакшн-гейту
**Blocked by:** feat-002 (вход — утверждённый прозрачный PNG, иначе дефекты маски станут лишними paths)
**Open question (решить на планировании):** нужен ли SVG сложным сценам-иллюстрациям вообще. Плоский вектор блестит на геометрии (логотипы, иконки, инфографика — feat-005), а сложные сцены векторизуются плохо и часто достаточно высокого PNG. Вероятный исход — SVG уезжает в бренд-кит (feat-005), сценам остаётся растр.

#### Предварительный состав
- Выбор и бенчмарк инструментов векторизации под наш плоский стиль
- Контроль качества (контуры, заливки, вес файла) на тёмном и светлом фоне
- Production SVG-пак

### feat-004: Design-system integration (cross: frontend)

**Цель:** затащить визуальную идентичность внутрь продукта на текущих ассетах PoC — завести дизайн-соглашения в документацию, отрефакторить существующие стили под дизайн-систему, интегрировать ассеты и токены light/dark в UI, при необходимости поправить лейаут. Цель — продукт перестаёт выглядеть generic (Фаза 4 «не стыдно показать»). Production-качество ассетов (чистый cutout, SVG) — отдельный предпродакшн-гейт (feat-002/003/006), эту итерацию не блокирует.

**Статус:** 🚧 In Progress — дизайн принят архитектором; PR #74 открыт, добавлены пост-приёмочный stub-gating (`SHOW_GROUP_B_STUBS`) и фаза HARVEST. ✅ Done — после merge в develop
**Зависит от:** feat-001 (стиль, токены, текущий пак с локальным cutout-fallback)
**Cross:** frontend (рефактор стилей и интеграция согласуются с frontend-треком; FSD-канон уже зафиксирован в codebase-maturity feat-006)

#### Предварительный состав
- Дизайн-соглашения в `conventions.md` (или профильный doc) — пишутся по ходу, как в codebase maturity
- Рефактор существующих стилей под дизайн-систему (токены, темизация light/dark)
- Интеграция текущих ассетов PoC в компоненты UI
- Лейаут/расположение — правки там, где дизайн их требует
- **Централизованные ссылки на ассеты** — путь/импорт ассета в одной точке, чтобы поздний пере-свап на production cutout/SVG (feat-006) был точечным (атрибут/расширение), а не охотой по кодовой базе

#### Scope (согласован)
Перенос спроектированной дизайн-системы «Электрик» из хэндоффа feat-001 в код. Объём — полный: **группа A** (редизайн + релейаут существующих экранов, бренд-примитивы, тема+переключатель, error UX) реализуется реально; **группа B** (семвер сферы, peek, студия-панель, вьюеры slides/audio/image, rich-редактор) — на фронтовых **заглушках**, бэкенд-контракты вынесены в бэклог брифа. Прогон — локальный оркестратор; верификация включает агента-визуального-ревьюера (Playwright MCP) и data-prep seed реальной БД. Merge PR и финальная приёмка — за архитектором.
