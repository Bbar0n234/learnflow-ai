# ADR-003: Knowledge Sphere (долгосрочная память)

## Статус

Принято

## Контекст

Ключевая боль пользователей: контекст между сессиями теряется (подробнее — [idea.md](../../idea.md)). Существующие решения (ChatGPT, Perplexity) хранят атомарные факты без связей — 500 фактов просто лежат, не обновляются, не связываются. "Память чтобы подлизать, а не понять тему."

Нужна долгосрочная память, которая строит связанную картину проекта и позволяет бесшовно продолжать работу через дни и недели.

## Решение

Knowledge Sphere — связанная картина проекта, а не набор атомарных фактов.

**Формат:** структурированный Markdown-документ (MVP). При росте (> 50k токенов, потеря связей между фактами) — миграция на Knowledge Graph с embeddings. Текущий формат достаточен и позволяет мигрировать без переписывания агента.

**Хранение:** LangGraph Store + PostgreSQL.

**Управление:** отдельный Knowledge Sphere Agent. Интегрирует факты в картину, а не просто добавляет. Может запросить уточнение, если контекста мало.

**Механика обновления:**

```
User message
     │
     ▼
Classifier (лёгкий LLM): нужно ли обновление?
     │
     ├── нет → продолжить без обновления
     │
     └── да → Knowledge Sphere Agent:
              - извлечь факты
              - интегрировать в картину
              - запросить уточнение при необходимости
```

**Два режима работы:**
1. **Автономный** — работает тихо, не грузит пользователя
2. **Проактивный** — пользователь видит шар, может править

## Альтернативы

### Атомарные факты (отклонено)

Подход ChatGPT: список изолированных фактов о пользователе и проекте.

**Причина отклонения:** нет связей между фактами, нет целостной картины. Факты не обновляются и не связываются. Память поверхностная — ключевые слова без глубины.

### Без долгосрочной памяти (отклонено)

Только история текущей сессии, без персистентного контекста между сессиями.

**Причина отклонения:** контекст теряется при каждом новом чате — та самая боль, которую решаем. Пользователь вынужден заново объяснять, что уже обсуждалось.

### Full RAG с embeddings с первого дня (отклонено)

Knowledge Graph с векторным поиском как стартовая реализация.

**Причина отклонения:** overkill для MVP. Markdown-документ с Progressive Disclosure ([ADR-004](ADR-004-progressive-disclosure.md)) достаточен на старте. Миграция на KG — при реальных failure modes, не заранее.

## Следствия

- Проект = "шар контекста" — ключевое отличие от generic LLM-инструментов
- Knowledge Sphere Agent — первый sub-agent в системе
- Classifier добавляет overhead, но защищает от лишних обновлений
- Формат миграции заложен: Markdown → Knowledge Graph без переписывания агента
