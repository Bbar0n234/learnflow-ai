# ADR-004: Progressive Disclosure для контекста

## Статус

Принято

## Контекст

Knowledge Sphere ([ADR-003](ADR-003-knowledge-sphere.md)) может расти — нельзя загружать весь шар в контекст всегда. Контекстное окно ограничено, каждый токен стоит денег. Агент должен получать ровно столько контекста, сколько нужно для текущей задачи.

## Решение

Двухуровневая организация Knowledge Sphere: Index + Full.

| Уровень | Что содержит | Размер | Когда в контексте |
|---------|--------------|--------|-------------------|
| Index | Структура + descriptions + теги | 500-1500 токенов | Всегда (pre-loaded) |
| Full | Полное содержимое секции | 2-10k токенов | По требованию (just-in-time) |

**Принципы:**
- Index ≠ пересказ Full. Index — навигационный слой.
- Агент выбирает глубину по контексту диалога.
- Расширение до 3+ уровней — только по реальным failure modes.

**Tool interface:**
- `get_sphere_index()` — получить Index (или он уже в контексте)
- `get_section(section_id)` — получить Full секцию

### Just-in-Time vs Pre-loaded

| Что | Стратегия |
|-----|-----------|
| Knowledge Sphere Index | Pre-loaded (всегда в контексте) |
| Full sections | Just-in-time (через tool) |
| История диалога | В контексте + compaction при приближении к лимиту |
| Skills | Just-in-time (подгружаются когда нужны) |

### Compaction (сжатие истории)

При приближении к лимиту контекста:
1. Суммаризировать историю диалога
2. Сохранить: ключевые решения, нерешённые вопросы, текущий фокус
3. Отбросить: избыточные tool outputs, промежуточные рассуждения
4. Продолжить с compressed context

## Альтернативы

### Весь шар всегда в контексте (отклонено)

Загружать полный Knowledge Sphere в каждый запрос.

**Причина отклонения:** работает пока шар маленький. Не масштабируется при росте, расходует токены впустую. При большом шаре — вытесняет из контекста историю диалога и другую полезную информацию.

### RAG с embeddings (отклонено на MVP)

Векторный поиск по чанкам Knowledge Sphere.

**Причина отклонения:** сложнее в реализации и отладке. Двухуровневый Markdown достаточен на старте. Миграция на Knowledge Graph с embeddings — при реальных failure modes (шар > 50k токенов, потеря связей между фактами).

## Следствия

- Агент работает эффективно при любом размере шара
- Минимальный overhead: Index всегда в контексте (500-1500 токенов)
- Compaction позволяет вести длинные сессии без потери важного контекста
- Формат масштабируется: 2 уровня → 3+ уровня → KG с embeddings, без переписывания агента
