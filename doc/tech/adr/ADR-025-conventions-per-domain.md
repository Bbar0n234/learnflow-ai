# ADR-025: Per-domain дробление conventions.md

## Статус

Принято

## Контекст

`doc/tech/conventions.md` — источник истины по конвенциям проекта: его открывают перед каждой нетривиальной правкой кода и в фазе CODE_REVIEW (ревьюер-B сверяет дифф с конвенциями). Документ рос монолитом: каждый slice добавлял проектные развилки в свой домен (схема БД, REST-контракты, agent runtime, frontend), и файл подошёл к ~720 строкам.

Два связанных риска. Первый — неподъёмность: монолит, который читается «целиком на любой задаче», вытесняет из контекста полезное и со временем перестаёт читаться внимательно. Второй — ревьюер тянет нерелевантное: ревью фронтенд-диффа загружает 90 строк про индексы Postgres и барьерный стек ошибок, которые к диффу отношения не имеют. Та же проблема, что решал [ADR-004](ADR-004-progressive-disclosure.md) для Knowledge Sphere: не грузить весь объём, когда нужна его часть.

## Решение

Progressive disclosure по принципу когезии. **Универсальное ядро** (нужно на любой задаче) остаётся в `conventions.md`; **доменные кластеры** уезжают в `doc/tech/conventions/<domain>.md` и подгружаются при работе в домене.

**Ядро (`conventions.md`):** Git, Структура проекта, Code Quality, Enforcement, Секреты и fail-fast, Обработка ошибок, Тестирование, Docker, Makefile, Именование, Documentation, Logging Conventions, Типизация.

**Доменные файлы (`conventions/`):**

| Файл | Секции |
|------|--------|
| `db.md` | Схема БД, Database migrations, DB-сессии и commit |
| `api.md` | FastAPI, REST API |
| `agent.md` | Agent Runtime, Reasoning LLMs, Prompt Naming |
| `frontend.md` | Frontend |

В шапку `conventions.md` добавлен указатель доменных конвенций (домен → файл → когда читать). Каждый доменный файл начинается с H1 + строки контекста и ссылки на ядро; H2-заголовки секций сохранены (работают как навигационная конвенция). Кросс-ссылки, пересёкшие границу файла, переписаны на относительные пути с якорями (ядро→домен `conventions/<d>.md#…`, домен→ядро `../conventions.md#…`).

## Альтернативы

### Монолит, только сжать прозу (отклонено)

Оставить один файл, убрать декоративные вступления и повторы (рычаг плотности). Сжатие даёт разовый выигрыш в строках, но не меняет режим чтения: документ по-прежнему «весь на любой задаче», и с каждым новым slice'ом снова раздувается. Не решает проблему «ревьюер тянет нерелевантное».

### Nested CLAUDE.md по дереву кода (отклонено)

Разнести конвенции по `CLAUDE.md` в поддиректориях (`backend/CLAUDE.md`, `frontend/CLAUDE.md`). Размазывает источник истины по дереву кода: норма ищется не в одном предсказуемом месте, а зависит от того, в какой директории ты находишься; кросс-доменные правила (обработка ошибок, охватывающая оба сервиса + agent + frontend) не имеют естественного дома. Единый `doc/tech/` остаётся точкой входа в документацию.

## Следствия

- Slice пишет новую доменную норму в свой файл `conventions/<domain>.md`, а не в монолит; ядро прирастает только кросс-доменными правилами.
- Ревьюер-B читает ядро + затронутый домен, а не весь свод.
- Рычаг удаления норм (вычистить то, что ушло в детерминированный arch-checker) на этой итерации **отложен**: при дроблении переносим всё дословно, включая дублирующее checker, — как страховку на период обкатки. Снятие дублей — отдельным решением, когда checker докажет надёжность.
- Добавился слой относительных кросс-ссылок между файлами: при переносе секции между ядром и доменом (или переименовании) ссылки и якоря надо выверять. Внешние документы (`backend.md`, `frontend.md`, `siem-service.md`), ссылавшиеся на якоря перенесённых секций, обновлены на новые пути.
