# Скиллы агента

Библиотека скиллов монтируется в контейнеры `app` и `executor` как `/skills` (read-only) — см. [ADR-032](../doc/tech/adr/ADR-032-project-workspace-file-model.md) и [agent-runtime.md](../doc/tech/agent-runtime.md#skills). Хранилище — этот репозиторий: деплой скиллов идёт релизом вместе с кодом, копий в workspace проекта нет.

Каждый скилл — директория с `SKILL.md` (YAML front matter `name` + `description`, по нему строится Skills Index) и произвольным набором сопутствующих файлов: дополнительные инструкции, шаблоны, скрипты. Скрипты скилла агент исполняет через `run_command` / `execute_code` — они читаются из `/skills` в песочнице, поэтому зависимости скрипта обязаны быть в образе executor'а либо в стандартной библиотеке.

## Реестр

| Скилл | Назначение | Происхождение |
|-------|-----------|---------------|
| `structure` | Структурирование учебного материала: модули, последовательность, learning objectives | Собственный |
| `tech-article-writing` | Методология написания технических статей вместе с автором | Собственный |
| `gost-lab-report` | Оформление студенческих работ по ГОСТ 7.32 (лабораторные, курсовые, ВКР): Markdown → `.docx` со стилями и титульным листом | Вендоренная копия, см. ниже |

## Вендоренные скиллы

`gost-lab-report` — копия внешнего репозитория [Bbar0n234/gost-report-skill](https://github.com/Bbar0n234/gost-report-skill), директория `gost-lab-report/`, коммит `96d4e10ba8542753b041e7d2f1ff3541d759b00d`.

Копия, а не submodule: клонирование, CI и docker build не должны зависеть от `--recursive`, иначе на любом из этих путей скилл тихо станет пустой директорией. Обновление — осознанный ре-копи с обновлением коммита в этой таблице, а не автоматическая синхронизация.

Зависимости обязательного слоя скилла (`pandoc`, `python-docx`, `docxcompose`) запечены в образ executor'а. Опциональный слой (LibreOffice для автоматического обновления поля СОДЕРЖАНИЕ) в образ не входит: скрипт сборки деградирует штатно — поле остаётся, обновляется в Word по F9.
