# Ревью собранного отчёта

Независимая проверка готового .docx перед сдачей пользователю. В идеале выполняется **субагентом с чистым контекстом** (не автором отчёта): автор слеп к своим ошибкам. Если субагента запустить нельзя — пройти чек-лист самому, честно.

Ревьюеру передать: итоговый .docx, исходный Markdown, контентный вход пользователя (методичка/положение, если были).

## Порядок

1. **Детерминированная часть:** `python <skill>/scripts/verify.py <report.docx>` — стили, шрифты, отступы, поля, целостность merge. Любой FAIL — блокер.
2. **Рендер:** `soffice --headless --convert-to pdf` + `pdftoppm -png` → осмотреть все страницы глазами.
3. **Чек-лист ГОСТ** (ниже) по рендеру и тексту.
4. **Контентная сверка:** структура и формулировки против методички/задания (цель дословно? все пункты задания закрыты? порядок разделов по документу?).

Вердикт: список замечаний с серьёзностью (блокер / надо поправить / вкусовщина) и указанием страницы. Пустой список — тоже результат, если честный.

## Чек-лист соответствия ГОСТ 7.32-2017

Пункты стандарта в скобках. Помеченное ⚙ проверяет verify.py — глазами перепроверять только при сомнении.

**Титульный лист**
- [ ] Ровно одна страница; тело начинается со следующей
- [ ] Все поля заполнены (нет пустых линий там, где ждали значение; нет остатков `{{...}}`)
- [ ] Линии форм доходят до правого края, значения стоят на линиях

**Типографика** (6.1.1)
- [ ] ⚙ Times New Roman, 14 pt, чёрный; полуторный интервал; абзацный отступ 1,25 см
- [ ] ⚙ Поля: левое 30 мм, правое 15 мм, верхнее/нижнее 20 мм
- [ ] Полужирный — только в заголовках; курсив — только для латинских терминов/объектов

**Заголовки** (6.2.1–6.2.4)
- [ ] Структурные элементы (РЕФЕРАТ, СОДЕРЖАНИЕ, ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ, СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ) — прописными, в середине строки, без точки, каждый с новой страницы
- [ ] Заголовки разделов/подразделов — с прописной буквы (не капсом), ⚙ полужирные, без точки в конце, без переносов слов
- [ ] Каждый раздел основной части — с новой страницы (для курсовой/ВКР; у лабы допустимо подряд)
- [ ] Известное отклонение движка (зафиксировано, не считать ошибкой генерации): заголовки от левого края, а ГОСТ требует с абзацного отступа (6.2.3)

**Нумерация** (6.3, 6.4)
- [ ] Разделы пронумерованы «1», «1.1» — без точки после номера; структурные элементы и приложения без номеров
- [ ] Страницы: арабскими, сквозная, в центре нижней части; на титуле номер не проставлен, но титул входит в счёт

**СОДЕРЖАНИЕ** (5.4, 6.13) — если есть
- [ ] Все разделы/подразделы и структурные элементы присутствуют, номера страниц совпадают с фактическими (не «обновите поле»)
- [ ] Записи выровнены влево, отточие, номера по правому краю; подразделы с отступом относительно разделов
- [ ] Начертание записей обычное (полужирный TOC — не по ГОСТ)
- [ ] Известное отклонение движка: приложения в содержании без наименования (ГОСТ 6.17.7 требует «ПРИЛОЖЕНИЕ А … Наименование»)

**Рисунки** (6.5)
- [ ] Подпись под рисунком: «Рисунок N — Название», по центру, без точки в конце
- [ ] На каждый рисунок есть ссылка в тексте ДО него («представлено на рисунке N»); нумерация сквозная без пропусков

**Таблицы** (6.6)
- [ ] Подпись над таблицей слева: «Таблица N — Название»
- [ ] На каждую таблицу есть ссылка в тексте; таблица не разваливается по ширине страницы
- [ ] Заголовки граф по центру, заголовки строк по левому краю (6.6.6); таблица ограничена линиями со всех сторон
- [ ] Известное отклонение движка: при переносе таблицы на следующую страницу повторяется шапка, а не подпись «Продолжение таблицы N» слева (6.6.3) — место разрыва знает только рендерер, автоматизировать нельзя; для строгого вуза правится руками за минуту

**Источники** (5.7, ГОСТ 7.0.100-2018)
- [ ] Записи оформлены по 7.0.100 (авторы «Фамилия И. О.», тире между областями, у электронных ресурсов URL + дата обращения)
- [ ] Ссылки в тексте `[N]`; каждый источник из списка процитирован хотя бы раз; порядок соответствует правилу (цитирование/алфавит — по контентному входу)

**Приложения** (6.17) — если есть
- [ ] «ПРИЛОЖЕНИЕ А» прописными по центру, с новой страницы; название следующей строкой по центру
- [ ] Буквы по порядку без Ё, З, Й, О, Ч, Ъ, Ы, Ь
- [ ] Рисунки/таблицы внутри — «Рисунок А.1», «Таблица А.1»; на каждое приложение есть ссылка из текста

**Реферат** (5.3, 6.12) — для ВКР
- [ ] Первая строка — статистика в строку через запятые, с абзацного отступа; счётчики подставлены (не `{{PAGES}}`) и правдоподобны
- [ ] Ключевые слова: 5–15, прописными, в строку, без точки в конце

**Содержание работы**
- [ ] Цель (если из методички) — дословно; выводы/заключение перекликаются с целью и задачами
- [ ] Задание из методички воспроизведено дословно, не пересказано
- [ ] Нет обрывов: пустых разделов, «TODO», незакрытых предложений

## Помимо ГОСТ — общая вычитка

Не полноценная стилистическая редактура, а отлов очевидного:

- [ ] Опечатки и грамматика — особенно в заголовках, терминах, ФИО и названиях с титульника (их никто не перечитывает, а видят первыми)
- [ ] Числа согласованы: значение в тексте = значение в таблице/на рисунке, на которые он ссылается
- [ ] Термины единообразны: одна сущность называется одним словом по всему тексту (не «сервер БД» / «база» / «СУБД» вперемешку об одном)
- [ ] Нет повторов мысли: один и тот же тезис не пересказывается в соседних разделах разными словами
- [ ] Нет технических артефактов: остатки Markdown-разметки, непереведённые кальки, служебные фразы («как показано выше» без адресата)

## Для A/B-оценки

Тот же чек-лист как метрика: считать долю выполненных пунктов (применимые к данному типу работы). «Известные отклонения движка» считать по фактическому состоянию документа — без поблажек, одинаково для обеих рук эксперимента.
