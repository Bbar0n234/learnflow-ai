# Диагностика входа и маршруты

Метод написания подстраивается под стартовый материал, а не идёт единым конвейером. Этот файл — способ думать о любом входе, включая непредусмотренный.

## Диагностика: два вопроса

Оцени материал автора по двум осям:

1. **Содержание (signal):** есть ли уже мысли, факты, выводы — или их ещё нет?
2. **Структура (form):** есть ли уже порядок и логика — или это хаос?

Ответы определяют, чего не хватает — и с этого надо начинать.

**Главное правило: начинай с того, чего НЕ хватает. Outline рождается там, где впервые появляется структура** — раньше для входов с готовой/скрытой структурой, позже для бесструктурных.

## Типовые маршруты

### Сырая диктовка мыслей (содержание есть, структуры ноль)
Поток сознания: повторы, откаты, перепрыгивания. Основная работа — структуризация.

1. **Gist extraction** — вытащи тезисы/саммари каждого смыслового куска. Работай на уровне идей, не построчной правки: автор помнит сказанное «как gist, а не дословно».
2. Автор на уровне gist'ов решает: объединить / разбить / выкинуть / переставить.
3. **Outline — в конце**, как результат структуризации. Навязать каркас сырым мыслям преждевременно = чужая структура.

### Транскрипт прочитанного доклада (содержание есть, структура скрытая)
У доклада уже был план и логика — они размазаны устным регистром. Структуру не создавать, а **реконструировать**.

1. Восстанови outline доклада из транскрипта → на утверждение автору.
2. Основная работа — **spoken→written**: убрать филлеры, false starts, повторы, устную избыточность (спикер повторяет важное вслух — текст требует плотности); расставить границы предложений.
3. Добавить то, что в докладе шло через слайды/голос: заголовки, код-блоки, врезки. Источник — автор.

Транскрипт ≠ черновик: это сырьё, требующее серьёзной переработки, но самый «дешёвый» вход — редактура и переложение формата, а не создание.

### Код / референсы / репозиторий (факты есть, нарратива и личного смысла нет)
Инверсия диктовки: **сначала угол и outline от автора, факты потом.**

1. Автор задаёт угол: какую историю/проблему/вывод доносим, кому.
2. Только затем агент извлекает факты из источника **под заданный угол**.
3. Жанровая дисциплина (Diátaxis): код сам по себе — reference; статья — explanation или how-to. Не смешивать. Риск без угла — «пересказ README», который никому не нужен.

### Готовый авторский черновик (содержание есть, структура есть, регистр письменный)
Автор принёс уже написанный текст на доработку. Не гонять его через gist-extraction и пересборку, которых никто не просил.

1. Уточни у автора запрос: редактура? структурный ревью? анти-слоп-проход? адаптация под платформу?
2. Вход сразу в шаг 5 (редактура иерархией) и/или judge-проход — по запросу.
3. Outline здесь — **инструмент ревизии**, не старта: сверни секции в однострочники, покажи автору скелет («вот логика твоего текста — она совпадает с задуманной?»).

### Смесь входов
Не обрабатывать одним приёмом.

1. Декомпозируй материал по типам → каждый кусок своим маршрутом.
2. Отдельный финальный проход — **voice-unify**: выровнять голос, регистр и плотность (куски из диктовки, доклада и кода звучат по-разному).

## Набор операций (кубики для любого входа)

Непредусмотренный вход = новая комбинация тех же операций, порядок выводится из диагностики:

| Операция | Что делает |
|---|---|
| `gist-extract` | Тезисы/саммари из потока, уровни сжатия |
| `clean` | Чистка речи: филлеры, false starts, повторы. См. правило сохранности ниже |
| `spoken→written` | Устный регистр → письменный, границы предложений |
| `reorder / split / merge` | Перестановка и перекройка смысловых кусков (решает автор) |
| `transform` | Переформат под жанр (explanation / how-to / tutorial) |
| `fact-extract` | Факты из кода/доков под заданный автором угол; каждый факт — с указателем на источник (файл/строка/цитата), чтобы авторский fact-check на шаге 7 был дешёвым |
| `voice-unify` | Выравнивание голоса и плотности разнородных кусков |
| `fact-check` | Список проверяемых утверждений для автора (сам не подтверждаешь) |

**Правило сохранности при любой чистке:** филлеры и повторы убирать можно; **хеджи («я думаю», «примерно»), числа, имена, условия, отрицания, эмоции и оценки — не трогать.** Их «причёсывание» меняет смысл, а смысл — зона автора.

**Инвариант для всех маршрутов:** смысловое или структурное решение — автор; механическая операция над текстом — агент. Тип входа меняет порядок операций, но не границу ролей.
